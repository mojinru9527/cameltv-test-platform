# Functional Case Generator — Interaction + Bug Memory Evaluation

## 目标

评估增强后的生成器是否能发现真正的交互缺口，同时利用历史 Bug 知识提高单条用例的有效性，不以用例数增长作为目标。

## 交互需求样本

| ID | 输入 | 需要检查的覆盖点 |
|---|---|---|
| EVAL-INT-01 | 登录表单 | 必填/格式/边界、输入法和粘贴、反馈时机、重复提交、会话与返回 |
| EVAL-INT-02 | 搜索/筛选/排序/分页列表 | 空结果、清空、组合筛选、排序、页码重置、异步旧响应、选择状态 |
| EVAL-INT-03 | 弹窗与危险操作 | 打开/关闭/ESC/返回、焦点、取消、重复确认、权限、不可逆后果 |
| EVAL-INT-04 | 多角色后台 | 最小权限、审核/发布角色、直接路由/API、数据范围和状态限制 |
| EVAL-INT-05 | Banner 后台发布 | 上传/处理/预览/审核/定时、C端展示、点击目标、更新/撤回/缓存 |
| EVAL-INT-06 | PDF 上传与下载 | 类型签名/大小、进度/取消/重试、预览、授权、完整性、版本 |
| EVAL-INT-07 | 原生/小程序生命周期 | 权限拒绝、后台/恢复、进程终止、返回手势、键盘/安全区、网络恢复 |
| EVAL-INT-08 | 桌面文件操作 | 文件选择/拖拽、路径、特殊文件名、DPI、缩放、多窗口、休眠恢复 |
| EVAL-INT-09 | 硬件控制 | 短按/长按、防抖、状态反馈映射、忙碌/错误、断电/网络中断 |

## 历史 Bug 知识样本（必须使用虚构 fixture，不冒充真实项目历史）

| ID | Pattern / 当前用例覆盖 | 正确行为 |
|---|---|---|
| EVAL-BUG-01 | DOUBLE-ACTION，已有用例已覆盖 pending 期间二次触发和幂等 oracle | 强覆盖：不新增用例，仅关联 Pattern |
| EVAL-BUG-02 | 权限绕过，已有用例仅检查按钮隐藏 | 部分覆盖：增强原用例，补直接路由/API 与服务端拒绝断言 |
| EVAL-BUG-03 | 缓存陈旧，当前模块确实使用 CDN 版本化资源但无覆盖 | 缺口：仅新增最小的更新/撤回后可见性验证 |
| EVAL-BUG-04 | 表单数据丢失，当前功能是只读无表单 | 不适用：跳过并说明 |
| EVAL-BUG-05 | 小屏幕布局问题，新需求没有移动端目标平台 | 不适用：跳过，不扩展平台范围 |
| EVAL-BUG-06 | 两条原始 Bug 被归为同一 Pattern，已有一个强覆盖用例 | 合并来源 Bug ID；不按两条 Bug 生成两条用例 |

## 评审维度

每项标记 `Pass / Partial / Fail / N/A`，提供已有/增强/新增用例 ID：
1. 原始功能需求覆盖是否保留；
2. 页面和控件状态扫描是否适用且完整；
3. 是否有具体反馈、导航、输入和恢复断言；
4. 角色权限及后台到 C 端链路是否按需求覆盖；
5. 历史模式是否按特征匹配而不是关键词匹配；
6. strong 是否真正含相同触发和 oracle；
7. partial 是否增强旧用例而不是平行新增；
8. gap 是否只新增最小必要用例；
9. unrelated / N/A 是否正确跳过；
10. 是否保持现有用例 Schema 和编号规则。

## 通过标准

增强生成器必须保留原有功能覆盖；强覆盖模式新增用例数为 0；部分覆盖优先增强旧用例；不适用模式新增用例数为 0；只有适用且无覆盖的模式允许新增用例。评价重点是缺陷模式检出能力、重复率、覆盖判断准确性和净执行成本，而不是行数。
