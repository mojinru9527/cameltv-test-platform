# 接口/API 用例检查点速查（输出用例要求 v2 — 主结构）

> **权威输出要求**：`tests/test-case-standards/接口测试输出用例要求.md`（来源：用户重新整理的 接口测试.xmind）。
> 设计接口用例时**按以下五类逐一覆盖**：业务功能 / 健壮性 / 安全 / 性能 / 数据；
> 返回值校验贯穿各类，幂等/稳定性/兼容性按需补充。**最后必须叠加深度用例补充层**。禁止脱离本框架凭记忆写接口用例。

## 接口测试流程

1. 分析接口文档和需求文档（接口说明、请求方式、请求 URL、请求参数、返回数据、返回实例）
2. 接口用例设计（按五类框架）
3. 编写接口测试用例
4. 接口测试执行
5. 输出接口测试报告

## 覆盖率三问（必须自检）

1. **业务功能覆盖是否完整**：单接口冒烟 + 多接口场景串联（状态转变可验证）
2. **参数验证是否完整**：合法入参（等价类+边界值）+ 非法入参（类型/缺字段/缺值/加不存在参数/特殊字符/-1、0、null）
3. **安全/性能/数据是否覆盖**：加密/注入/越权/CSRF；响应时间/吞吐/并发/资源；入库/字段/表关系/约束

---

## 一、业务功能测试【必选】

### 1. 冒烟测试
- 以业务中某一入参为起点，完成接口实现的功能，并通过**结果验证**或**其他接口验证**。

### 2. 场景测试
- 从业务逻辑层面，通过**几个接口的连续调用**达到状态转变效果，通过返回结果或其他接口验证。
- 输出：跨接口场景串联用例（依赖接口串联、状态流转断言）。

## 二、健壮性测试【必选】

### 1. 入参合法覆盖测试（等价类划分 + 边界值联合）
- **取值范围覆盖**：范围小（≤10）全量取值；范围大按等价类 + 边界值取值。
- **组合配置可选参数合法入参**：类型符合接口要求；符合业务逻辑、真实存在。
- **覆盖所有必选参数合法入参**：符合业务逻辑、真实存在；类型符合接口要求。

### 2. 入参非法覆盖测试
- **业务边界取值**：超长度限制入参；特殊字符入参（期望服务器处理）。
- **必选参数非法入参**：类型非法；字段缺少；字段值缺少；增加不存在的参数；特殊字符；-1、0、null。

## 三、安全测试【按需】

- **敏感信息加密**：https / 请求签名 / 身份确认机制 / SSL pinning（防抓包）/ 请求响应全链路加密。
- **SQL 注入**：输入校验（正则/限长/引号转换）、参数化 SQL、最小权限连接、敏感信息加密、错误信息最小化。
- **XSS**：反射型 / 存储型 / DOM 型（思维导图标注**暂不进行**，保留检查说明）。
- **越权访问**：接口权限最小化、token 校验、用户请求合法性、静态密钥强加密、时间戳+随机数防重放、访问权限控制。
- **CSRF 请求伪造**：来源/凭证校验。

## 四、性能测试【按需，低优先级】

- 响应时间、吞吐量、并发数、服务器资源使用率（CPU / IO / 内存 / Network）。

## 五、数据测试【按需】

- **基本**：熟悉 DB 字段类型/含义；执行操作后确认数据库正常入库；字段长度/类型定义与需求一致。
- **专业化**：表结构合理性；主外键/表关系；索引；存储过程；输入输出正确；插入/更新/删除正确；
  操作权限；并发处理；表级/列级完整性约束；处理能力/可靠性/可维护性/性能。

---

## 返回值校验（必选，贯穿各类）

- 返回状态码校验；新增类校验新生成标识非空；更新/删除类校验 success=true；
- 列表查询类校验记录数/排序；数据详情类校验核心字段准确性。

## 幂等 / 稳定性 / 兼容性（可选）

- **幂等**：重复提交 / 超时重试 / 消息重复消费。
- **稳定性**：限流 / 熔断 / 降级；qps、rt、fail、机器/中间件/存储资源。
- **兼容性**：入参只增不删改；返回值按序新增；老功能/老数据兼容。

## 接口测试用途

- 回归测试 / 非功能性测试 / 易于自动化持续集成（越底层发现 bug 修复成本越低）。

---

## 深度用例补充层（强制，基座基础用例之上叠加）

> 基础用例（五类框架生成）覆盖单接口正/负/边界后，**必须**再叠加深度用例，
> 从业务状态、闭环串联、数据一致性、权限与端差异四个层面补足，禁止只出孤立单接口用例。
> 模式来源：Batch 122 体育全模块深度用例（接口域含 ads/forecast/home/league/match/news 等）。

1. **业务状态机覆盖**：同一接口在不同业务状态下（数据未开始/进行中/已结束/已结算/已关闭/已取消等）的入参与返回差异，逐状态断言。
2. **跨接口闭环串联**：完整业务链路的接口串联用例（如 查询赛事 → 下注 → 查预测记录 → 开奖 → 查余额/流水 → 校验发放），状态转变逐段断言，与功能闭环用例对齐。
3. **数据一致性**：接口操作后 DB 入库校验（字段/长度/类型/表关系）、列表与详情返回一致性、幂等重复调用不产生脏数据。
4. **权限与端差异**：未登录/越权/不同角色调用同一接口的返回差异；同一接口在用户端 4 入口（安卓/iOS、PC-web、移动端-web）与运营后台（konfi/运营后台）的参数/权限差异。
5. **异常与边界补充**：并发重复提交、超时重试、活动边界（上下限/结束前后）、空数据/大分页/特殊字符数据等。
