# 接口用例交互/缺陷模式增强清单（运行时注入 · 生成时必读）

> 与 `api-checklist.md` 叠加使用：`api-checklist.md` 管「测什么类别」，本文件管「断言是否够硬、是否漏了历史失效模式」。

## 1. 每个接口用例必须具备的可判定 oracle

| 层 | 断言 | 不合格示例 |
|---|---|---|
| HTTP | 状态码（200/400/401/403/404/405/413/415/429/500） | 只写「请求成功」 |
| 业务码 | `code` 精确值（200/401/403/500…），**不得把 500 兜底当通过** | 只断言 `code != 0` |
| 结构 | 关键字段存在与类型、数组长度、分页字段（items/total/page/page_size） | 只写「返回 JSON」 |
| 业务规则 | 状态迁移结果、金额计算、库存扣减、幂等键唯一 | 只看 HTTP 200 |
| 数据 | DB 入库/未入库、字段值、软删标记、计数与明细一致 | 只看响应体 |
| 副作用 | 无重复记录、无脏数据、外部回调只处理一次 | 不检查 |
| 安全 | 无敏感字段明文（openid/手机号/密钥/验证码答案） | 不检查 |

## 2. 参数维度（缺一类即覆盖不全）

- 合法：等价类代表值 + 边界值（min-1 / min / max / max+1）。
- 非法：缺必填、字段值缺省、类型错误、`null`/`-1`/`0`/空字符串、超长、特殊字符、Emoji、多传不存在字段、非法 JSON、空 body。
- 对象不存在：不存在的 ID / 已删除对象 / 他人对象（越权）。
- 分页：`pageSize` 超上限（1000/10000）、`pageNum` 超末页、大偏移。
- 幂等：同一请求连发 2 次、超时重试、并发 5 以内。

## 3. 历史失效模式必查（来自项目缺陷库，详见 `bug-pattern-digest.md`）

| Pattern | 必查点 |
|---|---|
| BP-021 | 非法入参是否返回 4xx + 可读业务码，而非 500/兜底编号/堆栈 |
| BP-022 | 用 B 的 token 访问 A 的资源 ID → 403/404 且不返回数据 |
| BP-023 | 响应/日志不含 openid、手机号明文、密钥、验证码答案 |
| BP-024 | 非法状态迁移（已取消订单发货、重复退款）是否被拒且原状态不变 |
| BP-025 | 接口计数 == DB `count(*)`；分页 total 与列表一致 |
| BP-026 | `pageSize` 超上限被拒/截断；P95 < 2000ms |
| BP-027 | 无签名/错签名/重放回调 → 401/403 且不改业务数据；重复回调幂等 |
| BP-029 | 低权限角色直连高权限接口 → 403；数据范围只返回授权范围 |

判定规则：`strong` 只关联不新增；`partial` 增强该用例断言；`none` 才补最小用例。

## 4. 跨接口闭环（禁止只出孤立单接口用例）

每条闭环需逐段断言并落 DB 校验，例如：
`查询可售商品 → 创建结算 → 支付回调 → 订单变待发货 → 后台发货 → 确认收货 → 售后申请 → 退款`
每段：状态码 + 业务码 + 关键字段 + DB 状态。

## 5. 质量门禁

- 预期结果只写「200/成功」→ 不合格。
- 把 `code=500` 兜底提示当通过 → 不合格。
- 无 DB 校验或副作用断言的写接口用例 → 不合格。
- 用占位假数据（`abc`、`123`）代替真实业务参数 → 不合格（见 `../../tests/test-case-standards/接口用例必填真实数据规范.md`）。
- 复制历史用例只改 ID → 不合格。
