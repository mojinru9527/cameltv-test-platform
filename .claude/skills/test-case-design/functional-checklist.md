# 功能用例检查点速查（输出用例要求 v2 — 主结构）

> **权威输出要求**：`tests/test-case-standards/功能测试输出用例要求.md`（来源：用户提供的 7 份功能用例文档：
> 功能测试用例规范、功能测试检查点【辅助】、测试的具体体现、测试用例标准、测试用例具体用法、界面测试的方法要点、功能测试用例用途）。
> 设计功能用例时**按以下主结构覆盖**：设计前置 → 输出结构 → 覆盖维度 → 深度用例补充；
> 禁止脱离本框架凭记忆写功能用例。

## 功能用例设计流程

1. 测试需求分析：从需求文档拆出全部**功能点**，输出功能点清单（覆盖率基线）。
2. 业务流程分析：梳理主流程（基本流）/ 备选流 / 异常流 / 数据流向 / 关键判断条件 / 前置条件。
3. 按覆盖维度设计用例（第三章逐条比对）。
4. 按标准模板输出（case-template.md）。
5. **叠加深度用例补充层（第四章，强制）**。
6. 覆盖率自检（第五章清单）。

## 覆盖率基线（必须自检）

1. **功能点覆盖是否完整**：与需求一一对应，基本流覆盖 100%
2. **正/负用例是否成对**：每个需求点 ≥1 正面 + ≥1 负面
3. **深度用例是否叠加**：状态机 × 用户视角 × 闭环 × 关联功能 × 异常边界 × UI 细节 × 权限/端差异

## 一、设计前置

- **用例用途 / 设计依据**：指导测试、确保与需求符合、跟踪重点、评估度量、分析缺陷；依据需求说明书 + 功能点 + 业务知识 + 个人经验。
- **编写原则（六性）**：系统性 / 连贯性 / 全面性 / 正确性 / 符合正常业务规则 / 可操作性。
- **编写标准**：统一模板 + 编号规则；步骤明确、输入输出清晰；覆盖全部需求功能点；可复用。
- **用例字段（18 项）**：用例编号、模块名称、用例标题、维护人、用例类型、重要程度（P0/P1/P2）、测试类型、关联项目、前提条件、操作步骤（含输入数据）、预期结果（含验证手段）、备注、执行结果、实际结果、缺陷、执行人、结果附件。
- **级别划分**：P0 关键路径/最常用/基本流/数据有效性；P1 不常用/异常流/边界值；P2 界面/提示一致性/可用性/性能。
- **维护规则**：过时置废弃、需求变更同步修改（执行超 2/3 不再变更/新增）、删冗余（相同输入输出只留一条）、新增插到模块最下方并备注。

## 二、输出结构

- **正/负用例成对（强制）**：每个需求 ≥1 正面（证明满足）+ ≥1 负面（反常/意外数据，论证仅所需条件下满足）。
- **三事件模型**：基本事件（100% 覆盖）+ 备选事件（分支再汇入）+ 异常事件（错误数据，验证报错及报错文字）。
- **按功能/路径混合模式**：简单功能按功能遍历；复杂关联模块用路径分析法避免漏测。
- **输出模板**：`用例编号 | 模块 | 用例标题 | 重要程度 | 前提条件 | 操作步骤 | 预期结果 | 备注`；复杂流程用**场景矩阵**（V/I/n/a 标记，空白即缺用例）。

## 三、覆盖维度（逐条比对）

### 1. 功能性
- **功能点缺失/不一致**：实现少于需求；与需规不能一一对应；实现需求外功能但有误；title/弹窗名与按钮不一致。
- **功能实现错误**：计算/逻辑公式不符；开始>结束无提示（开始=结束应正常）；导出乱码/表头不一致；必填未标注；二次查询未按条件；必填不填能保存；上传无成功提示；导入格式不符应失败且提示。
- **系统稳定性**：异常退出、崩溃、停止服务、无法运行。

### 2. 常见功能模块检查点（按模块加载）
安装 / 配置 / 卸载 / 运行与关闭 / 服务程序 / 系统管理（参数设置）/ 用户权限管理 / 系统登录 / 注销 / 修改口令 /
右键功能 / 记录列表 / 统计查询 / 文件操作（保存/打开/打印/导入导出/检入检出）/ 界面对象功能（文本框/口令域/时间域/货币域/身份证/电话/图表/列表）/ 备份与恢复 / 系统日志。

### 3. 易用性
响应慢 / 界面展示（显示不全/出框/遮挡/对齐/置灰/风格统一/无横向滚动/菜单≤3级）/
可终止性（缺取消/回退）/ 易操作性（确认左取消右/时间框可清空/新增后关窗/悬停高亮/快捷键/删除提示）/
输入校验（手机/身份证/URL/邮箱/范围/长度/唯一性/空值/特殊字符/表情/超长/NULL/空格）/
易理解性（避免「系统内部错误」无指导提示）/ 默认值。

### 4. 界面测试要点（界面测试的方法要点）
标题栏（文字正确、按钮按窗口特性）/ 文字（描述与功能一致、无错别字、用语统一、全量文字资源）/
控件（对齐/缩进/置灰引导/状态匹配）+ 菜单、快捷键、焦点、Tab 顺序、字体、滚动条、对话框、模态。

### 5. 其他质量维度
兼容性（浏览器/分辨率/操作系统/其它软件/接口）/ 可维护性（角色/日志/开关/重启）/
可靠性（稳定/容错/容量）/ 可移植性（适应/易安装卸载/易替换/依从）/ 文档（完整/正确/一致/易理解/易浏览）。

### 6. 性能 / 压力 / 容错 / 并发（按需）
查询/保存/统计/刷新/传输/下载响应；小数据量与累积大数据两种场景；大数据文件处理；多客户端提交；
断网/断电/死机/服务器 down；登录/提交/DB 读写并发。

### 7. 易出错点（测试必查）
已存在内容提示 / 删除（确认/校验/使用中/级联/重用）/ 提示正确性（重要操作换方法验证）/
磁盘满 / 系统时间影响 / 慢按钮连点 / 并发必测 / 版权 logo / 初始化默认设置。

## 四、深度用例补充层（强制，基座基础用例之上叠加）

> 基础用例覆盖「功能点正/负」后，**必须**再叠加深度用例，从状态、用户、闭环、关联四个层面补足。
> 模式来源：Batch 122 体育全模块深度用例（507 条 SP-，用户端 4 入口 + 运营后台/konfi + 接口）。

1. **状态机覆盖**：被测对象全生命周期状态 × 每个状态的可操作行为（如赛事 未开始/进行中/已结束；预测活动 未开始/预测中/进行中但预测结束/待开奖/已开奖/已关闭/已取消退款），特殊组合必须覆盖。
2. **用户视角**：登录态矩阵（未登录/已登录/不同角色）；资产前置（充足/不足/临界/0）；定义并校验「正常参与状态」。
3. **闭环验证**：跨功能串联完整业务闭环（操作→记录→状态流转→结算/发放→流水/明细可查），如 下注→预测记录→开奖→银钻奖励→我的资产-银钻明细；多步骤可执行，不拆孤立单点。
4. **关联功能校验**：主功能与相邻入口联动（如 Pick ↔ Prediction History ↔ Predict More Matches ↔ 我的资产/钱包 ↔ 玩法说明），每个关联入口都要有跳转/展示/回写用例。
5. **异常与边界**：非正常状态操作拦截；取消退款/失败不返还/重复操作/多选下注/超限拦截；单场/单日上限边界值；空态（无数据/无预测/无记录）。
6. **UI / 交互细节**：玩法说明（?）、实时数据变化（赔率 highlight 3s）、成功/失败标识（WIN）、提示语文案、弹窗字段与按钮。
7. **权限与端差异**：用户端 4 入口（安卓/iOS 客户端、PC-web、移动端-web；安卓/iOS 与移动端-web 同套样式但功能略有差异、PC-web 完全功能版）分别覆盖；运营后台（konfi/运营后台）单独覆盖；未登录/越权/权限不足拦截。

## 设计方法（综合运用）

等价类划分、边界值分析、场景法（基本流+备选流）、因果图、正交表（组合>20 时）、错误推测、正确性测试、
容错性测试、安全性测试、接口间测试、数据库测试、压力测试、回归测试、比较测试、兼容性测试、历史版本兼容性测试。
