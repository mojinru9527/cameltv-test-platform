# 功能用例交互增强清单（运行时注入 · 生成时必读）

> 来源：`cameltv-qa-skill-pack v1.1.0` → 本项目适配版。
> 本文件是**生成阶段**的强制检查层，不是回归套件。方法细节见 `../../tests/test-case-standards/interaction-testing/`，
> 历史缺陷模式见 `bug-pattern-digest.md` 与 `.claude/skills/interaction-case-augmenter/references/`。

## 0. 生成链路（强制顺序）

```
功能点清单 → 基础功能用例（正/负/边界）→ 交互风险扫描 → 历史缺陷模式检索
→ 既有用例覆盖判定 → 增强原用例 / 仅在真实缺口新增 → 去重 → 覆盖率自检
```

禁止跳过覆盖判定直接按 Bug 或用例清单堆数量。

## 1. 交互风险扫描维度（按对象选取，不无差别套用）

| # | 维度 | 必查内容 | 适用对象 |
|---|---|---|---|
| 1 | 可发现性 | 入口可见、跳转目标正确、标题与当前位置一致 | 每个页面/菜单 |
| 2 | 控件状态 | 默认/禁用/只读/加载/选中/pending | 按钮、开关、行操作 |
| 3 | 操作反馈 | 成功/失败/pending/进度的时机与文案 | 提交类操作 |
| 4 | 导航与关闭 | 返回、ESC、遮罩点击、抽屉关闭后页面是否仍可操作、滚动锁释放 | 弹窗/抽屉/二级页 |
| 5 | 输入与校验 | 必填、格式、长度、跨字段、校验时机、错误定位 | 表单/搜索框/富文本 |
| 6 | 重复触发 | 连点、双击、弱网重试、防抖与幂等键 | 提交/跳转/点赞 |
| 7 | 中断与恢复 | 取消、超时、重试、失败后保留已填内容 | 异步任务/支付 |
| 8 | 生命周期 | 刷新、重进、切后台/前台、杀进程、重启 | 表单/草稿/登录态 |
| 9 | 权限 | 菜单可见性→按钮→直接路由→直连 API→数据范围（L1–L8） | 全部角色 |
| 10 | 平台差异 | 视口/缩放/输入法/键盘/触控/手势/扫码/安全区 | Web / 小程序 / 平板 |
| 11 | 状态覆盖 | 空/加载/成功/失败/无权限/无数据/资源异常 | 列表/详情/首页 |
| 12 | 后台→C 端 | 保存≠处理完成≠审核通过≠发布≠C 端可读≠页面已展示 | 内容/配置类 |

不适用维度不进入用例；**不得**生成「所有按钮都测 hover/双击/读屏」这类机械清单。

## 2. 覆盖判定（控制用例数量的唯一开关）

| 判定 | 条件 | 动作 |
|---|---|---|
| `COVERED_STRONG` | 既有用例的触发条件 + 检测位置 + 关键 oracle 都能捕获该失效 | 只登记 Pattern/Bug ID，**不新增** |
| `COVERED_PARTIAL` | 有相关用例但缺触发条件或断言 | **增强该用例**步骤/预期，不建平行用例 |
| `GAP` | 无用例能触发并发现该失效，且当前需求适用 | 新增**一条**最小可判定用例 |
| `NOT_APPLICABLE` | 当前需求无该机制 | 跳过并写理由 |
| `NEEDS_CONFIRMATION` | 证据或预期行为不足 | 标 `OPEN` 待确认，不猜测 |

- 多条 Bug 同一失效模式 + 一条用例强覆盖 → 只关联多个 Bug ID。
- 一个需求命中多个模式但同一操作路径 + 同一组独立断言可验证 → 合并进一条用例。
- 标题相似 ≠ 强覆盖，必须核对触发动作与断言。

## 3. 增强写法（可直接落到既有字段）

- **前提条件**：补「环境/数据/角色/状态」前置，如「组件已上架；门店 A 无该商品库存」。
- **操作步骤**：补触发动作，如「连续点击 2 次（间隔 300ms）」「关闭抽屉后立即点击列表第 2 行【查看】」。
- **预期结果**：补可观察断言 + 显式验证手段，如「只创建 1 条记录；DB `hz_order` count +1 且 `business_no` 唯一」。
- **备注**：写 `【增强】BP-xxx；关联 Bug REG-xx`（不新增字段）。
- **标签**：可加 `交互/闭环/状态机/权限/幂等/防抖`。

## 4. 用例预算与输出

- 不设「用例必须增加 X%」目标；允许只增强、只更新台账、零新增。
- 输出统计：`保留原用例数 / 增强原用例数 / 新增用例数 / 强覆盖跳过数 / 不适用数 / 待确认数`。
- 每条新增用例必须写明：未覆盖的 Pattern、检测位置、oracle。

## 5. 质量门禁（Red Flags）

- 减少原需求覆盖 → 退回。
- 按 Bug 数机械生成用例 → 退回。
- `COVERED_STRONG` 仍新增用例 → 退回。
- Bug 派生判断无 Bug ID / Pattern ID 可追溯 → 退回。
- 预期结果只写「成功/报错」无判定标准 → 退回。
- 把 Web 规则套到小程序/平板/硬件 → 退回。
