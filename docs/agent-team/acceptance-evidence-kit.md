# 验收证据库规范

> 事实源：`.claude/skills/cameltv-agent-team/SKILL.md`「验收证据库」。目标：验收/复测不再从零重复劳动。

## 1. 原则

- **复用基线，只跑增量**：已通过的三视口截图、契约、回归矩阵、结果清单作为基线证据；新批只验证本批变更影响的增量，并在 QA 报告中注明「引用基线 + 新增增量」。
- **证据必须可追溯**：每条证据指向提交/文件/命令，禁止"历史通过"这种无锚点引用。
- **失效即刷新**：若基线证据对应模块在本批被修改，该基线作废，必须重跑并替换。

## 2. 建议目录结构

```text
test-platform-v2/work-logs/evidence/
└── batch-{N}-{name}/
    ├── README.md          # 证据索引：覆盖范围、基线/增量、命令、结论
    ├── pc-usage-snapshots/ # 三视口截图（1440×900 / 768×1024 / 390×844）
    ├── contracts/          # 契约/OpenAPI 校验结果
    ├── regression/         # 回归矩阵与结果清单
    └── manifests/          # 数据/环境清单（真实输入清单等）
```

## 3. 索引表字段（README.md）

| 字段 | 说明 |
|------|------|
| 证据 ID | `E{batch}-{seq}` |
| 覆盖范围 | 模块/页面/接口 |
| 类型 | 截图 / 契约 / 回归 / 清单 |
| 基线或增量 | 复用基线 vs 本批新增 |
| 对应提交 | commit 或工件链接 |
| 结论 | PASS / PARTIAL / FAIL |
| 复用规则 | 后续哪类批次可引用 |

## 4. 复用规则

- 同类模块且本批未改动的证据 → 可复用，QA 报告中注明「引用基线 E{n}」。
- 本批改动过的模块 → 必须重跑，不得引用旧基线。
- 外部前置条件解锁（如 Test5、AI/OCR）导致旧"阻塞"结论过期 → 按 C 条件登记流程重新解锁并留新证据。

## 5. 与 C 条件、复盘卡的关系

- 复用的基线证据要能被 `audit-cconditions.ps1` 和 C 条件关闭证据引用。
- 每批验收工作量（新增 vs 复用）计入 QA 复盘卡，用于衡量证据库收益。
