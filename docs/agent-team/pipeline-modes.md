# Agent Team 批次模式：完整 / 轻量

> 事实源：`.claude/skills/cameltv-agent-team/SKILL.md`「批次模式」。本文件为详细判定与豁免记录规范。

## 1. 两档定义

| 档位 | 适用场景 | 强制工件 | 豁免记录 |
|------|---------|---------|---------|
| 完整批次 | 命中任一触发器：新接口 / 新配置 / 新依赖 / Schema 或数据模型变更 / **执行链路变更** / **AI 链路变更** / 权限模型变更 | PRD + PM + Design + Dev（代码+看板）+ QA + Leader 六件 | 无 |
| 轻量批次（**Batch 256 起默认**） | 其余全部：验收 / 修复 / 纯文档 / 纯证据 / 内部流程工具 / UI 调整 / 对外契约不变的重构 | PRD-lite + QA + Leader 三件 + 看板 | PRD-lite 记录 `mode: light` + 理由 |

## 2. 判定流程（Product 第 1 步执行；Batch 256 起改为「默认轻量 + 触发升级」）

```text
需求输入
  ├─ 是否命中任一触发器（新接口 / 新配置 / 新依赖 / Schema 或数据模型 /
  │  执行链路 / AI 链路 / 权限模型 变更）？
  │     ├─ 是 → 完整批次（六部门）
  │     └─ 否 → 轻量批次（PRD-lite + QA + Leader + 看板）——默认档，无需再论证
  └─ 拿不准 → 完整批次
```

> **动因（Batch 256）**：Batch 75–255 期间"拿不准按完整"被反复用于普通修复与 UI 调整，
> 单个批次的文档成本超过了代码成本。改为默认轻量后，风险仍由触发器兜住：
> 执行链路 / AI 链路 / 数据模型的变更永远不会漏到轻量档。

## 3. 轻量批次豁免记录格式

PRD-lite 头部必须含：

```markdown
mode: light
豁免理由: {一句话，指向 SKILL.md 判定标准}
非目标: {明确不做的新行为/新接口/新配置}
```

## 4. 两档共同的强制项（不可因轻量而免除）

- QA 硬门禁（typecheck/build/ruff/import/Alembic，按变更域）
- Leader 判决 + 流程回写 + 复盘卡
- C 条件纳入/豁免 + 看板更新
- PR 审计与用户一次总确认（推送+PR+合入）

## 5. 与 AGENTS.md 的关系

AGENTS.md 的 Git 门禁（分支/PR/审计/确认）对所有批次一视同仁。本文件只定义部门工件档位，不降低 Git 门禁。若 AGENTS.md 后续同步双档措辞，以仓库两个事实源对齐后的版本为准。

## 6. 批次合并与发布节奏（Batch 115 起）

- **同域小修复合并**：多个同域小修复（如本周 UI 修复）归并为一个轻量批次，走一次流水线，而不是每个修复一个批次。
- **纯文档/证据合并**：README/ADR/work-logs 类改动合并提交，不单独开 PR。
- **合代码 ≠ 发版本**：批次合入 main 后不立即发布；版本按发布火车聚合（每 2–3 天或每周 `release/vX.Y.Z`），一次 test 部署 + 一次生产验收。
- 详见 [release-cadence.md](release-cadence.md)。
