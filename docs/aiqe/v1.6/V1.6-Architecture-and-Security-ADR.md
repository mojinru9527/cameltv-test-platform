## ADR-V16-01：目标授权收敛为四态显式决策

**背景**：V1.5 用 `_has_target_policy()` 布尔判断 + `db=None` 兼容开关决定是否走
legacy 执行器；策略解析异常被吞成“无策略”，进而 fail-open。

**决策**：
1. `TargetPolicyResolver.resolve()` 返回不可变 `TargetPolicy`（别名
   `ResolvedExecutionPolicy`），带显式 `PolicyDecision`：
   `ALLOW / DENY / UNAVAILABLE / MISSING_BINDING`。
2. 只有 `ALLOW` 允许创建 Driver；其余决策一律 `BLOCKED` 并记录
   `reason_code`、`policy_id`、`policy_version`、`policy_hash`、`expires_at`。
3. `resolve_execution_policy(db, run, node)` 是唯一解析入口，异常统一转 `UNAVAILABLE`。
4. `execute_node(*, policy_context)` 必填；纯本地节点使用
   `ExecutionCapabilities.NONE` 显式声明无外部能力，禁止用 `None` 表示绕过。
5. 删除 `_execute_http()` / `_execute_db()` / `_has_target_policy()`；
   静态门禁 `scripts/ci/check_aiqe_v16_static_gates.py` 防止回归。

**差异说明（相对计划 §V16-001）**：
- 计划要求 `ResolvedExecutionPolicy.allowed_origins`；实现保留既有
  `allowed_hosts` + `allowed_schemes` + `allowed_ports`（origin 由三者推导），
  避免同时存在两套白名单字段造成判定分叉。
- 计划允许“Environment base_url 作为服务端绑定”；V1.6 明确**移除**该隐式放行：
  `base_url` 不是管理员策略，没有 `TargetPolicyRecord` 一律 `MISSING_BINDING`。
- 新增 `ExecutionCapabilities` 与策略 TTL（默认 300s，每次 claim/重试重新解析）。

**后果**：所有历史 Run/Workflow 必须先迁移策略（`scripts/aiqe/migrate_workflow_target_policy.py`），
无法映射的 Workflow 标记 `NEEDS_POLICY_REVIEW` 并禁止启动。

## ADR-V16-02：浏览器三层防护 + 进程内 egress 代理

**背景**：实测 Playwright 1.61 的 `context.route` **不会**看到 HTTP 重定向目标；
仅靠 route 无法满足“每个 redirect 重新校验”。V1.5 也没有任何浏览器层拦截。

**决策**：
1. **应用层**：`PlaywrightDriver` 在任何浏览器动作前校验主页面/导航 URL。
2. **浏览器层**：`context.route("**/*")` 在 Page 创建前安装；覆盖 iframe/XHR/
   fetch/图片/脚本；`service_workers="block"` 防止 SW 绕过。
3. **出口层**：Runner 进程内 `BrowserEgressProxy`（仅绑定 `127.0.0.1` 随机端口），
   Chromium 以 `--proxy-server` + `--proxy-bypass-list=<-loopback>` + `--disable-quic`
   强制全部流量经过代理：
   - `CONNECT` / 绝对 URI / WebSocket Upgrade 均按 TargetPolicy 校验；
   - 连接**已校验的 IP**（DNS pinning，消除 rebinding 窗口）；
   - 重定向目标在代理层重新校验，失败时用 403 替换 30x，目标服务器零请求；
   - TLS 端到端透传（不 MITM）。
4. **容器层（第四层，V16-024）**：生产 Runner 必须叠加容器/网络命名空间
   egress deny-by-default。进程内代理是纵深防御，不是唯一控制。

**后果**：
- `V16-002-R2` 在容器 egress 落地前保持 `IMPLEMENTED`（不是 `VERIFIED`）。
- 拦截证据写 `security-denials.json` Artifact 与 `security.ssrf_blocked` RunEvent，
  只记录 host/path，不记录 header/query 值。

## ADR-V16-03：凭据以 Secret Handle 跨节点传递

**背景**：V1.5 的 `capture_node_outputs` 直接把 Driver 响应的 token 写入
`outputs_json`，且 Run Detail API 原样返回。

**决策**（目标态，V16-003 实施中）：
1. `RunContext.capture_node_outputs()` 是唯一写入口：输出 schema/分类器判定 SECRET →
   `SecretVault.put()` → 用 `vault://<opaque-id>` Handle 替换；
   Vault 失败即 fail closed，不退回明文。
2. `NodeRun.outputs_json/output_ref`、`StepAttempt.output_summary_json`、
   `RunAssertionResult`、`RunEvent`、Artifact metadata、日志统一走同一个
   `OutputSanitizer`（禁止三套脱敏实现并存）。
3. DB 写入边界执行 `assert_no_secret`；命中即中止提交并产生不含 secret 内容的安全事件。
4. Run Detail API 默认只返回 `***`/`secret://...`；Handle 解析校验
   project/run/producer/consumer/TTL，并写访问审计。
5. 生产 Vault 支持 KMS/envelope encryption；进程内实现仅用于测试。

**差异说明**：`use_external_secret_store` 死配置在 V16-003 中删除或实现，不允许作为
“已支持外部 Secret Store”的虚假信号。

## ADR-V16-04：DB 只读执行只允许服务端 Query Registry

**背景**：V1.5 的 `_execute_db()` 接受 Workflow 自带 inline SQL / allowed_tables /
query_registry，且登记查询路径未把表白名单传给 Driver。

**决策**：
1. DB 节点输入白名单：`{query_key, query_version, params, outputs, assertions}`；
   其余键一律 `WORKFLOW_DB_OVERRIDE` BLOCKED 并落安全事件。
2. Registry 由管理员配置：`QueryDefinition + QueryVersion + QueryExecutionAudit`，
   含 project/environment、SQL hash、参数 schema、allowed tables/columns、
   只读、行数/超时上限、审批人。
3. 执行时绑定变量 + 服务端 tenant 谓词；只读账号 + AST allowlist 为纵深防御。
4. 每次查询落审计（query id/version/hash、脱敏参数、project/env、行数、耗时、
   执行身份、policy decision）。

**后果**：旧 Workflow 的 inline SQL 必须迁移为 Registry 查询，否则 `NEEDS_POLICY_REVIEW`。

## ADR-V16-05：唯一执行入口与不可变冻结快照

**背景**：V1.5 中 triage/regression 各自 `TestRun(status="QUEUED")` 后结束，
不产生 ExecutionJob；复制 DAG 时清空 `depends_on`/`edges`。

**决策**：
1. `launch_run()` 是唯一创建正式执行 Run 的服务；所有执行类型
   （NORMAL / NOISE_EXPERIMENT / DEFECT_REGRESSION）共用 Launch → Preflight →
   ExecutionJob → Worker → DAG → Assertion → Finalize。
2. `LaunchResult` 必须包含 `run_id/run_status/job_ids/node_run_ids/snapshot_hash/
   dispatch_status/blocked_reason`；QUEUED 必须有 Job 或 QueueTicket。
3. 执行只能绑定 `WorkflowSnapshot`（canonical JSON + sha256 + schema version）；
   `SnapshotCloner` 保留全部 depends_on/edges/条件/断言/输出映射。
4. 幂等键唯一约束 `(run_id, node_run_id, attempt_no, execution_kind)`；
   Outbox 与 Run/NodeRun/Job 同事务写，relay 幂等。

## ADR-V16-06：PASS 必须有业务 Oracle

**背景**：V1.5 中“Driver 成功但无断言”的节点直接 `PASSED`，Run 可零业务 Oracle 判 PASS。

**决策**：
1. 节点类别 `BUSINESS/SETUP/CLEANUP/OBSERVE`；BUSINESS 必须有 required 业务断言，
   Validate/Preflight 阶段拒绝空断言。
2. Assertion 结构必须含 `assertion_id/kind/subject/operator/expected/actual_source/
   severity/required/timeout_ms/evidence_required/version`。
3. `PASS` = 实际执行 required business assertions 全部通过且证据可追溯；
   `NOT_EVALUATED/UNKNOWN` 不贡献 PASS。
4. Run PASSED 需要至少一个有效业务 Oracle，且无 FAIL/BLOCKED/ERROR/UNKNOWN。
5. Quality Gate 与 Run Outcome 使用同一 required assertion 集合。

## ADR-V16-07：租户边界在 Service 层强制

**背景**：V1.5 中 Benchmark/Learning/Insights 多个 service 方法无 `project_id`，
`BugPattern` 表无 project 维度。

**决策**：
1. 所有 AIQE service 方法 `project_id` 必填；SQL 查询同时包含 `resource_id` 与
   `project_id`，禁止“先按裸 UUID 查询再由 API 过滤”。
2. 跨项目错误统一 404（避免枚举），或按 API 规范 403，全系统一致。
3. `BugPattern` 增加 project scope；复合唯一约束 `(project_id, pattern_key)`。
4. 测试必须直接调用 Service 层验证跨项目拒绝，不能只测 Router dependency。

## ADR-V16-08：能力状态必须由真实运行证据产生

**背景**：V1.5 中 `mark_verified` 可由脚本/DB 直接写入；验机脚本伪造
`COMPLETED/PASS` Run 后调用 `mark_verified`。

**决策**：
1. 状态 `REGISTERED → AVAILABLE → VERIFIED`，异常时 `DEGRADED/BLOCKED`。
2. 只有成功的 Capability Verification Run（真实 Job/Worker/Driver/Assertion/Artifact）
   才能写 `VERIFIED`；API 不允许直接改状态。
3. 设备断连、Runner 镜像/Driver 版本变化后自动降级。
4. GA 支持矩阵只列 VERIFIED 平台；未实现平台明确 BLOCKED 并对外披露。

## ADR-V16-09：交付治理代码化（V16-025）

**决策**：
1. `docs/aiqe/v1.6/traceability/requirements.yaml` 是唯一事实源；Markdown 矩阵由
   `check_traceability.py --emit-markdown` 生成，禁止手工编辑。
2. `.github/workflows/aiqe-v16-gates.yml` 提供 Traceability / Quality / Unit /
   Runtime-Security / Migration / Evidence 六类 Gate。
3. `.github/CODEOWNERS` 将安全、执行运行时、Agent/Learning、Driver/Device、
   迁移与 CI 映射到责任域。
4. 状态语义：`NOT_STARTED/PARTIAL/IMPLEMENTED` 不计通过率；`VERIFIED` 需要
   正式入口 L2/L3 测试；`ACCEPTED` 需要非原作者 Reviewer。
5. `evidence-index.json` 由 CI 生成并归档 90 天；禁止手工填写测试数量。
