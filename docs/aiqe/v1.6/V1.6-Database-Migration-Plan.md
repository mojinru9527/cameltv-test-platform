## 2. V16-001 数据迁移（历史 Workflow）

1. 备份 `aiqe_workflow_definitions`；
2. `alembic upgrade head`；
3. `python scripts/aiqe/migrate_workflow_target_policy.py --database-url ... --strict`（dry-run）归档报告；
4. 管理员补齐 TargetPolicy 后 `--apply`；
5. 验证：`SELECT policy_status, count(*) FROM aiqe_workflow_definitions GROUP BY 1`；
   `NEEDS_POLICY_REVIEW` 禁止调度。

## 3. 生产执行顺序

1. 备份 DB + 对象存储 Artifact + Vault 元数据；记录 RPO/RTO；
2. staging（生产脱敏副本）演练 upgrade/downgrade；
3. 生产 `alembic upgrade head`（Expand 阶段，无破坏性变更）；
4. 部署应用；观察 Outbox/Reconciler/指标；
5. Contract 阶段（移除旧字段/旧路径）单独发布，需回滚预案；
6. 失败时应用回滚到上一 release tag；数据不可逆迁移使用 forward-fix 或已演练备份恢复。

## 4. 风险与不可逆项

- Secret Handle 明文不可恢复：Vault/KMS 必须单独备份与轮换演练；
- WorkflowSnapshot/CaseCatalog 数据不可回滚（只回应用），downgrade 仅删表；
- 旧 Workflow inline SQL/allowed_hosts 需迁移报告；无法映射者 `NEEDS_POLICY_REVIEW` 暂停。
