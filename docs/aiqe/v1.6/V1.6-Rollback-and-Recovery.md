# V1.6 回滚与恢复

- 触发条件遵循实施计划 §8.6；与 `docs/aiqe/rollback.md`、`V1.6-Production-Runbook.md` 配套
- 原则：**安全不变量优先于可用性**；先止血（停新任务/隔离 Worker），再回滚代码，最后评估数据

---

## 1. 立即停止与回滚的触发条件（任一命中）

| 编号 | 条件 | 立即动作 |
|---|---|---|
| R-01 | 任何 Secret Canary 在持久化数据/日志/Artifact/API 中出现明文 | 停止相关 Worker；隔离数据；启动密钥轮换 |
| R-02 | SSRF 测试目标实际收到被拒绝请求 | 关闭外部执行；回滚到不含该路径的镜像 |
| R-03 | 任意跨 Project 资源访问成功 | 停止对外服务；修复并全量审计访问日志 |
| R-04 | Run PASS 但没有业务 Assertion / Required Evidence | 停止发布；标记相关 Run 为 ERROR；回查断言引擎 |
| R-05 | Noise/Regression 创建 Run 但无 Job，或终态无法收敛 | 暂停回归/实验；Reconciler 修复 + 回滚 |
| R-06 | Worker fencing 失效，迟到结果覆盖新结果 | 停止 Worker；回滚 lease 逻辑；重放 Attempt |
| R-07 | 发布后错误率/延迟超 SLO 且观察窗口无法恢复 | 回滚上一稳定镜像 |

---

## 2. 回滚步骤

### 2.1 应用回滚（5 分钟内）

1. 关闭新任务入口：`AIQE_INPROCESS_EXECUTOR_ENABLED=false`、暂停 Queue 消费；
2. 将 API/Worker/Runner 回滚到上一个 release 镜像（记录 digest）；
3. 保留证据：Run/Job/Artifact/日志快照，禁止清理；
4. 验证：健康检查 + 受控冒烟（Allow 1 次 / Deny 0 次）。

### 2.2 数据回滚

- **首选 forward-fix**；`downgrade` 仅在确认无新写入依赖新列/新表时执行。
- V1.6 迁移 `20261119_v16_001_policy_status` 可安全 `downgrade`（只删列）。
- 不可逆迁移（契约阶段删列/删表）必须：
  1. 事前备份（全量 + WAL 归档）；
  2. 提供 `scripts/aiqe/recover_<issue>.py` 恢复脚本；
  3. staging 演练记录归档 `work-logs/evidence/aiqe-v16/`。

### 2.3 策略与 Secret 回滚

- TargetPolicy 回滚：用 `upsert_target_policy(base_version=...)` 写入上一版本；
  旧版本行保留（`active=false`）可审计。
- **不要**回滚到“没有策略”状态：`MISSING_BINDING` 会让所有 Run BLOCKED（这是预期安全行为）。
- Secret 回滚：撤销泄露 Handle（`revoke_secret_handle`）→ 轮换上游凭据 → 重跑受影响 Run；
  禁止复用旧明文。
