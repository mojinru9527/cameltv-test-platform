## 3. 核心遗漏：V3.9 Reality Gate 延后到 V4.0 的认证项（未被 V4.0 计划承接）

### 3.1 证据来源

以下项在 `work-logs/aitde-v39-ongoing-handoff.md` §3「剩余（未完成，体量大）」与「人工闭环交接」中，被明确标记为**延后至 V4.0 生产发布 + 账号**：CERT-004、CERT-006、§74/75、CI 三 job 真实运行、R6 全量版本认证、真实 PostgreSQL 迁移 drill。

`V3.9_Reality_Gate_..._Plan.md` §112「R6 / V4.0 Transition Gate」要求（全部满足才允许 `V3.9 VERIFIED → V4.0 Cutover`）：

```text
统计阈值：P0 False Pass Rate < 1%｜False Fail Rate < 3%｜P0 Evidence Completeness > 99%
         Replay Audit Consistency > 99%｜Fixture Cleanup Success > 99%
         Production Unauthorized Write = 0｜Secret Leakage = 0｜PII Leakage = 0
         Contract Unauthorized Mutation = 0
认证项：真实 Full Chain PASS｜真实故障注入 PASS｜真实 RED→GREEN PASS｜Temporal Recovery PASS
        Prod RO Certification PASS｜Smart Regression Golden PASS｜AI Evaluation PASS｜Migration Drill PASS
```

`V3.9_Verification_Report.md` §8「【BLOCKED】需真实环境/模型密钥/人工数据」列表给出**本地不可产**项，均属 V4.0 前置。

## 4. 其它发现

### 4.1 版本模型断层（3 处文档不一致）
- `CamelTV_AITDE_Existing_Platform_Full_Upgrade_Implementation_Plan.md` §04「推荐版本线」：`V3.0…V3.8` 后**直接 V4.0**，**无 V3.9**；V3.3.1(v331) 亦未单列。

- `V4.0_Detailed_Development_Implementation_Plan.md`：头部「上一版本依赖：V3.0-V3.8 已全部 VERIFIED」**系陈旧表述**；§90「开工准入条件」同样写「V3.0-V3.8」。

### 4.2 V4.0 开工准入条件（§90）并未满足
`§90` 要求：`V3.0-V3.8 全部 Transition Gate 有记录`、`Cutover 指标达阈值`、`Legacy endpoint usage inventory 完成`、`第三方消费者 owner 确认`、`备份/恢复环境准备完成`。
- **Cutover 指标达阈值**：即 §112/§12 的统计阈值 —— 该组指标（P0 False Pass / Replay Audit Consistency / Secret·PII Leakage 等）**尚未在真实环境采集**（V3.9 BLOCKED），未达成。
- **Legacy endpoint usage inventory**：V4.0 的 V40-001 才做；当前未完成。
- **第三方消费者 owner 确认**：无记录。

> 结论：按 V4.0 自身计划，**现在不满足开工准入**。第一条 V4.0 工作应是「关闭 V3.9 R6/V4.0 过渡门禁 + 完成 Legacy inventory」，而非直接实现 SSO/RBAC。

### 4.3 版本链依赖与「不可跳过」次序
`§04 §3 模块迁移顺序依赖`：Mission → Contract → Scenario → Oracle → Execution/Evidence → Data → Hybrid UI → Worker → Continuous Acceptance → Production Evidence → Impact/Closed Loop。
`§3` 明确「不能先做 Production Autonomous Agent 再补 Contract」。
> 对 V4.0：应先完成 Legacy Cutover（Inventory→Mapping→Cutover Waves）与 V3.9 过渡门禁认证，再谈 Enterprise 补齐（SSO/RBAC/Audit/Retention/HA/DR/Governance）。V40 当前把 Enterprise 与 Cutover 并列，建议按 `Cutover Waves`(§15 Wave 0..9) 顺序编排。

### 4.4 验证报告留档稀疏
- `docs/aitde/validation/` 仅 V3.6、V3.9 有独立 Verification Report；V3.0/3.1/3.2/3.3/3.3.1/3.4/3.5/3.7/3.8 缺失。
- 与 `99 §2 每版发布必须归档`（Alembic Head / OpenAPI / Feature Flags / Domain Invariant / Backend-Frontend Report / Migration / Security / Quality Metrics / Known Limitations / Rollback / Transition Gate）不一致。
- 修复建议：V4.0 收尾统一为各版本补齐「Verification Report」或至少建立「版本归档索引」（在 `99_Cross_Version_Validation` 中列出每版的证据位置）。

## 6. 结论

1. V3.0–V3.9 的**代码级功能**均已交付并合入 main；V3.9 是真正把 V3.0–V3.8「假/记录式/占位」能力校正为「真实/可验证」的版本。
