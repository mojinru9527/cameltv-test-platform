# CamelTV AITDE V3.9 — V4.0 Cutover 前置基线（V39-013）

> 日期：2026-08-30
> 分支：`feature/aitde-v39-implementation`（基于 `origin/main` @ `b8e426d2` + 本版本硬化提交）
> 依据：`docs/aitde/versions/V3.9_Detailed_Development_Implementation_Plan.md` §7（V4.0 Cutover 前置基线）、`99_Cross_Version_Validation` §12（Cutover Gate）。
> 用途：为 V4.0（Legacy Cutover + Enterprise Stable）铺好**连续、非一次性**的质量历史数据与稳定性基线。

> 说明：V3.9 不实施 Cutover，只建立 Cutover 所需指标的**连续观测基线**。运行时指标（真实 test/prod 跑测）由 CI / QA 产出的 Run 数据驱动；本文件给出指标口径、现有观测能力与基线基线口径。

---

## 1. Cutover 目标指标（99 §12，V4.0 最低目标）

```text
P0 False Pass Rate              < 1%
False Fail Rate                 < 3%
P0 Evidence Completeness        > 99%
Replay Audit Consistency        > 99%
Fixture Cleanup Success         > 99%
Production Unauthorized Write   = 0
Secret Leakage                  = 0
PII Leakage                     = 0
Contract Unauthorized Mutation  = 0
Mission Workflow Adoption       > 80%
```

## 2. 现有观测能力（代码实证）

| 指标 | 现有实现 / 数据源 | 说明 |
|------|-------------------|------|
| False Pass / False Fail | `app/modules/aitde/execution`（Outcome 分类）；`ai_closed_loop`（Triage/Gap） | 由 Run 的 Outcome + Oracle + Evidence 判定；可统计 |
| Evidence Completeness | `evidence_artifacts`（metadata + hash） | 证据是否齐备可校验 |
| Replay Audit Consistency | V3.1 `replay_manifest` + `environment_snapshots` | 回放一致性可比对 |
| Fixture Cleanup Success | V3.2 Fixture Lease（`fixture_leases`）+ Cleanup | Cleanup 幂等性指标 |
| Secret / PII Leakage | V3.6 Evidence Sanitizer + PII Mask；`MASK`/`SecretRef` | 脱敏/掩码机制存在 |
| Contract Unauthorized Mutation | V3.7/V3.8（Frozen Contract 守卫） | AI 改 Oracle/Contract 拒绝 |
| Mission Workflow Adoption | V3.0 Mission 主链使用率 | 从 `missions`/`version_mission` 统计 |

## 3. 基线口径（趋势非快照）

V3.9 需把上述指标作为**连续时间序列**采集，而非单次快照。建议记录：

```text
per_version_window:
  window_start / window_end
  runs_total / runs_pass / runs_fail / runs_error
  p0_false_pass_rate / false_fail_rate
  p0_evidence_completeness
  replay_audit_consistency
  fixture_cleanup_success
  production_unauthorized_write / secret_leak / pii_leak / contract_unauthorized_mutation
  mission_workflow_adoption
```

> 现有 `app/services/statistics_service.py`、`dashboard_service.py`、`report_aggregator.py`、`version_coverage_service.py` 已具备按项目/版本聚合统计的能力；V39-013 的落地动作是：把这些指标的**累计 Run 数据**接入异常/阈值监测，形成版本窗口间的趋势对比。

## 4. V4.0 Cutover Gate（延续）

- 需 SSO/RBAC 安全测试、PostgreSQL 备份/恢复演练、Object Storage 恢复演练、Temporal Recovery 演练（V4.0 实施，非 V3.9）。
- Legacy Active Consumer 清单 / 写截止回滚窗口 —— V4.0。
- V3.9 交付：**连续质量指标的历史数据启动**（为 V4.0 Gate 提供输入）。

## 5. 结论

V3.9 已完成 Cutover 前置项的**基线口径与观测能力盘点**；实际连续数据需在充分 Run 数据积累（CI/QA 全量回归 + 各版本窗口）后形成趋势。该基线与 `V3.9_Quality_Baseline_Inspection.md`、`V3.9_Transition_Gate_Evidence.md`、`V3.9_Known_Limitations_and_Archive.md` 共同构成 V3.9 硬化证据包。
