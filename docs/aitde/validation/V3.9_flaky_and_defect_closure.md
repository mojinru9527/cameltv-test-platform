## A. V39-008 ｜ Flaky 收敛

### A1. 收敛策略（沿用 V3.9 方案 §4.1）
- 只把 **AUTOMATION / ENV 波动** 纳入 Flaky；**BUSINESS_FAIL 默认排除、不自动吞掉**。
- 收敛目标：P0/P1 场景在 test 环境 **3 连跑无随机失败**；Clusters 可回链样本 Run。
- 运行时证据（`run` 数据的 3 连跑统计）需 **test 环境 + 连续 Run**，超出离线沙箱。

### A2. 离线可观察证据
覆盖回归（`pytest tests/aitde`）中发现 1 例集成竞态，登记为 Flaky 候选：

| 用例 | 根因 | 归类 |
|------|------|------|
| `tests/aitde/v34/test_approval_workflow.py::test_approval_gate_reject_aborts_before_dangerous_step` | `temporalio.service.RPCError: workflow execution already completed` —— 依赖本地 Temporal Server（`localhost:29795`），workflow 在 reject signal 前已完成 | **ENV/INTEGRATION 竞态**（非 BUSINESS_FAIL、非 V3.9 变更引入） |

> 处理：该用例依赖 Temporal 服务，属集成测试；不应被标为 BUSINESS_FAIL，也不应静默通过。
> 其运行稳定性证据由 CI 全量 + Temporal 服务兜底。

### A3. Flaky 检测机制
- `test-platform-v2/backend/tests/aitde/v38/test_flaky_detector.py`（✅ 通过）：Flaky 判定逻辑的定位
  与「不吞 BUSINESS_FAIL」守卫已具备。

### A4. 【BLOCKED】项与证据路径
- **P0/P1 3 连跑实证**：需 test 环境 + 连续 Run 数据 → `BLOCKED:CI`（`pr-check.yml` 每日观察 +
