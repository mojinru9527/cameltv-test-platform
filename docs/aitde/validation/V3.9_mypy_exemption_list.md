## 3. 根因归类

- **系统性 ORM 硬墙（占多数，attr-defined/assignment/union-attr）**：`from __future__ import
  annotations` + SQLAlchemy 2.0 `Mapped[]` 声明式模型，`Mapped` 列在类型检查器看来与运行时
  不一致；`db.get(...)` / `db.scalar(...)` 的 `Model | None` 未收窄。这类多为「类型系统表达
  不了 ORM 运行时行为」的墙，**离线安全清理已到边际**——继续改会为满足 mypy 而引入
  `assert`/`cast` 噪声甚至改变运行时语义，风险大于收益。
- **真类型错误（arg-type 一部分、operator、call-overload）**：`APIException()` 参数、枚举
  `.value`、缺参与签名不匹配。V3.9 已尽可能修掉可安全部分（见 §4）。

## 4. 本分支已修复（V39-003 落地）

两个 `fix(aitde-v39-continue)` 提交共修复以下可离线安全项：

- `cookie_samesite`：`Literal["lax","strict","none"]` 类型校正（修复 `arg-type`）。
- `playground_service`：`duration_ms`/`stdout`/`stderr` 的 `None` 收窄（`union-attr`）。
- `diff` 中 `risk_hint` 可为 `None`/`''` 的处理（`union-attr`）。
- `openvpn` 配置 `str` keys 收窄。

对比基线（244 → 112），**离线安全修复减少 132 项**，并把剩余项从「可修」收敛到
「ORM 硬墙 / 需真实调用上下文」。

## 5. 分级决策（V3.9 定稿）

- **核心模块优先**（`mission/scenario/execution/data/healing`）：未来每个版本把这几域的
  错误数作为「只减不增」观测项；V3.9 未强推清零以规避为类型检查而改运行时语义。
- **豁免可追踪**：凡无法在离线安全范围内修复的错误，在本清单逐条登记（按文件 + 错误码），
  不通过 `disable_error_code` 静默隐藏（已在 `pyproject.toml [tool.mypy]` 注释中明确此决策）。
- **不阻断硬门禁**：mypy 观测基线为 112；硬门禁（ruff F821）保持 0。
