# 0. 版本目标

> **把现有 API/UI/TestExecution 的执行事实统一到 Scenario → ExecutionRun → Assertion → Evidence → Replay，并第一次从架构上控制假成功、假失败。**

全版本共享不变量：

```text
Frozen Contract 不可直接修改
ScenarioVersion 精确绑定 ContractVersion
AI 不拥有正式 PASS/FAIL 裁决权
Required Oracle + Deterministic Assertion + Evidence 才能形成可信 PASS
Runtime/Data/Environment 问题不能伪装成 BUSINESS_FAIL
Production 默认只读
```

# 2. 核心架构

```text
TestScenarioVersion
        │
        ▼
ScenarioAdapter
        │
        ▼
ExecutionRun
        │
        ├─ ExecutionStep
        ├─ AssertionResult
        ├─ EvidenceArtifact
        └─ EnvironmentSnapshot
                 │
                 ▼
          OutcomeClassifier
                 │
                 ▼
            ReplayManifest
```

规则：

1. Run 永远绑定 `scenario_version_id + contract_version_id + environment_snapshot_id`。
2. `runtime_status` 与 `outcome` 分离。
3. AI 不参与正式 Outcome 计算。
4. PASS 必须满足 Required Oracle 全部已评估且 Required Evidence 完整。
5. Legacy API/UI Runner 先通过 Bridge 接入，不在本版删除。

# 5. Service / Class

- `ScenarioAdapterService`：把 ScenarioVersion 与已有 API/UI 资产或未来 Runtime Adapter 绑定。
- `EnvironmentSnapshotService`：Run 前捕获环境版本；识别不到时允许 tester build_label，但生成 fingerprint_hash。
- `ExecutionRunService`：创建 Run、状态迁移、取消、retry child run。
- `LegacyExecutionBridge`：ApiExecutionTaskItem / UiTestRun / TestExecution → 统一 Step/Evidence。
- `AssertionEngine`：消费 TestOracle 与 Observation/Evidence，不调用 LLM。
- `EvidenceService`：Artifact metadata、hash、storage、sanitization。
- `EvidenceSanitizer`：Authorization/Cookie/token/password/secret 清洗；未 SANITIZED 不可成为正式 Replay。
- `OutcomeClassifier`：确定性决策表。
- `EvidenceCompletenessPolicy`：定义各 Adapter/Oracle 的 Required Evidence。
- `ReplayService`：生成 append-only Timeline 与 ReplayManifest。

# 6. Outcome 决策表

严格顺序：

```text
ENV hard error
  → ENV_FAIL

DATA error
  → DATA_FAIL

runtime / automation error before business oracle
  → AUTOMATION_FAIL

assertion evaluator error
  → ASSERTION_ERROR

required oracle FAIL
  → BUSINESS_FAIL

required oracle NOT_EVALUATED
  → INCONCLUSIVE

all required oracle PASS
AND required evidence COMPLETE
  → PASS

else
  → INCONCLUSIVE
```

禁止：

```text
HTTP 200 → PASS
看到 Toast → PASS
脚本 exception → BUSINESS_FAIL
```

# 7. Backend API

- `POST   /api/v2/scenarios/{id}/adapters` — 创建/绑定 Adapter
- `GET    /api/v2/scenarios/{id}/adapters` — 查看 Adapter
- `POST   /api/v2/scenarios/{id}/runs` — 创建统一 Run
- `GET    /api/v2/runs/{run_id}` — Run 详情
- `POST   /api/v2/runs/{run_id}/cancel` — 取消
- `POST   /api/v2/runs/{run_id}/retry` — 创建 retry child run
- `GET    /api/v2/runs/{run_id}/steps` — Timeline
- `GET    /api/v2/runs/{run_id}/assertions` — Oracle 结果
- `GET    /api/v2/runs/{run_id}/evidence` — 证据元数据
- `GET    /api/v2/runs/{run_id}/replay` — Replay manifest
- `GET    /api/v2/missions/{id}/executions` — Mission Run 列表
- `POST   /api/v2/legacy-executions/{type}/{id}/link` — 桥接历史执行
- `POST   /api/v2/environments/{id}/snapshots` — 环境快照

# 98. 前后端联调顺序

```text
Round 1  ScenarioAdapter + EnvironmentSnapshot API ↔ Mission Scenario UI
Round 2  ExecutionRun/Step API ↔ Run Detail
Round 3  API Legacy Bridge ↔ Execution Center
Round 4  UI Legacy Bridge ↔ Evidence Viewer
Round 5  Assertion/Outcome ↔ Why PASS / Failure Classification
Round 6  ReplayManifest ↔ Replay 三栏页面
Round 7  Shadow Audit ↔ Tester False Pass/False Fail Feedback
```

每一 Round 完成后先用固定 Scenario Fixture 联调，再进入下一 Round。
