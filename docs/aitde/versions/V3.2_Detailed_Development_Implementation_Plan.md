# 0. 版本目标

> **把测试数据从 CSV/JSON 参数提升为 Scenario 的一等运行时能力：声明数据需求、自动寻找/构造、租约隔离、DB 校验、Before/After 快照和幂等 Cleanup。**

全版本共享不变量：

```text
Frozen Contract 不可直接修改
ScenarioVersion 精确绑定 ContractVersion
AI 不拥有正式 PASS/FAIL 裁决权
Required Oracle + Deterministic Assertion + Evidence 才能形成可信 PASS
Runtime/Data/Environment 问题不能伪装成 BUSINESS_FAIL
Production 默认只读
```

# 2. 核心原则

Scenario 描述：

```text
membership.status = EXPIRED
wallet.balance >= 100
user.enabled = true
```

而不是：

```sql
UPDATE ...
```

执行：

```text
DataRequirement
→ DataPlanner
→ DataPlan
→ Policy Check
→ Provision
→ Lease
→ Snapshot Before
→ Run
→ Snapshot After
→ Cleanup
→ Cleanup Verify
```

数据准备失败：

```text
DATA_FAIL
```

不能污染业务结果。

# 5. Service / Class

- `DataRequirementService`：从 Scenario Given/Expected/Oracle 推导候选业务数据需求，Tester 可修订。
- `DataPlanner`：按项目策略选择 EXISTING → API → DB_FIXTURE → WORKFLOW，输出 Plan，不直接执行。
- `DataPlanPolicy`：按环境、access mode、schema/table allowlist、风险等级检查。
- `ExistingDataFinder`：只读搜索测试数据，并根据约束验证后创建 Lease。
- `ApiDataBuilder`：通过测试环境 API 创建数据，所有创建实体记入 Fixture Manifest。
- `DbFixtureBuilder`：受控 INSERT/UPDATE，仅测试环境 allowlist；事务、timeout、影响行数限制。
- `WorkflowDataBuilder`：提供业务流程构造接口，本版不依赖 AI Browser。
- `FixtureService`：状态机 PROVISION→READY→LEASED→IN_USE→CLEANING→CLEANED。
- `FixtureLeaseService`：并发隔离、TTL、释放。
- `DataSnapshotService`：Before/After/Cleanup Verify，进入 V3.1 Evidence。
- `CleanupService`：补偿动作、幂等重复清理。
- `DatabaseAssertionEvaluator`：接入 V3.1 AssertionEngine，执行 DB Oracle。

# 6. Data Planner 策略

默认优先级：

```text
1 Existing Test Data
2 API Builder
3 DB Fixture
4 Workflow Builder
```

策略升级不得静默发生：

```text
Existing 找不到
→ DB Fixture（高风险项目）
```

如果项目策略要求审批，必须进入 APPROVED。

禁止：

```text
AI 自动改 data_source access_mode
AI 自动新增 schema/table allowlist
AI 直接执行自由 SQL
失败后偷偷换更高风险策略
```

# 8. Execution 集成

Timeline 新增：

```text
DATA PLAN
DATA FIND / CREATE
LEASE
DB BEFORE
ACTION...
DB AFTER
ASSERT DB
CLEANUP
CLEANUP VERIFY
```

Evidence Type：

```text
FIXTURE_MANIFEST
DATA_PLAN
DB_BEFORE
DB_AFTER
DB_CLEANUP_VERIFY
```

如果 Data Plan/Fixture 失败：

```text
ExecutionRun.outcome = DATA_FAIL
```

若 Cleanup 失败但业务 Oracle 已评估：

- 正式业务 Outcome 保留；
- Run 增加 cleanup health；
- Quality Gate 可按策略阻断；
- 不能静默忽略脏数据。
