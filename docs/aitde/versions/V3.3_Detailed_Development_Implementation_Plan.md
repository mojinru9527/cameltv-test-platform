# 0. 版本目标

> **让同一个 Scenario 在功能测试阶段就能使用：自动造数、Tester/AI 浏览器动作、API/DB/UI Oracle、Observe/Record 转回归 Adapter，并用统一 Replay 审计。**

全版本共享不变量：

```text
Frozen Contract 不可直接修改
ScenarioVersion 精确绑定 ContractVersion
AI 不拥有正式 PASS/FAIL 裁决权
Required Oracle + Deterministic Assertion + Evidence 才能形成可信 PASS
Runtime/Data/Environment 问题不能伪装成 BUSINESS_FAIL
Production 默认只读
```

# 3. Command IR

新 Scenario 的正式 UI 执行输入是声明式 IR，而不是 LLM 任意代码：

```json
{
  "schema_version": "1.0",
  "commands": [
    {"id":"1","driver":"data","action":"ensure","input":{"requirement_ref":"expired-member"}},
    {"id":"2","driver":"browser","action":"goto","input":{"route":"/member"}},
    {"id":"3","driver":"browser","action":"click","input":{
      "locator":{"strategy":"role","role":"button","name":"立即续费"}
    }},
    {"id":"4","driver":"assertion","action":"evaluate","input":{"oracle_key":"ui-member-active"}},
    {"id":"5","driver":"assertion","action":"evaluate","input":{"oracle_key":"db-member-active"}}
  ]
}
```

执行前：

```text
Schema Validate
→ Contract/Scenario Version Validate
→ Policy Validate
→ Capability Validate
→ Execute
```

# 5. 四种浏览器模式

## Explore

AI 动态查找页面/路径，用于首次理解，不作为默认持续回归。

## Regression

只执行 Approved CommandPlan；不允许每次重新生成 Expected。

## Observe

Tester 自己操作，系统记录 DOM/点击/输入/XHR/navigation，结束后生成 ActionPlan Candidate。

## Manual Assist

系统自动准备 Fixture，Tester 按 Functional Projection 手工操作，后台自动捕获 Evidence 并执行 API/DB/UI Oracle。

# 6. Backend Service / Class

- `CommandSchemaRegistry`：注册 driver/action/schema/version。
- `ActionPlanner`：When → Command IR Candidate。
- `CommandPlanService`：版本、validate、approve、active、stale。
- `BrowserRuntimeDriver`：Playwright 正式执行。
- `BrowserObserverService`：Observe event 标准化。
- `ManualExecutionService`：人工 step 状态与证据。
- `HybridExecutionCoordinator`：V3.3 临时编排 Data→Browser/API→Assertion→Cleanup；V3.4 替换调度层但保留接口。
- `UiOracleEvaluator`：DOM/text/attribute/visible/state 确定性断言。
- `ActionHealingService`：只创建 Action diff Proposal。
- `LegacyPlaywrightCompilerAdapter`：旧 spec.ts 继续运行；新 Scenario 走 Command IR。

# 7. Backend API

- `POST   /api/v2/scenarios/{id}/action-plans/generate` — 生成 Command IR Candidate
- `GET    /api/v2/scenarios/{id}/action-plans` — Plan 版本
- `POST   /api/v2/action-plans/{id}/validate` — Schema/Policy 校验
- `POST   /api/v2/action-plans/{id}/approve` — 批准
- `POST   /api/v2/browser-sessions` — 启动 Explore/Observe/Manual
- `POST   /api/v2/browser-sessions/{id}/stop` — 结束
- `GET    /api/v2/browser-sessions/{id}/events` — 观察事件
- `POST   /api/v2/browser-sessions/{id}/derive-action-plan` — 观察转 Plan
- `POST   /api/v2/scenarios/{id}/manual-sessions` — 人工辅助执行
- `POST   /api/v2/manual-sessions/{id}/steps/{step}/complete` — 人工步骤
- `POST   /api/v2/scenarios/{id}/hybrid-runs` — 混合执行
- `GET    /api/v2/healing-proposals` — Healing 建议
- `POST   /api/v2/healing-proposals/{id}/approve` — 批准 Action 修复

# 8. `case_compiler_service` 重构

保留：

```text
Legacy TestCase → LLM/Playwright Spec
```

新主路径：

```text
Scenario When
→ AI ActionPlanner
→ Command IR
→ deterministic Playwright action compiler

Frozen Oracle
→ deterministic assertion compiler
```

禁止新 Scenario 将 `expected_result` 交给 LLM 随意生成 `expect()`。
