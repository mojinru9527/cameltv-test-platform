# 0. 版本目标

> **把 Hybrid Runtime 从单机/旧队列升级为可恢复、可重试、跨内网、带 Secret/Policy/mTLS 边界的 Durable Test Runtime。**

全版本共享不变量：

```text
Frozen Contract 不可直接修改
ScenarioVersion 精确绑定 ContractVersion
AI 不拥有正式 PASS/FAIL 裁决权
Required Oracle + Deterministic Assertion + Evidence 才能形成可信 PASS
Runtime/Data/Environment 问题不能伪装成 BUSINESS_FAIL
Production 默认只读
```

# 1. 目标架构

```text
Control Plane
  ├ FastAPI
  ├ PostgreSQL
  ├ Object Storage
  ├ Temporal
  ├ Policy Gateway
  └ Secret Metadata
```

Worker 使用 Pull 模式；Control Plane 不主动拨入各内网。

# 2. Workflow 设计

```text
capture_environment_snapshot
→ plan_data
→ ensure_fixture
→ compile/resolve_command_plan
→ policy_check
→ execute_commands
→ evaluate_oracles
→ collect_evidence
→ classify_outcome
→ cleanup_fixture
→ build_replay
```

每个 Activity 定义：

```text
start_to_close_timeout
schedule_to_close_timeout
retry_policy
heartbeat_timeout（长 Browser/Data Activity）

```

Cleanup 放 `finally/compensation` 路径。

## `MissionDesignWorkflow`（P1）

可逐步把 V3.0 AI Job 迁入：

```text
scope analyze
→ wait tester signal
→ ambiguity/intent
→ wait
→ contract
→ wait freeze
→ scenario
```

Human Review 通过 Signal/Update，而不是数据库轮询流程状态作为唯一控制。

# 4. Worker 注册与路由

Worker 启动：

```text
Load Machine Identity
→ mTLS Authenticate
→ Register Metadata
→ Join allowed Temporal TaskQueue
→ Heartbeat Worker Registry
```

路由输入：

```text
network_zone
required capabilities
project tags
policy
```

LLM 不选择具体机器。

# 5. Secret

Secret value 只在 Worker 运行时解析：

```text
Control Plane
  secret_ref only
      ↓
Temporal Activity gets ref
      ↓
Worker local resolver
      ↓
process memory
      ↓
Driver
      ↓
discard
```

绝对禁止 Secret value 出现在：

```text
Temporal Workflow History
CommandPlan JSON
ExecutionStep input/output
Evidence
AI Prompt
普通日志
```

# 6. Policy Gateway

统一接口：

```json
{
  "actor": "user/worker",
  "project_id": 1,
  "environment_id": 5,
  "network_zone": "TEST",
  "driver": "database",
  "action": "fixture_update",
  "target": {"schema":"member_test","table":"membership"}
}
```

返回：

```text
ALLOW
DENY
REQUIRE_APPROVAL
```

所有危险 Driver 必须后端执行 Policy，不接受“前端按钮隐藏”作为安全边界。

# 7. Service / Class

- `TemporalWorkflowGateway`：start/signal/query/cancel。
- `ScenarioExecutionWorkflow`：只负责编排，不含 DB/UI 细节。
- `ExecutionActivities`：封装 Data/API/Browser/Assertion/Evidence Driver。
- `WorkerRegistryService`：注册、heartbeat、drain、disable。
- `TaskQueueRouter`：zone/capability/tag → queue。
- `SecretRefService`：只管理 metadata，不向前端返回 secret。
- `WorkerSecretResolver`：本地 resolver。
- `PolicyGateway`：OPA 或自研 Provider Adapter。
- `ApprovalService`：REQUIRE_APPROVAL 持久化，审批后 Signal Workflow。
- `IdempotencyService`：Run/Data/Cleanup 等重复调用保护。
- `LegacyQueueBridge`：把 V3 Scenario 从旧 API/UI queue 逐步迁至 Temporal。

# 8. Backend API

- `GET    /api/v2/workers` — Worker 列表
- `GET    /api/v2/workers/{id}` — 详情/能力
- `POST   /api/v2/workers/{id}/drain` — 排空
- `POST   /api/v2/workers/{id}/disable` — 禁用
- `GET    /api/v2/workflows/{id}` — Workflow 状态
- `POST   /api/v2/runs/{id}/resume` — 恢复
- `POST   /api/v2/runs/{id}/retry-step` — 受控重试
- `GET    /api/v2/approvals` — 审批列表
- `POST   /api/v2/approvals/{id}/approve` — 批准
- `POST   /api/v2/approvals/{id}/reject` — 拒绝
- `GET    /api/v2/policy-profiles` — Policy
- `POST   /api/v2/secret-refs` — 创建 Secret 引用 metadata

# 9. 旧 Queue 迁移

分步：

```text
1. Temporal 只跑新 V3 Scenario
2. API Runner 包成 Activity
3. UI Runner 包成 Activity
4. 新 V3 Run 停止写旧 queue
5. Legacy 页面仍可走旧 queue
6. V4.0 再真正退役
```

不要在本版把所有 DSH/Schedule 一次迁完。
