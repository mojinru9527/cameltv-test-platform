# 0. 版本目标

> **在证据充分和权限受控的前提下，让 AI 承担失败归因、Action 修复建议、Flaky 识别、数据策略优化和测试缺口发现，但仍不允许越权修改 Frozen Oracle。**

全版本共享不变量：

```text
Frozen Contract 不可直接修改
ScenarioVersion 精确绑定 ContractVersion
AI 不拥有正式 PASS/FAIL 裁决权
Required Oracle + Deterministic Assertion + Evidence 才能形成可信 PASS
Runtime/Data/Environment 问题不能伪装成 BUSINESS_FAIL
Production 默认只读
```

# 1. 闭环边界

允许：

```text
Failure Hypothesis
失败证据总结
Action Healing Proposal
已批准修复后的自动重试
Flaky 统计/聚类
Data Strategy 建议
Scenario Gap Proposal
Tester Feedback Learning
Prompt/Model Evaluation
```

禁止：

```text
修改 Frozen Contract
修改 Required Oracle Expected
把生产当前行为直接认定为标准
删除/跳过 P0 Scenario
提升权限
自动关闭正式业务缺陷
```

AI 是增强层，不是事实层。

# 3. Service / Agent

- `FailureEvidencePackBuilder`：从 Proof Bundle 构造最小必要、已脱敏上下文。
- `FailureTriageAgent`：只产出 hypothesis，不改变 Outcome。
- `ActionHealingAdvisor`：扩展 V3.3 Healing，仍只 Action diff。
- `HealingPolicy`：强制 Oracle/Contract diff 为空。
- `FlakyDetector`：基于历史 Run/Step signature/Outcome 聚类。
- `DataStrategyAdvisor`：基于 strategy_performance 给 DataPlanner 建议，不越权。
- `ScenarioGapDetector`：结合 Prod Evidence、Defect、Coverage、Repeated Failure 生成 Gap Candidate。
- `HumanFeedbackService`：记录 Tester 对 AI/规则的纠正。
- `PromptEvaluationService`：Golden Suite 比较 Model/Prompt Version。
- `AutoRetryPolicy`：仅 transient AUTOMATION/ENV 或 Approved Healing 可自动 retry。

# 4. Failure Triage Prompt

`failure_triage_v1.md` 输入：

```text
正式 Outcome（已确定）
Scenario / Contract refs
Assertion failures
Timeline
Sanitized API/UI/DB evidence
EnvironmentSnapshot
Historical same-signature samples（可选）
```

输出：

```json
{
  "classification": "BUSINESS_LOGIC_SUSPECTED",
  "confidence": 0.87,
  "evidence_refs": ["..."],
  "summary": "...",
  "suggested_checks": ["..."]
}
```

不得输出新的正式 Outcome。

# 5. Healing

可修：

```text
locator
wait strategy
navigation non-business step
browser synchronization
```

不可修：

```text
Expected
Oracle
Contract Rule
Production Policy
```

所有 Apply：

```text
Old CommandPlanVersion
→ Healing Proposal
→ Approve
→ New CommandPlanVersion
→ Validation Run
```

旧历史 Replay 永不重写。

# 6. Flaky 判定

不能使用简单规则：

```text
失败 → 重跑通过 → flaky
```

要结合：

```text
adapter
step_key
error_type
locator/api target
environment
browser
sample_size
```

只把 AUTOMATION/ENV 波动纳入 Flaky；BUSINESS_FAIL 默认排除。

# 7. Data Strategy Learning

统计：

```text
Existing Data success/duration
API Builder success/duration
DB Fixture success/duration
Workflow success/duration
```

AI 可建议优先顺序，但：

```text
Policy
Environment access mode
Approval requirement
```

永远优先于 AI 推荐。

# 8. Scenario Gap

输入可来自：

```text
Production new state
Historical defect
Repeated business failure
Uncovered Contract Rule
Uncovered Observed Journey
New OpenAPI state/error
```

输出 `scenario_gap_candidate`。

转正式 Scenario：

```text
Gap
→ Tester Review
→ Contract/Scenario Change Proposal
→ New Version
```

不能直接写正式 Scenario Expected。

    # 93. 版本完成后的专项校验与检查

    > 开发完成后必须单独执行本节。代码合并不等于版本验证完成。

    - [ ] 至少 100 个已人工分类失败 Run 评估 Triage Accuracy/Confusion Matrix
- [ ] 对诱导 AI 修改 Oracle 的测试，后端拒绝率=100%
- [ ] Healing Apply 产生新 CommandPlanVersion，历史 Replay 不改变
- [ ] 至少 30 个 locator 变化评估 Healing 成功/误修率
- [ ] 真实 BusinessFail 连续 retry 不自动标 flaky/通过
- [ ] Flaky 可回链样本 Run
- [ ] Data Strategy 推荐危险策略仍被 Policy 拒绝
- [ ] Gap 转 Scenario 必须走 Review/Version
- [ ] 模型/Prompt 更新 Golden 不达阈值阻止发布
- [ ] P0 Suggestion 批量批准二次确认

    # 94. Release Gate
