## 全链路硬化与稳定（Full-Chain Hardening & Stabilization）

> 文档版本：1.0
> 日期：2026-08-30
> 适用仓库：`mojinru9527/cameltv-test-platform`
> 上一版本依赖：V3.8 VERIFIED：AI QA Closed Loop（#368 合入 `main`）
> 下一目标版本：V4.0 Legacy Cutover + Enterprise Stable
> 用途：在进入 V4.0 大版本前，把 V3.0–V3.8 全链路做一次系统性硬化与稳定——关闭质量债务、收敛 Flaky、清零 P1/P2、达成 V3.8→V4.0 过渡门禁，并为 V4.0 Cutover 累积连续、可审计的质量基线。直接拆 Epic / Issue / PR、Quality Gate、四层回归、测试与发布验收。

# 0. 版本目标

> **在进入大规模 Legacy Cutover（V4.0）之前，先让 V3.0–V3.8 全链路在质量、稳定、可信、可运维上达到可发布基线，并为 V4.0 准备连续的、非一次性的质量历史数据。**

本版本只做「硬化 / 稳定 / 补齐 / 治理」，**不新增新业务模型，不做 Legacy Cutover**（那属于 V4.0）。

全版本共享不变量（沿用 V3.0–V3.8，V3.8 起 AI 升格为受控增强层）：

```text
Frozen Contract 不可直接修改
ScenarioVersion 精确绑定 ContractVersion
AI_INFERRED 不能静默成为 Required Oracle
PASS 必须来自 Required Oracle + Deterministic Assertion + Evidence
Runtime/Data/Environment 问题不能伪装成 BUSINESS_FAIL
Auto Healing 只能修改 Action，不修改 Oracle/Contract
Production 默认只读，数据库账号本身必须真正只读
Secret/PII 不进入 Prompt / Workflow History / Evidence / 普通日志
所有跨项目访问都做授权
所有正式事实可追溯 Source / Version / Audit
```

# 1. 为什么是 V3.9：插入硬化版而非直奔 V4.0

V4.0 含 Legacy Cutover + Enterprise Stable（SSO/RBAC/Audit/Retention/Encryption/HA/Backup/Secret Rotation/Model Governance/Cost Governance/Release Gate），并要求 Cutover 目标指标：

```text
P0 False Pass Rate              < 1%
False Fail Rate                 < 3%
P0 Evidence Completeness        > 99%
Replay Audit Consistency        > 99%
Fixture Cleanup Success         > 99%
Production Unauthorized Write   = 0
Secret Leakage                  = 0
PII Leakage                     = 0
Contract Unauthorized Mutation  = 0
Mission Workflow Adoption       > 80%
```

这些指标依赖「连续历史数据」而非一次性快照。`99_Cross_Version_Validation_and_GoLive_Gates.md` 第 11 节（V3.8 → V4.0）也明确：

```text
Failure Triage Benchmark 达团队阈值
AI 修改 Frozen Oracle 的拒绝率 = 100%
Healing 只产生新 ActionPlanVersion
BUSINESS_FAIL 不被 Flaky 自动吞掉
Suggestion/Gap 正式应用均经过 Review
Prompt/Model 更新有 Golden Evaluation
所有 AI 自动能力有 Kill Switch
Cutover 所需质量指标已有连续历史数据
```

若在 V3.8 后直接进 V4.0，等于一边做大剪接、一边靠一次性快照放行，风险不可控。因此插入 **V3.9 全链路硬化与稳定版**：

| 硬化目标 | 面向谁 |
|---|---|
| 四层回归（新增 / 不变量 / Legacy / 跨版本）稳定 | 证明 V3.0–V3.8 聚合后不退化 |
| 质量债务关闭（Ruff / mypy / 覆盖率 / a11y） | 让 CI 硬门禁全绿、可信 |
| P1/P2 Defect 清零 | 减少 V4.0 期间被旧缺陷干扰 |
| Flaky 收敛 + Run 数据累积 | 为 V4.0 Cutover 提供连续质量基线 |
| V3.8→V4.0 过渡门禁（99 §11）逐条达成 | 获得进入 V4.0 的准入资格 |

# 2. 硬化边界

本版本**允许**：

```text
修复/加固（不影响对外契约的改动）
质量债务清零（后端 lint/type/coverage/a11y）
四层回归执行与记录
Flaky 收敛（限 AUTOMATION/ENV 波动）
P1/P2 Defect 修复
迁移/回滚演练
指标采集与看板（为 V4.0 提供连续基线）
V3.8→V4.0 过渡门禁项
```

本版本**禁止 / 不做**（留给 V4.0）：

```text
Legacy → Canonical Cutover 或删除旧模型
TestCase/TestPlan 结构性迁移
SSO / RBAC / Audit / Retention / Encryption / HA / Backup / Secret Rotation
Model / Cost Governance、Release Gate 整套 Enterprise 平台
改变 Frozen Contract / Required Oracle 语义
对 P0 Scenario 做批量删除/跳过
```

# 3. 质量债务基线（现状 → 目标）

依据 `AGENTS.md` §4.3 与 `99` §13，现状差距：

```text
全量 Ruff、mypy、覆盖率阈值、a11y 仍存在历史债务（暂由扩展工作流报告）
运行时 F821、全量测试、类型检查、构建已经必须阻断（本地需与 CI 同步）
```

V3.9 目标：把「扩展工作流报告」的债务降到 **0**，或生成**正式豁免清单**并冻结。

## 3.1 Backend

- 全量 `ruff`（含 F821/F401/F841 及全量规则集）清零
- `mypy` 全量（`app/` 全包）清零，或按模块分级配置并记录豁免
- 覆盖率基线：声明每模块最低覆盖率，缺口进入豁免清单；核心模块（mission/scenario/execution/data/healing）优先
- Alembic 单头，迁移可回滚；`lanhu-mcp` 子模块指针健康

## 3.2 Frontend

- `tsc` 全量、`vite build` 全量
- `eslint` 全量 + a11y（axe/act 断言）修复
- @AGENTS.md §3.4：useEffect cleanup、无循环依赖、无 N+1、TabsContent forceMount、Network 仅 1 次有效请求

## 3.3 硬门禁

- `dev-gate.ps1`（G0–G2）全绿 → HARD 0
- 受影响模块 Pytest / Vitest 全绿
- 无调试遗留、无硬编码密钥

# 4. 四层回归与稳定（99 §13）

每次变更至少跑四层：

```text
A. 当前版本新增能力（V3.9 硬化项）
B. AITDE Invariants Regression（V3.0 起累加，不能只跑当前版本）
C. Legacy Regression（TestCase/TestPlan/API/UI 覆盖）
D. 跨版本（V3.0→V3.8 关键链路）
```

## 4.1 Flaky 收敛

```text
只把 AUTOMATION / ENV 波动纳入 Flaky
BUSINESS_FAIL 默认排除，不自动吞掉
收敛目标：P0/P1 场景在 test 环境 3 连跑无随机失败
Clusters 可回链样本 Run，样本可追溯
```

## 4.2 Run 数据累积

```text
全量回归产生的 Run 数据作为 V4.0 Cutover 指标的真实输入
指标采集为连续时间序列，而非一次性快照
```

# 5. Migration / 数据完整性

- 全库 Alembic 单头无分叉：`heads` 唯一
- 迁移可回滚（`down_revision` 完备）
- 数据完整性校验：mission(source/scope/contract/scenario 链)、execution(evidence/outcome)、fixture(lease/cleanup) 关键引用无孤儿
- `lanhu-mcp` / `knowledge-mcp` 子模块指针随主干同步

# 6. V3.8→V4.0 过渡门禁（99 §11 逐条）

```text
[ ] Failure Triage Benchmark 达团队阈值（≥100 人工分类 Run 基线）

[ ] Healing 只产生新 ActionPlanVersion，历史 Replay 不重写
[ ] BUSINESS_FAIL 不被 Flaky 自动吞掉

[ ] Prompt / Model 更新有 Golden Evaluation 且阈值阻断

[ ] Cutover 所需质量指标已有连续历史数据
```

> 硬化版以“修 / 加固”为主，减少新增契约。仅当修复缺陷需要时，才新增或调整 `/api/v2`，并同步 OpenAPI schema。
