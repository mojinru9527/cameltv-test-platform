# 现有功能 ABCD 分级去留白名单（用户定稿）

> 结论层事实源。代码入口收敛在 batch-212（B2）落地；死代码删除在 batch-215（B5）落地；
> 重复模型收敛在 batch-224（B14）落地。判定方法见文末「去留判定器」。

## 1. 分级定义

| 级 | 定义 | 处置 |
|----|------|------|
| 🟢 A | 主线保留，升级进「版本验收工作台」做强 | 主链路/向导/内嵌 |
| 🟡 B | 高复杂度、普通测试员用不上 | 收「专家/系统」层，默认隐藏不删 |
| 🔴 C | 砍入口 / 下架宣称 / 冻结 / 删除 | 入口移除或代码删除（见 §3） |
| 🔁 D | 功能重复（旧体系 vs AITDE 各一套） | 收敛为单一事实源 |

| 功能 | 去向 | 说明 |

| 集成/通知/系统管理 | B：管理员 | 系统治理 |

## 4. D 级重复收敛清单

| 重复概念 | 现状（几套并存） | 收敛为 |
|---------|----------------|--------|
| 「组织执行」容器 | TestCase/TestPlan + Mission/Scenario + Campaign + ReleaseBundle | 只留「版本验收任务」一个主线容器；TestPlan 只读/历史 |
| 数据 | Dataset + DataSources + Fixtures + DataRequirement | 一层「数据资产」 |
| 环境 | 目标环境 + 环境快照/指纹 + Runner 绑定 | 被测系统管理（人工） + 快照指纹（自动采集） |
| 缺陷 | 缺陷管理 + AI 失败分类 + 自动转缺陷 | 一个缺陷事实源，AI 只填草稿 |
| 任务入口 | DSH 任务 + 智能测试任务 + Agent 工作台 | 用户只走「版本验收」，AI 引擎收后台 |
| 报告 | 报告中心 + 验收报告 + 证据包 | 放行报告为主，其余自动汇聚 |

收敛规则：**每个业务概念只保留一个事实源，另一套降级为「视图/历史」，绝不双写**。

## 5. 去留判定器（以后每个功能过 4 问）

1. 使用者是谁？普通测试员 / 专家 / 系统自己？→ 普通测试员用不到的不进默认导航；
2. 服务主链路的哪一环？（建任务→审方案→执行→看证据→放行→沉淀）答不上 = 冻结；
3. 有真实业务在用吗？外部依赖解锁了吗？长期阻塞 = 下架宣称、冻结代码，不做半成品入口；
4. 和别的模块重复吗？重复 = 只留一个事实源，另一个变视图。
