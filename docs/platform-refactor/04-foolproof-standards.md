# 傻瓜化设计规范（可用性门禁）

> 目标：**让一个"傻子测试工程师"（零培训、不看文档）也能用懂平台**。
> 傻瓜化 ≠ 功能做简单/做弱，而是：平台承担 90% 脑力活，用户只做看得懂、点得动、错了能回头的简单决策。
> 本规范与代码门禁同级：**每个功能批次必须过小白走查**，否则 Leader 不予 APPROVED。

## 1. 傻瓜化设计十诫

1. **一屏一事**：每页只服务一个任务；两个以上并列主按钮 = 不合格；
2. **空态即教学**：列表为空时显示「三步完成你的第一个 XX」，而不是空表格；
3. **默认值正确**：能猜的绝不问（默认项目/环境/执行集/报告模板预填），用户只改例外；
4. **向导化**：复杂操作用 3 步向导（放东西 → AI 出结果 → 确认），每步顶部一句话 + 示例；
5. **说人话**：UI 词表用 `03-terminology-map.md`，引擎术语禁止出现在普通用户文案；
6. **动作可预期**：按钮说明「点了会发生什么」；危险动作二次确认 + 预览影响；
7. **做完有交代**：操作结束马上给「成功/失败/下一步」；失败给原因 + 怎么修；
8. **错了能回头**：草稿/撤销/重来；AI 生成物永远可「重新生成/修改/丢弃」；
9. **前后一致**：动作/状态/颜色/按钮位置全局统一（并入 ui-conventions 基线）；
10. **小白可走查**：新功能上线前找「从没用过平台的人」独立完成主任务并记录卡点。

## 2. 功能在场景里出现（just-in-time）

- 用户不需要预知功能目录；功能 = 任务上下文里按需出现的「下一步按钮」；
- 例如：用户不知道「定时任务」存在，直到版本任务里出现「要不要每周自动跑？[一键开启]」；
- 导航只保留 ≤5 个一级入口（见 01 文档 §3.1）。

## 3. AI 兜底：内嵌「问我」助手

- 每个页面有问号入口，用户用业务语言提问：「这页是干嘛的？我要测会员中心这版怎么走？」；
- AI 用业务语言解释，并能「代做」：一句话发起版本任务，只在需要人决策处停下问「选 A 还是 B」；
- 实现复用语料与 DSH/Agent 执行能力，不新增独立模块（batch-214 落地 MVP）。

## 4. PRD 必含「小白走查」节（门禁）

每个功能/重构批次的 PRD 或 PRD-lite 必须含：

```markdown
## 小白走查
- 新用户画像: {谁是新用户}
- 主任务: {一句话}
- 走查方式: {单人独立完成 / 录屏 / 记录卡点}
- 卡点清单: {看不懂的词 / 找不到的入口 / 多余的步骤}
- 结论: PASS（无 P0/P1 卡点）或 待修复清单
```

验收证据与代码测试同级；禁止「AI 自证」式验收。

## 5. 效果指标（无埋点，owner 人工记录）

| 指标 | 定义 | 记录方式 |
|------|------|---------|
| 3 分钟主任务 | 首次使用者 3 分钟内完成页面主任务 | 每次走查人工记录 |
| 卡点数 | 每批走查记录看不懂/找不到/多余步骤条数 | 走查记录 |
| 回归人天 | 一个版本回归花费人天（前后对比） | owner 人工记录 |
| 提测→放行周期 | 一个版本从提测到放行的日历时间 | owner 人工记录 |
| 周活跃 | 每周实际使用主链路的测试人数 | owner 人工记录 |

> 平台当前仅 owner 一人使用：不做点击埋点；用「真实版本走查 + owner 体感」驱动决策。
> 交给真实黑盒测试员时，指标自动生效。
