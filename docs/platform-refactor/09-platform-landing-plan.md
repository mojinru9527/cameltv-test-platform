# 落地方案：控制面 + 本地执行节点（2026-09）

> 基线：`main@96cd5b65`（Batch 255）。输入是用户 2026-09-18 的四项决定。
> 本文是**执行事实源**：批次划分、完成定义（DoD）、安全硬线、运维要求都以本文为准；
> 与 `01-platform-positioning-and-mainline.md` 冲突时，以本文的落地口径为准（定位不变，路径更具体）。

## 0. 四项已确认决定（决策记录）

| # | 决定 | 影响 |
|---|------|------|
| D1 | 采用**方案 B：云端控制面 + 本地执行节点** | 执行与推理离开 4C4G 单机；平台回归"登记·调度·证据·知识" |
| D2 | 需要 iOS/Android **原生真机**能力，但**本轮暂不排期**（先跑通 Web + 接口） | 真机设计保留在附录，不阻塞当前 8 周计划 |
| D3 | 本地 AI 全链路**按需运行，不做常驻服务**（测试人员在场） | 节点用一条命令启动、用完即退；但必须做到"任务不丢 + 状态可见" |
| D4 | 允许按风险分层走流水线（详见 §6） | 默认轻量批次；执行/AI/数据模型变更强制完整批次 |

## 1. 目标形态

```text
            云端控制面（腾讯云单机，瘦身后 ≤2GB）                      本地节点（测试人员机器，按需启动）
 测试工程师 ─▶ Web(React) · FastAPI(只读+登记+调度) · PostgreSQL  ◀──▶  cameltv-node
              · 证据元数据/对象 · 知识检索                                   ├─ ai     : 认领 AiJob → 本地/客户端模型 → 回传
              （不跑浏览器 / 不跑模型 / 不存被测系统凭据）                     ├─ runner : 认领 ExecutionJob → httpx(接口)/Playwright(Web)
                                                                            └─ upload : 证据分片上传 + 断点续传 + 校验
```

**一句话**：平台只做"登记、调度、证据、知识"，模型推理与测试执行全部发生在测试人员本机，按需启动。

## 2. 视角一：业务 / 产品

### 2.1 菜单收敛：4 个入口 + 1 个专家区

原则：**任何能力必须挂在 4 个入口之一；挂不上的一律下沉专家区或隐藏。**

| 保留（tester 默认可见） | 回答的问题 | 吸收的现有模块 |
|------------------------|-----------|--------------|
| ① 我的待办（首页） | 今天要审什么、什么在跑、什么失败 | 工作台、通知、待审队列 |
| ② 版本验收 | 这个版本怎么测、能不能放行 | 版本任务、需求源、AI 方案、执行记录、放行结论（用例/计划降为资产，被它调用） |
| ③ 结果与缺陷 | 跑完的结果、证据、缺陷 | 报告中心、执行记录、缺陷管理、失败分类 |
| ④ 知识库 | 上版怎么测的、这版改了哪、能复用啥 | 知识中心（只读视图 + 复用建议，≤3 Tab） |
| 专家区（二级 + 权限门禁） | — | 资产（用例/接口/UI/数据/环境）、执行节点管理、AI/模型配置、集成、系统管理 |

**隐藏/下线（不再进一级导航）**：蓝湖证据包、DSH 任务、数据集、播放器、AI 建议、Flaky、Healing、
Campaigns、Oracle、Mission/Contract 等引擎概念页、定时任务、模板、发布包独立页。

**DoD**：tester 登录后一级导航 ≤4 项 + 1 个专家入口；E2E 断言导航项数量，防止回涨；
每个可见页面必须能回答"服务版本放行的哪一环"。

### 2.2 唯一主链路（体育试点）

```text
版本任务 ─┬─ 需求源（PRD / 蓝湖 / 接口文档 / 变更范围）
          ├─ 验收方案（AI 生成 功能 + 接口 + Web UI 用例，含置信度与待确认问题）→ 人工逐条审 → 冻结
          ├─ 执行（本地节点：接口 httpx / Web Playwright）→ 证据（截图·请求·回放·日志）
          ├─ 缺陷（业务失败一键转草稿）
          └─ 放行结论（覆盖 / 通过率 / 风险 → 证据包）
                    │
                    └─▶ 版本知识记录 → 下个版本任务自动带出（复用建议）
```

### 2.3 试点范围与完成定义

- 业务域：**1 个**（赛事/比赛方向，复用现有 `scripts/sports/*` 与 16.0.0 资产）；
- 用例量：接口 **50 条** + Web UI **30 条**（P0 冒烟）；真机用例本轮不纳入；
- 环境：Test5（内网 + VPN），凭据仅存在于本地节点。

| DoD | 目标 |
|-----|------|
| 单版本"需求 → 方案" | ≤ 2 小时（本地 AI 生成 + 人工审） |
| 单版本执行（80 条） | ≤ 3 小时（本地 2 并发） |
| 证据包完整率 | 100%（每条失败用例都有截图或请求回放） |
| 复用建议命中率 | ≥ 50%（人工判断"确实可复用"） |
| 连续达成 | **≥ 3 个版本**才算跑通 |

### 2.4 知识库只做一条主线

唯一要回答的问题：**这个版本改了哪些需求/功能模块 → 要跑哪些用例 → 上次跑得怎么样？**

```text
RequirementVersion ──(变更)──▶ Module ──(覆盖)──▶ Case(功能/接口/UI) ──(执行)──▶ Run → Evidence/Defect
        ▲                                                                              │
        └──────────────────── 版本知识记录：怎么测的 + 下版复用建议 ◀────────────────────┘
```

**DoD**：输入"16.1.0 改了 X 模块"→ 一次查出受影响模块 → 关联用例 → 最近一次执行结果 → 未覆盖缺口；
响应 ≤2s，且每个结论都能点回原始用例/执行记录。其余知识玩法本阶段冻结。

## 3. 视角二：架构

### 3.1 职责边界（硬约束）

| 层 | 组件 | 允许 | **禁止** |
|----|------|------|---------|
| 控制面（云端） | FastAPI、PostgreSQL、证据对象存储、知识检索 | 登记、调度、聚合、检索、展示、签发节点令牌 | ❌ 跑浏览器 ❌ 跑模型 ❌ 跑 ffmpeg ❌ 存被测系统凭据 |
| 执行面（本地，按需） | `cameltv-node`（ai / runner / upload） | 认领任务、本地推理、执行、采集证据、上传 | ❌ 持有平台 SECRET_KEY/DB 口令 |

### 3.2 协议与数据模型（新增）

| 对象 | 说明 | 关键字段 |
|------|------|---------|
| `NodeRegistration` | 本地节点注册（扩展现有 agent token 模型） | node_id, project_id, capabilities[ai,api,web], token_hash, last_seen |
| `ExecutionJob` | 执行任务（**与 `AiJob` 并列，不合并**） | kind(api/web), case_refs[], env_ref, status, attempt, evidence_bundle_id |
| `JobLease` | 认领租约（沿用 AiJob 的 claim/heartbeat/stale 语义） | owner_node, claimed_at, expires_at, heartbeat_at |
| `EvidenceBundle` | 证据包（可校验） | bundle_id, manifest(每文件 sha256), size, storage_uri, completeness, produced_by_node |
| `ModelRun` | 本地 AI 运行记录（审计） | job_id, model_name, model_version, prompt_version, duration_ms, imported_by |
| `ImpactEdge` | 知识主线边 | source_ref, target_ref, kind(changed/covers/depends), version, confidence |

兼容策略：老的 `ui_test_service` / `api_task_worker` 队列**冻结不扩展**，试点通过后再删；
避免 Batch 240–255 已经清理过的"双执行栈"再次长回来。

### 3.3 本地节点：按需即可，但三个细节必须做到

1. **任务不丢**：节点离线时任务留 pending，租约超时自动回收，节点回来继续认领；
2. **状态可见**：平台显示"节点在线/离线 + 队列长度 + 预计等待"，避免"点了没反应"；
3. **一键化**：`cameltv-node up` 一条命令完成注册 + 心跳 + 认领循环（不是现在文档里的 5 步手工）。

### 3.4 演进切片

| 切片 | 内容 | 明确不做 |
|------|------|---------|
| S1 | `ExecutionJob` 协议 + `cameltv-node` 认领循环（API + Web） | 不碰真机、不动老队列 |
| S2 | 执行沙箱化 + 出网白名单 | 不改业务逻辑 |
| S3 | 知识主线（ImpactEdge + 查询 + 复用建议） | 不新增知识玩法 |
| S4 | 菜单收敛到 4 入口 + 体育连续 3 版本验收 | 不延伸其他业务 |

## 4. 视角三：攻击者（安全）

### 4.1 五条硬线

| # | 硬线 | 要求 | DoD |
|---|------|------|-----|
| H1 | 执行隔离 | 本地节点内执行于无凭据沙箱：非 root、无平台 SECRET/DB 口令、无内网 egress（白名单=被测系统+平台 API）、危险 API 静态拦截（`child_process`/`fs` 写/`net`/`process.env`） | 恶意 spec（读 `.env`/连内网）必须失败 + 回归测试 |
| H2 | 出网守卫 | 所有用户可控 URL 走统一 `assert_public_url()`：私网/回环/链路本地拒绝、重定向后二次校验、响应 ≤5MB | 5 个恶意 URL 全拒 + 单测 |
| H3 | 凭据最小化 | 平台只保留自身密钥 + 节点令牌；被测系统凭据只存在本地节点；Token 只发白名单域名 | 平台库内搜不到被测系统账号明文 |
| H4 | 证据不可篡改 | `EvidenceBundle` 带 manifest(sha256) + 生产节点 + 时间；放行结论绑定 bundle 哈希 | 改一字节 → 校验失败并显红 |
| H5 | 节点令牌可吊销 | 令牌按项目隔离、可吊销、可轮换；节点是"一次性引用"而非长期凭据 | 吊销后节点立即无法认领 |

### 4.2 必须关闭的 6 条已知风险（来自审计基线）

| 风险 | 证据 | 落点 |
|------|------|------|
| SSRF 无守卫 | `app/services/requirement_source_service.py:80` | S1/B1 |
| Token 按域名关键字外发 | 同文件 `:71-75` | S1/B1 |
| `shell=True` + `{image}` 未加引号 | `app/services/lanhu_evidence/local_ocr_provider.py:62-74` | S1/B1 |
| 本地对象存储路径未收敛 | `app/integrations/object_storage/local.py:24-26` | S2/B2 |
| 密钥加密两套派生 | `app/core/cipher.py:21` vs `app/services/ai_config_service.py:61-62` | S2/B2 |
| "dry-run 当沙箱" | `app/services/case_compiler_service.py:290-345` | S2/B2（与 H1 同批） |

## 5. 视角四：运维

### 5.1 容量预算

| 位置 | 组件 | 预算 |
|------|------|------|
| 云端单机（4C4G） | Caddy/Nginx + FastAPI + PostgreSQL | ≤ 2.0 GB |
| 云端单机 | 证据存储卷 + 知识检索 | ≤ 0.8 GB |
| 云端单机 | 预留（OS + 峰值 + 迁移） | ≥ 1.2 GB |
| 本地节点 | runner/ai | 由使用者机器承担（建议 16 GB 起） |

关键变化：控制面不再跑浏览器/模型，3.7 GB 的机器从"OOM 边缘"回到"够用"。

### 5.2 备份与恢复（证据包是放行依据）

| 项 | 频次 | 保留 | 验证 |
|----|------|------|------|
| PostgreSQL dump | 每日 | 14 天 | **每周恢复演练**（临时库 + 抽查 3 条执行记录） |
| 证据卷 | 每日增量 | 30 天 | 每月抽 1 个 bundle 校验 manifest |
| 发布 manifest/制品 | 每次发布 | 与回滚窗口一致 | 回滚演练（ADR-0026 已要求） |

**DoD**：`docs/ops/restore-drill.md` 记录一次"从零恢复 → 证据可查 → 结论可点回"的完整演练证据。

### 5.3 最小可观测集

1. 执行维度：队列长度、等待时长、单任务时长、失败分类（业务/脚本/数据/环境/容量）；
2. 节点维度：在线节点数、心跳延迟、认领成功率、证据上传失败率；
3. 控制面：API p95、DB 连接池、**磁盘水位（当前 94%，必须告警）**；
4. 告警阈值：磁盘 >85%、队列 >50、节点离线 >10 分钟、失败率突增 2 倍 → 通知到人。

### 5.4 发布与回滚

- 控制面：不可变 manifest + 冒烟（ADR-0015 已有，保持）；
- 本地节点：版本自描述；落后 ≥2 个版本时平台提示升级，但保留一个窗口期的兼容；
- 回滚：控制面沿用现方案；节点回滚 = 换回上一个 CLI 版本，不影响平台。
