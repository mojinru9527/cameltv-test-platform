# 蓝湖需求导出格式规范

> 定义「蓝湖 → 本地需求提取」的标准导出格式，后续需求提取一律按此格式，保证**内容完整 + 层级结构 + 页面跳转可解析**。

## 1. 格式来源

蓝湖原型页可通过「蓝湖 → 导出 HTML（Axure 导出）」得到一份自包含目录。平台现有导出示例：
- `axure_extract_61930a83` — **运营后台原型**（74 页，含层级）
- `axure_extract_e6b5ce1e` — 蓝湖"用户端原型"项目导出（180 页；sitemap 树为运营后台侧，用户端页为平铺）

## 2. 目录结构（标准格式）

```
<导出目录>/
├── *.html                  # 每个页面一个 HTML（页面名.html，含页面内容与"功能点|说明"表）
├── images/<页面名>/        # 每个页面的设计稿截图（png/svg/webp…）
├── data/document.js        # Axure 数据文件 —— 含 sitemap 层级树（rootNodes）
├── .lanhu_cache.json       # 蓝湖元数据：document_name / version_id / 页面平铺列表
├── files/  resources/      # Axure 运行资源（跳转/脚本）
```

## 3. 层级结构解析（关键）

`data/document.js` 内含 Axure sitemap 树（minified）：
- `rootNodes` = 顶级模块数组；节点结构 `{id, pageName, type(Wireframe|Folder), url(html), children[]}`
- Folder = 模块（可嵌套），Wireframe = 页面
- 解析：将 minified `_(k,v,...)` 对象按 `s=id,u=pageName,w=type,x=Wireframe,y=url,I=Folder,J=children` 解码为 JSON 树

已验证解析器：Batch 124 已把 61930a83（运营后台 74 页）解析为 **17 个顶级模块 / 88 节点** 层级树。

## 4. 页面跳转（跳转正常）

- HTML 页面内保留页面间跳转链接（Axure 交互），可直接在浏览器打开跳转。
- 平台入库时可从 HTML 提取页面间 `navigates_to` 关系（后续切片）。

## 5. 导出规范（后续执行）

1. **用户端原型与运营后台原型分开导出**，分别放入两个独立目录：
   - `lanhu-exports/用户端原型/`
   - `lanhu-exports/运营后台原型/`
2. 每份导出必须包含：全部 `*.html`、`images/<页面名>/`、`data/document.js`（层级）、`.lanhu_cache.json`。
3. 用户端原型导出时若 sitemap 无层级（平铺），按 `docs/体育平台-功能模块地图.md` 的用户端模块归级，生成 `hierarchy.json`。
4. 运营后台原型导出后直接解析 `document.js` sitemap 生成 `hierarchy.json`。

## 6. 产物

- 需求模块树：`hierarchy.json`（节点=平台/模块/页，含 lanhu_page_id + 设计稿截图清单）
- 导入平台：`POST /requirement-modules/import-tree`（幂等，按层级建 parent）
- 内容入库：`POST /knowledge/design-assets/import`（文本+图片）
- 用例基座：需求文本 → `ai_service` 基础用例生成 → 叠加深度用例
