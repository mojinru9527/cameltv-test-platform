# Batch 57 生产验收输入补充操作单

## 1. 当前不需要补充的内容

- 测试平台自身的 production 服务器、域名、TLS 和 PostgreSQL 尚未采购，
  统一记为 `DEFERRED / UNPROVISIONED`，本轮不需要填写生产测试平台 URL。
- 双 VPN 切换手册保持 `paused`，未重新启用前不执行 vpn07/OpenVPN 切换。
- P0 浏览器验收只看 PC `1440×900`；tablet/mobile 降为 P2，不阻塞交付判定。
- 本地测试平台固定使用 `http://localhost:5173/`、后端
  `http://127.0.0.1:8000` 和独立 local 数据库。

## 2. 安全填写规则

可以在聊天中提供：

- 环境或服务的逻辑名称；
- URL 是否可访问、所属网络和允许的操作范围；
- OpenAPI 服务名称、接口公开/受保护分类；
- 数据库版本、快照时间、行数基线和文件 SHA-256；
- 允许执行的验收窗口和清理要求。

不要在聊天、Git、截图或验收报告中提供：

- 密码、短信验证码、Token、Cookie、Authorization；
- AI API Key、数据库完整连接串、SMTP 密码、Webhook Secret；
- OpenVPN 配置正文、私钥、隧道 IP；
- 原始生产业务数据或未脱敏数据库。

秘密值只在本机未跟踪的 `.env`、测试平台加密变量或批准的凭据管理工具中
填写。每组输入只需先回复“组号 + 非敏感信息已准备好”，再按该组步骤处理。

## 3. P0 输入组

### I01：体育测试节点、六服务 OpenAPI 与鉴权边界

对应：`B56-B01`、`B56-B02`、`B56-B03`。

请准备：

| 字段 | 要求 |
| --- | --- |
| 测试节点清单 | 6 个节点的逻辑名称和当前可用状态 |
| 页面入口 | 各节点当前 URL；若属于内网敏感地址，只在本机环境变量中填写 |
| OpenAPI | 6 个服务各自的实时 OpenAPI/Knife4j URL，或 6 份脱敏 JSON/YAML 快照 |
| 快照证据 | 来源、采集时间、服务版本、SHA-256 |
| 鉴权清单 | 哪些接口公开，哪些接口必须登录或带最小权限 Token |
| 测试身份 | 一个最小权限测试账号或 Token 槽位；秘密值不发到聊天 |
| 写入边界 | 只读、允许创建/修改、禁止删除的明确范围，以及测试数据清理方式 |
| 网络条件 | 是否仅 OpenVPN 可达；双 VPN 流程暂停期间只登记，不执行 |

完成标准：节点 6 恢复；6 份契约均可解析；公开/受保护声明与真实响应一致；
无效凭据被拒绝，合法最小权限凭据通过。

### I02：运营后台测试登录

对应：`B56-B04`。

请准备：

| 字段 | 要求 |
| --- | --- |
| 登录页 | 当前测试环境登录 URL |
| 测试身份 | 固定测试账号，或可重复使用的账号生成规则 |
| 验证方式 | 图形验证码是否绕过；短信验证码的固定测试机制或 OTP 获取方式 |
| 成功页面 | 登录成功后的预期受保护路由 |
| 会话形式 | Cookie 或 storage；预期有效期和注销行为 |
| 操作边界 | 默认只读；允许写入时列明可恢复范围 |

秘密值只放本机。完成标准：浏览器登录后跳转到受保护页面，刷新仍有效，
注销后会话失效，并保存不含 Cookie/Token 的网络证据。

### I03：用户端与运营后台设计源

对应：`B56-B09`、`G56-011`。

二选一提供：

1. 用户端和运营后台各一个当前只读蓝湖/设计源链接，并在本机配置可用登录态；
2. 两份脱敏证据包，包含页面树、截图或 OCR 结果、来源、采集时间、版本号、
   SHA-256 和脱敏记录。

需要同时说明目标页面/版本范围。完成标准：需求引用可追溯到真实页面和版本，
页面树、截图/OCR、需求/Wiki/Trace 结果可复核。

### I04：真实 AI/OCR 服务

对应：`B56-B05`、`G56-011`。

请准备：

| 字段 | 要求 |
| --- | --- |
| Provider | 服务名称和获授权用途 |
| Endpoint | API Base URL；敏感内网地址可只在本机填写 |
| Model | 文本、视觉/OCR 各自模型名称和版本 |
| Key | 只填入本机 `AI_API_KEY` 或平台加密变量 |
| 数据边界 | 是否允许发送脱敏截图、附件、需求文本 |
| 限额 | 速率、额度、超时和重试要求 |

完成标准：最小脱敏输入产生可追溯真实输出；主断言不使用规则 fallback 或
mock；无 Key、无权限、超时场景诚实失败。

### I05：旧 PostgreSQL 脱敏快照

对应：`B56-B08`。

请准备：

| 字段 | 要求 |
| --- | --- |
| 数据库版本 | PostgreSQL 主版本和扩展清单 |
| 快照 | 已脱敏、可在隔离环境恢复的 dump/backup |
| 完整性 | 文件大小、SHA-256、导出时间 |
| 基线 | 关键表名和各表行数；不含真实正文 |
| Schema 版本 | 当前 Alembic revision/head 或历史说明 |
| 恢复说明 | 所需角色、扩展、编码和恢复命令的非秘密部分 |

不要提供生产连接串。完成标准：隔离恢复、升级、数据保留、重复升级、唯一
Alembic head 和 ORM 零漂移均通过。

### I06：生命周期通知验收端点

对应：`C55-4`、`G56-012` 的定时任务/通知部分。

请准备一种获授权的测试通道：

- 本地可观察 Webhook 接收器；或
- 测试群机器人 Webhook；或
- SMTP 测试邮箱和收件箱。

请说明通道类型、允许发送的测试关键字、接收窗口和清理方式。URL、密码和
Secret 只在本机配置。完成标准：调度只触发一次，成功/失败状态、审计和通知
可追溯；端点失败可重试且不重复执行核心业务。

## 4. P1 输入组

| 组号 | 对应项 | 需要准备 |
| --- | --- | --- |
| I07 | `B56-B06` 真机性能 | 获授权设备、ADB/SoloX 代理、设备型号/系统版本、采样窗口、负载与停止阈值 |
| I08 | `B56-B07` ELK | Kibana/ELK 入口、只读身份、索引范围、可查询时间窗和一个脱敏 traceId |
| I09 | `B56-B10` 体育生产只读 | 生产节点清单、批准时间窗、仅 GET/HEAD 边界；双 VPN 手册重新启用后再执行 |

P1 输入不会替代 P0，但最终全平台 `READY` 前仍需补齐。

## 5. 建议补充顺序

1. `I02` 运营后台测试登录；
2. `I01` 六服务 OpenAPI、节点和鉴权边界；
3. `I03` 两端设计源；
4. `I04` 真实 AI/OCR；
5. `I05` 旧 PostgreSQL 快照；
6. `I06` 通知端点；
7. `I07`～`I09` P1 输入。

每完成一组，都重新固定代码 SHA、执行时间和输入版本，并只保存脱敏证据。
输入变化后，旧验收结果不自动沿用。
