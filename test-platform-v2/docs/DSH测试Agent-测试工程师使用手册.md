# DSH 测试 Agent — 测试工程师使用手册

> 版本：v1.0 | 日期：2026-08-17 | 适用：测试自动化平台
> 关联：`DSH测试Agent框架设计.md`（架构）· `知识中心-用户使用手册.md`（知识中心）· `docs/agent-team/dsh-agent-teams.md`（DSH 船长模式）

---

## 1. 这是什么

DSH 测试 Agent 把测试平台接入 DeepSeek Harness，让测试工程师可以：

1. **导入需求** → DSH 测试船长团队自动熟悉项目（知识中心骨架：模块拓扑/需求/用例/接口/设计稿）
2. **自动设计用例** → 按平台用例标准（test-case-design skill）产出并**直接入库**
3. **自动执行测试** → 经平台 Runner 跑接口/UI 自动化（agent 不直连测试环境）
4. **审查与报告** → reviewer 独立审查覆盖/格式/断链，船长产出最终报告
5. **知识回流** → 执行结果/新用例自动沉淀回知识中心，越测越准

**核心价值**：测试工程师不用从零熟悉项目——导入需求，DSH 团队帮你完成
「理解 → 设计 → 执行 → 报告」全流程，你只需要审查结论、处理异常。

## 2. 快速上手（3 分钟）

### 2.1 前置条件

- 平台已启用 DSH（后端 `DSH_ENABLED=true`，部署见平台运维）
- knowledge-mcp 服务已启动（部署见 `knowledge-mcp/README.md`）
- 你有 `agent:run` 权限（测试工程师默认角色）

### 2.2 提交一个测试任务

**方式 A：平台页面（推荐）**

1. 登录平台 → 左侧导航「DSH 任务」
2. 点击「新建任务」→ 任务模式选「**团队模式（team）**」
3. 团队视角选「**测试视角**」（analyst/case-designer/api-tester/ui-tester/reviewer）
4. 批次模式：完整（full，五成员）或轻量（light，两成员）
5. 任务描述写清目标，例如：

```
项目：被测业务平台
目标：为「登录注册」模块设计并执行接口测试
输入：需求已导入知识中心（关键词「登录」）
要求：用例按平台标准直接入库；执行走平台 Runner；输出项目理解摘要+测试报告
```

6. 提交 → 页面实时展示团队进度（任务依赖：分析→用例设计→接口/UI 执行→审查→报告）

**方式 B：知识中心工作流（熟悉项目优先）**

若只想让 DSH 帮你**熟悉项目**（不做用例/不执行）：

```
目标：熟悉「搜索」模块并输出测试影响面分析
输入：知识中心已有该模块需求/接口/用例
要求：产出项目理解摘要 + 影响面 + 用例建议清单（不执行）
```

## 3. 团队角色说明

| 角色 | 职责 | 产出 |
|------|------|------|
| 船长（tester-lead） | 导入需求、拆任务、唤醒成员、汇总报告 | 最终报告（理解摘要/影响面/用例统计/审查结论/流程反思） |
| analyst 需求分析 | 经 knowledge-mcp 拉模块拓扑/需求/接口/设计稿 | 项目理解摘要 + 测试影响面 |
| case-designer 用例设计 | 按 test-case-design skill 规则设计用例 | 用例（直接入库，含三关联：模块/需求/接口） |
| api-tester 接口测试 | 选计划/触发平台 API Runner、回读结果 | 接口执行结果与判定 |
| ui-tester UI 自动化 | 选任务/触发平台 UI Runner、回读结果 | UI 执行结果与判定 |
| reviewer 质量审查 | 对照需求核覆盖、对照 skill 核格式、转换断链检查 | 审查报告（发现问题列修正建议） |

## 4. 用例入库规则

- 生成规则**单一事实源** = `tests/test-case-standards/` 标准（test-case-design skill）
- 用例直接写入用例库（不走 AI 审核台），reviewer 审查留痕兜底
- 每条用例带三关联元数据：**模块归属 / 需求追溯（source_req_id）/ 接口契约**——这是 agent 按图索骥的前提
- 功能用例命名 `TC-{模块}-{编号}`；接口用例含 `api_method/api_endpoint/api_assertions`

## 5. 执行链路说明

```
DSH agent ──knowledge-mcp──> 平台开放 API
   ├─ 查计划/任务列表（get_test_plans / get_ui_test_jobs）
   ├─ 触发执行（trigger_test_plan / trigger_ui_test）
   └─ 回读结果（get_execution_result / get_plan_executions / get_ui_test_run）
```

- 执行统一走**平台 Runner**（Agent 不自跑测试环境，避免结果散落）
- 执行结果自动入库知识中心（执行结果事件源）→ 保鲜机制标记过时需求

## 6. 模型选择（可选）

- 平台管理员配置模型池（`DSH_MODEL_POOL`，逗号分隔，如 `deepseek-v4-flash,deepseek-v4-pro`）
- 测试工程师在「新建任务」对话框选择模型；不选则用平台默认模型
- 模型池未配置时不限（仅校验非空）
- 交叉审查视角：reviewer 可用不同模型跑（高级用法，需平台支持成员级模型）

### 6.1 AI 配置：自动发现模型（Batch fix）

- 平台管理员在「AI 配置」新建/编辑提供方时，点击 **「获取模型列表」** 按钮：
  平台调用提供方的 `GET /models`（DeepSeek 官方 / 智谱 / Moonshot 等 OpenAI 兼容端点均支持），
  自动把该提供方全部模型填入「模型清单」，无需手敲。
- 未实现 `/models` 的提供方会提示可读错误，仍可手动填写；API Key 无效会提示 401。

### 6.2 图片附件（Batch fix，对齐 DSH web 贴图）

- 新建 DSH 任务的输入框支持 **粘贴（Ctrl+V）/ 拖拽 / 选择** 图片（PNG/JPEG/WebP/GIF，≤10MB），
  提交时自动上传并随任务执行。
- 图片会放进任务隔离工作区（`attachments/`），任务文本尾部自动提示模型用
  `read_image` 工具查看——需要提供方有**视觉模型**（如 DeepSeek 官方
  `deepseek-v4-flash-vision-exp`）才能识别图片内容。
- 适合：把报错截图、页面设计稿、用例快照直接丢给 Agent 分析。

## 7. 常见问题

| 问题 | 处理 |
|------|------|
| 任务一直「等待中」 | 看 DSH 健康状态（页面右上角）；DSH 未启用或凭据缺失 |
| 团队进度停在某成员 | 平台会自动轮询快照；超时后任务标记 failed 且保留进度快照 |
| 用例没进知识中心 | 确认知识中心入库开关（`knowledge_ingest_enabled`）已开启 |
| 想只看不执行 | 任务描述里明确「不执行、只输出分析与建议」 |
| 结果怎么追溯 | DSH 任务详情含执行输出；执行记录在「测试计划→执行记录」可查 |

## 8. 知识回流闭环（越测越准）

```
需求导入 → DSH 理解项目 → 用例设计入库 → Runner 执行 → 结果自动沉淀知识中心
     ↑                                                        ↓
     └────────── 下一次任务检索到最新知识（含过时标记）──────────┘
```

- 需求调整时：DSH 用「知识差异对比」找受影响用例（reviewer 触发点②）
- 流程卡壳时：船长报告含「流程反思卡」，平台据此迭代流程（元审查层 L4）

### 8.1 缺陷自动回写（C-A4）

- reviewer/ui-tester 判定测试失败后，DSH 经 knowledge-mcp `submit_defect` 直接写入平台缺陷库（状态 open，severity P0-P3）
- 缺陷自动沉淀知识中心（缺陷知识源）——**下次测试检索即可命中历史缺陷**，形成「发现→登记→复用」闭环
- 缺陷编号平台自动生成（如 `DEF-20260817-001`），建议附 `external_url` 指向执行证据
- 前提：知识中心入库开关 `knowledge_ingest_enabled=true`（生产部署已开启）
