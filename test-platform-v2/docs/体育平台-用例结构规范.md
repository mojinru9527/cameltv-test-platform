# 体育平台-用例结构规范

> Batch 122 落地。定义体育平台用例的 域 / 模块 / 标签 / 编号 / 字段 / 深度标准，支撑「按端与后台定位、可执行、可追溯」的生产级用例库。

## 1. 域（domain）

| 域 | 内容 |
|----|------|
| `体育-用户端-功能` | 用户端全部功能用例（按入口拆分：安卓iOS / PC-web / 移动端-web） |
| `体育-运营后台-功能` | 运营后台 + konfi 功能用例 |
| `体育-接口测试` | 接口用例（按模块归类） |

## 2. 模块路径（module）= `入口/一级模块/二级模块`

| 入口代码 | 含义 | 备注 |
|----------|------|------|
| `安卓iOS` | 安卓 / iOS 原生客户端 | 与移动端-web 功能基本一致，差异单独标注 |
| `PC-web` | PC 网页端 | 完全功能版显示 |
| `移动端-web` | 移动端 H5 | |
| `运营后台` | 运营后台管理端 | |
| `konfi` | 配置系统 | 配置项下发 |

一级模块（用户端）：启动登录、首页、搜索、资讯、赛事详情、预测Pick、预测记录、联赛、球队、球员、排行榜、直播、聊天弹幕、个人中心、钱包财务、商城、装扮、付费活动、银钻任务、UGC、回放、世界杯专题、FAQ帮助、通用。

一级模块（运营后台）：直播管理、消息管理、UGC管理、内容管理、联赛及球队管理、商城、体育直播、装扮管理、赛事预测、广告管理、银钻任务、财务管理、用户管理、风控管理。

一级模块（konfi）：首页配置、赛事配置、球队配置、球员配置、资讯配置、直播间配置、回放配置、世界杯配置、UGC配置、广告配置、屏蔽配置、站内链接、通用参数、模板域配置。

二级模块：按页面/Tab/子功能，如 `安卓iOS/赛事详情/预测Pick`、`运营后台/赛事预测/奖励发放记录`。

## 3. 标签（tags）

- `功能用例` / `接口用例`
- `P0` / `P1` / `P2`
- `闭环`：端到端用户流程（如 下注→结算→奖励→流水）
- `关联:{模块}`：跨模块关联流程
- `权限`：系统权限类用例

## 4. 用例编号（case_id）

`SP-{入口}-{模块缩写}-{3位序号}`

| 入口 | 代码 |
|------|------|
| 安卓iOS | `AND` |
| PC-web | `PC` |
| 移动端-web | `WEB` |
| 运营后台 | `ADM` |
| konfi | `KON` |
| 接口（跨端） | `I` |

示例：`SP-AND-PICK-001`、`SP-PC-PICK-002`、`SP-ADM-FORECAST-REWARD-001`、`SP-I-ODDS-001`。

## 5. 用例字段规范

| 字段 | 要求 |
|------|------|
| preconditions | 明确数据构造（状态/账号/余额/环境），禁止 `—` |
| steps | 结构化步骤数组，每步含 desc + 可执行操作 + 该步预期 |
| expected_result | 具体可断言结果（文案/数值/跳转/状态） |
| source_doc | 来源：原型页 / 生产页面 / 功能地图章节 |

## 6. 深度标准（case-quality checklist）

每个核心模块必须满足：
1. **主流程闭环** ≥1 条（含跨模块跳转，tags 标 `闭环`）
2. **状态流转**：覆盖该模块全部业务状态（如预测：未开放/预测中/待开奖/已开奖/已取消）
3. **异常分支** ≥1 条（空态、无数据源、余额不足、越权、状态过期等）
4. **入口差异**：PC-web 与移动端（安卓iOS/移动端-web）分别成集；行为一致时标注「同安卓iOS」
5. **关联模块**：核心流程必须有跨模块关联用例
6. **权限**：PC-web/移动端-web/安卓iOS 的系统权限用例

**禁止**：仅「查看XX」且无断言的单步用例（校验脚本拦截）。
