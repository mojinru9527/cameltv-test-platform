# 体育平台-用例结构规范

> Batch 130 修订。定义体育平台用例的产品界面 / 业务模块 / 子模块 / 终端标签 / 编号 / 深度标准，支撑「同一功能聚合、可执行、可追溯」的生产级用例库。

## 1. 产品界面与业务模块

| 产品界面（surface） | domain 持久化形式 | 内容 |
|----|------|------|
| `用户端` | `用户端/{业务模块}` | 首页、赛事详情、预测 Pick、直播、搜索等用户功能 |
| `运营后台` | `运营后台/{业务模块}` | 配置、审核、上下架、数据维护等后台功能 |
| `接口测试` | `接口测试/{业务模块}` | 接口用例，按真实业务模块归类 |

同一业务模块只能在一个产品界面下出现一次。`体育-用户端-功能`、`首页PC端` 等历史值由分类服务兼容归一，但新入库不得继续产生这类路径。

## 2. 模块路径（module）= `子模块/功能点`

终端渠道不进入模块路径。以下均为禁止的新路径：`PC-web/赛事详情/预测Pick`、`安卓iOS/首页`、`首页PC端`。正确表达为：

- domain：`用户端/赛事详情`
- module：`预测Pick/入口`
- tags：`["端:PC Web", "端:安卓/iOS", "端:移动 Web"]`

一级模块（用户端）：启动登录、首页、搜索、资讯、赛事详情、预测Pick、预测记录、联赛、球队、球员、排行榜、直播、聊天弹幕、个人中心、钱包财务、商城、装扮、付费活动、银钻任务、UGC、回放、世界杯专题、FAQ帮助、通用。

一级模块（运营后台）：直播管理、消息管理、UGC管理、内容管理、联赛及球队管理、商城、体育直播、装扮管理、赛事预测、广告管理、银钻任务、财务管理、用户管理、风控管理。

一级模块（konfi）：首页配置、赛事配置、球队配置、球员配置、资讯配置、直播间配置、回放配置、世界杯配置、UGC配置、广告配置、屏蔽配置、站内链接、通用参数、模板域配置。

子模块：按页面/Tab/子功能，如 `预测Pick/入口`、`奖励发放记录`。模块父节点筛选必须包含所有后代用例。

## 3. 标签（tags）

- `功能用例` / `接口用例`
- `P0` / `P1` / `P2`
- `闭环`：端到端用户流程（如 下注→结算→奖励→流水）
- `关联:{模块}`：跨模块关联流程
- `权限`：系统权限类用例
- `端:安卓/iOS` / `端:PC Web` / `端:移动 Web`：终端覆盖元数据，不生成分类节点
- `对抗性` + `恢复性` / `幂等` / `并发`：异常恢复、重复操作和并发一致性用例

## 4. 用例编号（case_id）

人工维护的深度用例继续使用 `SP-{入口}-{模块缩写}-{3位序号}`；Batch 125 基础资产入库使用内容稳定 ID `SP-B125-{16位摘要}`，确保各源文件中重复的 `TC-001` 不碰撞，重复执行导入仍命中同一用例。

| 入口 | 代码 |
|------|------|
| 安卓iOS | `AND` |
| PC-web | `PC` |
| 移动端-web | `WEB` |
| 运营后台 | `ADM` |
| konfi | `KON` |
| 接口（跨端） | `I` |

示例：`SP-AND-PICK-001`、`SP-PC-PICK-002`、`SP-ADM-FORECAST-REWARD-001`、`SP-I-ODDS-001`。

## 5. 用例字段规范

| 字段 | 要求 |
|------|------|
| preconditions | 明确数据构造（状态/账号/余额/环境），禁止 `—` |
| steps | 结构化步骤数组，每步含 desc + 可执行操作 + 该步预期 |
| expected_result | 具体可断言结果（文案/数值/跳转/状态） |
| source_doc | 来源：原型页 / 生产页面 / 功能地图章节 |

## 6. 深度标准（case-quality checklist）

每个核心模块必须满足：
1. **主流程闭环** ≥1 条（含跨模块跳转，tags 标 `闭环`）
2. **状态流转**：覆盖该模块全部业务状态（如预测：未开放/预测中/待开奖/已开奖/已取消）
3. **异常分支** ≥1 条（空态、无数据源、余额不足、越权、状态过期等）
4. **终端差异**：PC Web 与移动端（安卓/iOS、移动 Web）分别覆盖；行为一致时共用用例并添加多个终端标签
5. **关联模块**：核心流程必须有跨模块关联用例
6. **权限**：PC-web/移动端-web/安卓iOS 的系统权限用例
7. **恢复性**：依赖超时/HTTP 5xx 时有明确错误、不写脏数据，故障解除后单次重试可恢复
8. **幂等与并发**：双击及两个客户端并发提交最多生效一次，关联记录、余额、库存和审计保持原子一致

**禁止**：仅「查看XX」且无断言的单步用例（校验脚本拦截）。
