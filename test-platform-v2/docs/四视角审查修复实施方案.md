## 2. 批次 A：执行链路修复（P0，batch-147）

**问题**：TP-01（一键执行 325/325 失败根因不可见）、TP-04（无环境前置检查）、B-8（执行双轨互不可见）

### 2.1 技术方案

1. **执行记录失败可见性**：
   - `test_execution` 表增加 `error_message` / `http_status` / `failed_stage` 字段（迁移）
   - 计划执行 worker 写入失败摘要（连接失败/超时/断言失败/业务错误码）
   - 计划详情「执行历史」增加「失败原因」列 + 行内展开请求/响应摘要
2. **环境前置检查**：计划执行前校验计划绑定环境存在 + 关键变量（BASE_URL/TOKEN）非空，缺失时阻断并提示「前往环境管理配置」
3. **执行双轨关联**：计划执行（test_execution）与 API 任务（api_execution_task）建立 `execution_source` 关联字段；计划发起的执行自动生成 API 任务记录（可下钻请求/响应），失败原因统一从任务结果回填
4. **误触防护**（连带 TP-02 最小修复）：三个执行按钮合并为「执行」+ 范围选择（全部/选中/单条），默认范围=选中

### 2.2 验收标准

- Given 计划含 325 条接口用例 When 一键执行 Then 每条执行记录含失败原因摘要，失败可在执行历史直接下钻到 HTTP 状态与错误阶段
- Given 计划未绑定环境/缺 Token When 执行 Then 阻断并给出配置引导（不再盲跑 325 失败）
- 325 失败案例回归：修复后重跑，失败原因可分类（环境/参数/业务）而非「全量失败原因未知」

## 3. 批次 B：统计口径统一 + 下游动作（P1，batch-148）

**问题**：WB-01/TR-01（7879 vs 9424）、TR-02/RP-01（执行/通过/缺陷/报告全 0）、B-1（5 套统计）、B-3（覆盖率多口径）、REQ-01（覆盖率 0%）

### 3.1 技术方案

1. **统计服务收敛**（B-1）：新建 `stats_service.py` 统一四类查询（用例总数/执行统计/计划覆盖率/趋势），删除 dashboard_service/report_aggregator/trace_service/test_plan_service/report_service 中的重复实现，全部改为调用 stats_service
2. **单一口径定义**：
   - 用例总数 = 非软删除 + 全部类型（manual/functional 归功能、api、ui）→ 工作台/追溯/集成页统一
   - 计划覆盖率 = 已入计划用例 / 用例总数（按类型分列）
   - 通过率 = 通过执行 / 有结果执行（pending 不计入分母）
3. **覆盖率口径修复**（REQ-01/C126-2）：需求覆盖率改为「已覆盖模块数/模块总数 × 覆盖模块内用例数权重」，修复 0% 显示
4. **下游动作打通**（TR-02/RP-01）：
   - 执行失败 ≥ 阈值（默认 1 条）自动创建缺陷草稿（标题=用例+环境+时间，P 级按用例优先级）
   - 计划执行完成自动生成报告（或报告中心显示「有可生成报告的已执行计划」引导卡）
   - 工作台/追溯统计接入真实执行数据（修复全 0）
5. **通知打通**（连带 F-6）：通知渠道配置后，失败自动通知订阅者（钉钉/SMTP）

### 3.2 验收标准

- 工作台/追溯/集成页用例总数三处一致（同一天同一项目）
- 一键执行 325 条后：执行历史真实计数、失败自动转缺陷草稿、报告中心出现可生成报告引导
- 需求覆盖率显示非 0 真实值（54/660 → 按新口径计算）

## 4. 批次 C：前端请求层重构（P1，batch-149）

**问题**：运行时 menus×15/environments×4/stats×2/domains×2；代码 A~H 全部模式；C146-3

### 4.1 技术方案

1. **请求层加缓存/去重**（G1 根因修复）：
   - `client.ts` 增加 GET 请求去重（同 URL 并发合并）+ 可选 session 缓存（menus/environments/domains/projects/current）
   - 缓存失效：登录/登出清空；项目切换清空项目域缓存
2. **菜单会话级缓存**（运行时最大头）：`/system/menus` 首次拉取后存 context（auth store 已有，扩展 menus 字段），路由切换不再重拉（15→1）
3. **Tab 状态保留**（B 模式）：apitest/knowledge/system/workbench 的 Tabs 组件改为保留挂载（forceMount + 可见性控制，符合 AGENTS.md 3.4「非活跃 tab 不挂载子组件」要求——改用条件懒加载 + 已加载缓存，不引入 forceMount 反模式）
4. **轮询退避**（C 模式）：usePerfWebSocket 500ms 轮询加指数退避（1s/2s/4s/8s 上限 30s）+ 连续失败停止；uitest/WikiDiff/WikiTab/special 轮询统一退避助手 `usePollingWithBackoff`
5. **搜索防抖**（D 模式）：defect/uitest 搜索 300ms 防抖（复用 requirement 先例）
6. **死代码清理**（G4）：`usePaginatedList.ts` 启用或删除（建议删除，各页已有自研分页）；`integration` 页全量拉取改分页
7. **mindmap 大数据**：page_size=10000 改后端分页/懒加载（树形渐进展开）

### 4.2 验收标准

- 会话内 menus 请求 15→1；environments 4→1；domains 2→1
- 14 页巡检总请求量下降 ≥50%（复用 batch-146 网络捕获脚本对比）
- apitest 4 tab 来回切换不重复拉已加载数据
- 轮询失败 5 次后停止或退避至 30s；搜索连续输入仅发 1 请求
