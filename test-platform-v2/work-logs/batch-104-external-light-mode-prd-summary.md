# Batch 104 — PRD Summary（外放轻量模式：开放注册 / 邀请制 / 自助项目）

> **Product (🟦)** | Date: 2026-08-06 | Status: Approved
> **mode**: full（完整批次：引入新行为、新接口、新配置、新 Schema）

## 1. 问题陈述

测试平台当前是「管理员中心」模式：账号只能由管理员手工创建（seed 内置 admin/tester/viewer），
普通测试人员没有 `project:create` / `project:manage` 权限，项目由管理员建好后把用户加为成员。

平台需要外放给其他用户/团队使用。目标用户的行为预期是：

- 用户自己注册进入平台（受邀请码管控，防止垃圾注册）；
- 注册后自己创建项目，立刻成为该项目负责人，并使用平台全部测试功能；
- 项目负责人可以邀请自己的同事加入项目协作；
- 超级管理员保持现状：对全平台所有项目拥有全部权限，不因外放而削弱。

现状证据（`test-platform-v2/backend/app`）：

- `seed.py`：tester 角色的 `_TESTER_ACTIONS` 不含 `project:create`/`project:manage`；
- `services/project_service.py::create_project`：创建项目只写 `sys_project`，**不自动写
  `sys_project_member`**——创建者创建后看不到也进不去自己的项目；
- `api/v1/project.py`：`/projects/all` 与成员管理全部要求全局权限点，无「所有者管理自己项目」语义；
- 全仓库无 register / invite / 邀请码相关代码（rg 验证）。

## 4. 用户故事 + 验收标准

### US-01: 新用户凭邀请码注册

As a 被邀请的新用户，I want 使用管理员发放的邀请码注册，so that 我可以进入平台并开始使用。

- Given 平台开放注册（`registration_enabled=true`）且需要邀请码
- When 我在 /register 填写用户名/昵称/邮箱/密码/邀请码并提交
- Then 注册成功并自动登录，跳转到「我的项目」空态（提示创建第一个项目）
- And 用户名或邮箱重复时返回 400 业务错误并提示；邀请码无效/过期/用尽时返回 400 并提示
- And 注册接口受频率限制（复用登录限流模式，独立桶）

### US-02: 注册用户自助创建项目

As 注册用户，I want 创建自己的项目，so that 我可以立即使用测试平台功能。

- Given 我已完成注册并登录
- When 我在「我的项目」页点击新建项目并填写编码/名称/描述
- Then 项目创建成功，我自动成为项目成员与项目负责人（owner）
- And 项目立即出现在顶栏项目切换器与「我的项目」列表
- And 超过个人项目数上限（默认 5）时返回 400 并提示

### US-03: 项目负责人邀请同事

As 项目负责人，I want 邀请我的同事加入项目，so that 我们可以协作测试。

- Given 我是项目负责人且项目内已有一个同事账号（同事需先注册）
- When 我在成员管理输入同事的用户名或邮箱并选择角色后提交
- Then 同事成为项目成员，其登录后项目出现在项目列表
- And 输入的同事不存在时返回 404/400 明确提示，不暴露用户目录
- And 非项目负责人/超管调用成员管理接口返回 403

### US-04: 管理员发放与管理邀请码

As 管理员，I want 生成/查看/停用邀请码，so that 我可以控制谁可以注册。

- Given 我拥有系统管理权限
- When 我在「系统管理 → 邀请码」生成邀请码（可选次数上限/有效期）
- Then 系统返回邀请码文本，可用于 US-01 注册
- And 可查看已用次数、状态，可停用；停用后注册被拒

### US-05: 超级管理员全局权限保持

As 超级管理员，I want 对所有项目保持全部权限，so that 平台治理不因外放而受阻。

- Given 超管账号
- When 查看项目列表/任意项目数据/管理成员
- Then 行为与现状一致（`is_super` 全量可见，`*` 权限不受影响）

## 5. 技术考量

- **新表**：`sys_invite_code`（code 唯一、created_by、usage_limit、used_count、expires_at、
  status、时间戳），Alembic 迁移，保持单头；
- **新配置**：`registration_enabled`（默认 false，生产默认关闭，灰度开启）、
  `invite_code_required`（默认 true）、`default_registration_role`（默认 tester）、
  `max_projects_per_user`（默认 5）、注册频率限制；
- **新接口**：`POST /api/v1/auth/register`（公开）、
  `GET/POST /api/v1/system/invite-codes`、`POST /api/v1/system/invite-codes/{id}/disable`
  （管理员）；项目成员/编辑/删除接口增加所有者放行；
- **核心修复**：`create_project` 自动写入 `ProjectMember`（owner + 项目管理员角色）；
- **权限语义**：新增 `require_project_owner` 依赖（owner_id==当前用户 或 超管），
  用于项目编辑/删除/成员管理；全局权限点保留给超管与现有管理端；
- **风险**：外放后匿名注册流量与资源滥用 → 邀请码默认强制 + 注册限流 + 项目配额；
  邮箱非唯一约束现状保留，但注册校验重复 email 时做唯一性检查（同 username）；
- **依赖**：无新第三方依赖；邀请码生成复用 `secrets`。
