## 1. 问题陈述

Batch 104 完成外放轻量模式后，平台结构仍是「用户 ↔ 项目」平铺：

- 每个项目有 owner 与项目成员，但没有「团队/组织」容器；
- 用户无法表达「我们团队共用一个工作空间、团队下有多个项目、新同事加入团队即可
  看到团队项目」的协作心智；
- 面向外部团队/公司使用时，项目散落在个人名下，无法按组织维度管理成员与项目。

租户模式引入组织层：**用户 → 组织/团队 → 项目**。每个用户拥有一个自动创建的个人组织；
可再创建团队组织并邀请同事加入；项目归属于组织，组织成员默认可访问该组织下的项目；
项目级成员管理保留（粒度控制与外部协作者）。

## 4. 用户故事 + 验收标准

### US-01: 注册即有个人组织

As 新用户，I want 注册后自动拥有个人组织，so that 我的项目有归属空间。

- Given 我完成注册
- When 我打开「组织管理」或创建项目
- Then 存在名为「我的组织」（个人）的组织，我是组织负责人
- And 我的项目默认创建在该组织下

### US-02: 创建团队组织并邀请同事

As 用户，I want 创建团队组织并邀请同事，so that 团队可以共用工作空间。

- Given 我已登录
- When 我创建团队组织并输入同事用户名/邮箱邀请
- Then 同事成为组织成员，登录后可见该组织及其项目
- And 非组织负责人不能管理成员（403）；超过团队组织数上限返回 400

### US-03: 组织成员访问组织项目

As 组织成员，I want 无需逐个被加为项目成员即可使用组织内项目，so that 协作更顺畅。

- Given 我是组织成员且项目属于该组织
- When 我切换/打开该项目
- Then 我可以进入项目并使用授权范围内的功能（业务权限仍受全局/项目角色约束）
- And 非组织成员且非项目成员访问该项目仍 403（隔离不回归）

### US-04: 存量项目迁移

As 平台方，I want 既有项目自动挂到其负责人名下组织，so that 升级不丢数据。

- Given 数据库已有项目和用户
- When 执行 Alembic 迁移
- Then 每个现有用户获得个人组织，其拥有的项目 organization_id 指向该组织
- And 原项目成员关系与权限完全保留

### US-05: 超管全平台权限保持

As 超管，I want 对所有组织与项目保持管理能力，so that 平台治理不因租户层受阻。

- Given 超管账号
- When 查看组织/项目/成员
- Then 可见全部且行为与现状一致

## 5. 技术考量

- **新表**：`sys_organization`（id/code/name/description/owner_id/status/时间戳）、
  `sys_organization_member`（org_id/user_id/role_id/时间戳，唯一约束 org+user）；
- **改表**：`sys_project.organization_id`（可空 → 迁移后回填非空，代码按 0 视为未分组兼容）；
- **迁移与回填**：为每个现有用户创建个人组织（owner=本人），其拥有的项目
  `organization_id` 指向该组织；幂等，可重复执行；
- **角色常量**：组织成员 role_id 用整数常量（1=负责人 2=管理员 3=成员），不引入 RBAC
  表依赖（避免与现有角色体系混淆）；
- **访问控制**：`require_project` 增加「项目所属组织成员」放行分支；
  `require_org_owner_or_admin` 管理组织成员/设置；
- **新配置**：`max_team_organizations_per_user=5`（个人组织不计入）；
- **前端**：新增「组织管理」页（menu:organization）、项目创建选择组织、我的项目显示组织；
- **依赖**：无新第三方依赖。
