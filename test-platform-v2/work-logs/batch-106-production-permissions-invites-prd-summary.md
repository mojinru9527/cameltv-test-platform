# Batch 106 — PRD Summary（生产启用 + 组织权限映射 + 项目邀请链接）

> **Product (🟦)** | Date: 2026-08-06 | Status: Approved
> **mode**: full（完整批次：新功能、新接口、新 Schema、生产配置变更）
> **驱动条件**: C104-2/C105-2（生产启用）、C105-1（组织权限映射）、C104-4（项目邀请链接）

## 1. 问题陈述

外放轻量模式与租户模式已合入，但三块收尾尚未落地：

- **生产启用未做**：注册/邀请码开关在真实生产环境（Railway + Supabase）未确认开启，
  存量组织迁移未在生产库演练，配额监控无登记；
- **组织权限映射缺失**：组织负责人/管理员只能管理组织成员，却无法管理组织内项目的
  成员/质量门禁（需逐个把自己加成项目负责人），协作心智断裂；
- **项目邀请成本高**：同事入项目需先注册（平台邀请码）+ 负责人再手动邀请两步，
  没有「凭一个链接注册即入项目」的顺滑路径。

## 4. 用户故事 + 验收标准

### US-01: 生产启用

As 运维/平台负责人，I want 确认并开启生产注册与配额，so that 外部用户可正式使用。

- Given 生产配置检查清单已列出（REGISTRATION_ENABLED、INVITE_CODE_REQUIRED、配额、密钥、cookie）
- When 逐项核对并（在凭据可用时）执行生产切换 + 迁移
- Then 清单登记完成；无法自动执行的项目明确标记为人工步骤（C106 条件）
- And 迁移演练证据（SQLite + PG）落盘

### US-02: 组织权限映射

As 组织负责人/管理员，I want 直接管理组织内项目，so that 团队协作不需要逐项目授权。

- Given 我是组织 A 的负责人/管理员，项目 P 属于组织 A
- When 我打开项目 P 的成员管理或质量门禁
- Then 操作成功（等价项目管理员），无需另行成为项目负责人
- And 普通组织成员对项目 P 的管理操作仍 403；非组织成员仍 403；超管不变

### US-03: 项目邀请链接

As 项目负责人，I want 生成邀请链接发给同事，so that 同事注册后自动加入项目。

- Given 我是项目 P 的负责人
- When 我在成员管理生成项目邀请链接（可设次数/有效期）并发给同事
- Then 同事打开链接进入注册页（链接自带项目上下文）
- And 注册成功后自动成为项目 P 成员；若项目有组织且用户不在组织内，自动加入该组织
- And 链接无效/过期/用尽时注册返回 400；非负责人不能生成链接（403）

### US-04: 超管与隔离不回归

As 超管/普通用户，I want 现有权限边界不变，so that 外放安全不回退。

- Given 超管与普通用户
- When 访问组织/项目
- Then 超管全量；普通用户仅可见成员/组织范围内资源（回归）

## 5. 技术考量

- **组织权限映射**：`rbac_service.permission_codes(db, user_id, project_id)` 增加
  「项目所属组织 owner/admin → 项目级管理权限点」推导；前端 `hasPerm` 自动生效；
- **项目邀请链接**：新表 `sys_project_invite`（token 唯一、project_id、created_by、
  usage_limit、used_count、expires_at、status）+ Alembic 迁移；`RegisterIn` 增加可选
  `project_invite_token`，有效 token 免除平台邀请码，注册事务内加入项目与组织（原子化）；
- **生产启用**：产出检查清单与演练证据；production 配置文档更新；凭据可用的环境变量
  切换执行并记录，否则登记人工步骤；
- **风险**：生产切换前必须演练；邀请链接 token 用 secrets（32 字节 urlsafe）；
  组织权限映射只在项目有 organization_id 且用户为组织 owner/admin 时生效，不扩大全局权限。
