## 3. 用户故事 + 验收标准

- As a **资深测试工程师**, I want 接口用例生成覆盖「测试考虑点」全部类别（冒烟/场景/健壮性/安全/性能低优先级/数据/返回值结构/稳定性/兼容性/监控），so that 一次生成即满足团队接口测试规范，减少人工补漏。
- As a **QA**, I want 接口用例断言基于真实响应的结构（业务状态码、记录数、排序、核心字段），so that 接口自动化断言贴合生产现实而非只查 2xx。
- As a **验收负责人**, I want 规范以文档形式落盘并可在平台查证，so that 后续接口用例评审有统一事实源。

Given 对真实样本接口（如 `/camel-service/ee/news/list_visible`）生成用例，When 查看生成结果，Then 覆盖冒烟/场景/非法入参/安全/数据/稳定性/兼容性/监控全部类别，且正向/组合用例带业务结构断言。
Given AI 生成接口用例（integration 功能点），When 检查提示词与产物，Then 提示词注入「测试考虑点」清单且断言含关键字段/业务规则。
Given 规范来源，When 检查 `tests/test-case-standards/`，Then 有「接口测试考虑点」文档且与 XMind 节点一一对应。
