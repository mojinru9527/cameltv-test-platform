# Batch 122 — Design Spec（用例结构规范 + 状态机/关联/权限模板）

> **Design (🎨)** | Date: 2026-08-08 | Status: 就绪

## 0. 技术体系确认
用例载体为平台 `test_case` 数据模型（domain/module/tags/preconditions/steps/expected_result/api_*），不引入新依赖；脚本 Python 3（后端 venv），幂等可重复执行。

## 1. 用例结构规范（本批核心交付）

### 1.1 域（domain）
| 域 | 内容 |
|----|------|
| `体育-用户端-功能` | 用户端全部功能用例（按入口拆分） |
| `体育-运营后台-功能` | 运营后台 + konfi 功能用例 |
| `体育-接口测试` | 接口用例（按模块归类） |

### 1.2 模块路径（module）= `入口/一级模块/二级模块`
| 入口代码 | 含义 |
|----------|------|
| `安卓iOS` | 安卓/iOS 原生客户端 |
| `PC-web` | PC 网页端（完全功能版） |
| `移动端-web` | 移动端 H5 |
| `运营后台` | 运营后台管理端 |
| `konfi` | 配置系统 |

示例：`安卓iOS/赛事详情/预测Pick`、`PC-web/赛事详情/预测Pick`、`移动端-web/个人中心/银钻明细`、`运营后台/赛事预测/奖励发放记录`、`konfi/首页/热门联赛`。

### 1.3 标签（tags）
`功能用例|接口用例`、`P0|P1|P2`、`闭环`（端到端用户流程）、`关联:{模块}`（跨模块）、`权限`。

### 1.4 用例编号（case_id）
`SP-{入口}-{模块缩写}-{3位序号}`，如 `SP-AND-PICK-001`、`SP-ADM-FORECAST-REWARD-001`、`SP-I-ODDS-001`（接口）。

## 2. 用例字段规范
| 字段 | 要求 |
|------|------|
| preconditions | 明确数据构造（状态、账号、余额、环境），禁止 `—` |
| steps | 结构化步骤数组，每步含 desc + 可选 action/expected |
| expected_result | 具体可断言结果（文案/数值/跳转/状态），禁止空 |
| 单步拦截 | 仅「查看XX」且无断言的用例视为无效，校验脚本拦截 |

## 3. 状态机模板（预测模块，作为全模块通用模板）
```
未开放 → 预测中(可参与) → 待开奖 → 已开奖(WIN/LOSS) / 已取消(退款)
```
| 状态 | 关键用例 |
|------|---------|
| 未开放 | 无预测入口/选项隐藏；比赛无预测时展示兜底 |
| 预测中 | 下注成功（选项/金额/赔率/实时可赢）；余额不足；低于下限/超上限；单日上限；赔率变更；未登录引导；「?」玩法说明；三选项分别下注/全下注 |
| 待开奖 | 不可再下注；预测记录展示「待开奖」 |
| 已开奖 WIN | 奖励=投入×赔率(向下取整)自动发放；银钻流水可见；记录展示选项与奖励 |
| 已开奖 LOSS | 不返还；记录展示失败 |
| 已取消 | 原路退款；记录展示「已退款」 |
| 跨状态 | 确认参与时状态已变化 → 关闭弹窗+更新+「非预测中」提示 |

## 4. 关联用例规范（闭环模板）
- 核心闭环：`赛事详情/预测Pick(下注) → 预测记录(待开奖/已开奖) → 银钻流水(奖励入账) → 我的资产/银钻明细`，一条 `闭环` 用例串起。
- 关联维度：赛事详情↔直播/聊天/指数/赛程/阵容；资讯↔赛事详情/球员/球队；联赛↔球队↔球员；商城↔钱包/银钻；运营后台赛事预测↔用户端预测。
- 每条闭环用例在 tags 标 `闭环`，steps 覆盖真实跳转链路。

## 5. 权限用例规范（PC-web/移动端-web/安卓iOS）
| 入口 | 权限点 |
|------|--------|
| 安卓iOS | 通知/相册/相机/定位 首次授权、拒绝、撤销、二次授权 |
| 移动端-web | 浏览器通知/摄像头/麦克风 授权与拒绝、H5 权限降级 |
| PC-web | 通知权限、摄像头/麦克风（直播互动）、浏览器弹窗拦截 |

## 6. 设计 QA 走查发现（本批结构层面）
### ⚪ P3-01 平台用例分类管理仅支持扁平模块
`test_case_module` 无 parent 层级；结构采用模块路径字符串表达层级，前端分类管理与脑图按字符串展示（可接受，作为 P3 建议后续做树形化）。
### ⚪ P3-02 用例编号需保持稳定
本批新增规范域用例采用新编号体系；旧域数据不动，避免破坏既有引用。

## 7. 设计签核
结论：**通过**（结构规范可落地；P3 建议记入 backlog，不影响本批）。
