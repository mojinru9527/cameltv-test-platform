# Batch 123 — PRD（知识中心可用性 + 体育模块关联图谱）

> **Product (🟦)** | Date: 2026-08-08 | Status: Review

## 1. 问题陈述

用户走查反馈：知识中心「部分功能能用、部分用不了」「样子货、可用性不高」，且**没有体现体育平台不同模块之间的关联关系**，无法帮助到测试工作。结合仓库核查，问题如下：

| # | 问题 | 证据（文件/数据） |
|---|------|------------------|
| 1 | **知识源详情弹窗歪七扭八、展示不全** | `SourceListTab.tsx` Dialog `max-w-7xl max-h-[90vh] w-[95vw]` + 网格 + 长原始内容，布局易错乱 |
| 2 | **wiki「编译」只是发起任务，无结果展示** | `WikiTab.tsx` compile → toast「已提交 Wiki 编译任务 #id，稍后刷新查看页面」；无任务进度/产物内容面板 |
| 3 | **知识差异对比「发起对比」结果不可用** | `WikiDiffTab.tsx` 发起任务后结果展示链路用户感知不到 |
| 4 | **图谱无完整逻辑关联与展示** | 本地库实体 519 个（api 271/field 246/requirement 1/test_case 1），关系 11310 条**全部为 contains**；`graph_view` 仅返回实体+关系，无语义关系（tested_by/navigates_to/configures 等） |
| 5 | **实体数据来源不明** | `EntityTab.tsx` 列表/详情无来源溯源展示；实体由 api/field 自动提取，非需求驱动 |
| 6 | **项目球无实际价值** | `SphereTab.tsx` 基于发布包层级渲染 vis-network，无操作价值 |
| 7 | **未体现体育模块关联** | 知识库无 用户端↔运营后台↔konfi、用例↔接口、闭环链路 的关系沉淀（Batch 122 已产出 507 条结构化用例与闭环/关联标签，未被知识库利用） |

## 2. 成功指标

| 指标 | 基线 | 目标 |
|------|------|------|
| 知识源弹窗 | 布局错乱 | 结构化展示（元数据/溯源/切片），滚动完整，无错乱 |
| wiki 编译 | 仅 toast 无结果 | 编译任务有状态面板（进行中/成功/失败/产物页面），成功后直接展示生成页面内容 |
| 差异对比 | 结果不可用 | 发起对比后可看到对比项列表（差异维度/严重级/证据），可逐条查看 |
| 图谱语义 | 仅 contains | 含业务语义关系（tested_by/navigates_to/configures/links_to_admin 等）；体育模块关联关系入库 |
| 实体溯源 | 来源不明 | 每个实体展示来源（来源类型/标题/切片/文档引用） |
| 项目球 | 无价值 | 改造为「体育模块关联球」或明确移除 |
| 模块关联 | 无 | 图谱体现 用户端↔运营后台↔konfi、用例↔接口、闭环链路（来源 Batch 122 用例结构） |

## 3. 非目标（本次不做）

- **体育用例内容本身**（Batch 122 已交付，本批只消费其结构/标签建关联）。
- **知识中心搜索/RAG 效果**（search 已可用，不在本批）。
- **外部 LLM Wiki 连接器**（health_check/search 已实现，不在本批）。
- **知识源内容正确性**（需求/设计稿入库为批次 C，后续处理）。
- **konfi/运营后台数据完整性**（同批次 C）。

## 4. 用户故事 + 验收标准

- As a **测试人员**, I want 查看知识源弹窗完整可读，so that 能快速看到来源、溯源与切片内容。
- As a **测试人员**, I want wiki「编译」能看到任务结果与生成页面内容，so that 编译不是黑盒。
- As a **测试人员**, I want「发起对比」后能看到差异项与证据，so that 对比结论可落地。
- As a **测试人员**, I want 图谱/实体能体现体育模块关联与来源，so that 知识库能帮助理解「哪个后台配置影响哪个用户端功能、哪个用例覆盖哪个接口」。

验收（Given/When/Then）：
- Given 知识源详情弹窗，When 打开任意知识源，Then 元数据/溯源/切片完整展示且可滚动到底。
- Given wiki 来源点「编译」，When 任务完成，Then 页面展示任务状态与生成页面列表，可打开页面查看内容。
- Given 差异对比「发起对比」，When 任务成功，Then 展示差异项列表（维度/严重级/证据），可逐条查看。
- Given 图谱，When 加载体育项目，Then 出现非 contains 语义关系（如 用例→接口 tested_by、运营后台→用户端 links_to_admin、闭环链路）。
- Given 实体列表，When 查看任一实体，Then 展示来源（来源类型/标题/切片引用）。

## 5. 技术考量

- 前端：`pages/knowledge/components/` 各 Tab 重构；布局走 `cameltv-ui-conventions`；弹窗用 Sheet/Dialog 规范化。
- 后端：`api/v1/knowledge.py` graph 端点扩展语义关系；`api/v1/wiki.py` ingest/diff 任务状态与结果查询补全；新增「模块关联」导入端点（消费 Batch 122 用例结构/闭环/关联标签生成 knowledge_relation）。
- 数据：`knowledge_relation` 新增非 contains 关系类型；`knowledge_entity` 补充 requirement/test_case 实体来源。
- 风险：图谱数据量大时 vis-network 性能；用 limit + 分层加载。
