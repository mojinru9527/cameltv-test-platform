# Batch 124 — PRD（需求/设计稿入库 + 图谱 P0 崩溃修复）

> **Product (🟦)** | Date: 2026-08-08 | Status: Review

## 1. 问题陈述

用户反馈两件事：
1. **需求/设计稿入库反复失败（批次 C）**：「已经是N次了，这个玩意就是用不到平台上来，要么就是截图少很多数据，要么就是遗漏对应数据的图片，这样你根本不知道这个需求里面是讲了啥东西。」现有 `requirement_document` 导入记录 `imported_count=0`——需求文档解析了但没有真正变成可用内容/图片。
2. **图谱页生产崩溃（P0）**：C123-2 生产 UI 走查发现，知识中心「图谱」Tab 在生产直接整页崩溃——`graph_view` 返回重复节点 id（旧提取重复实体 `test_case:p1:首页热门赛事-真实分页参数`），vis-network `add` 抛错 → React error 页。

## 2. 成功指标

| 指标 | 基线 | 目标 |
|------|------|------|
| 图谱页可用 | 生产崩溃（重复 id） | 图谱页正常渲染，重复节点/边自动去重不崩溃；生产重复实体清理 |
| 需求文档入库 | imported_count=0 | 需求文档（用户端 98 页 + 运营后台 72 页原型）完整入库：文本+图片完整，可查看/可溯源 |
| 设计稿图片 | 截图少数据/遗漏图片 | 每页设计稿图片完整入库（本地 `axure_extract_test/*.html + images/` 为输入源），可预览 |
| 知识中心可用 | 需求内容不可见 | 需求/设计稿在知识中心可见（来源/切片/图片） |

## 3. 非目标（本次不做）

- 体育用例内容（Batch 122 已交付）。
- 知识中心其他可用性（Batch 123 已交付，除图谱 P0 外）。
- 运营后台长尾接口深补（C122-2 长尾，后续批次）。
- konfi/运营后台数据完整性。

## 4. 用户故事 + 验收标准

- As a **测试人员**, I want 需求文档与设计稿完整入库（文本+图片），so that 我知道每个需求页讲了什么、长什么样。
- As a **平台用户**, I want 图谱页不崩溃且能查看模块关联，so that 知识中心可用。

验收（Given/When/Then）：
- Given 需求/设计稿导入，When 完成入库，Then `requirement_document` imported_count>0 且每条来源含完整文本+设计稿图片（可预览）。
- Given 图谱页，When 生产打开，Then 正常渲染不崩溃，重复实体不导致错误。

## 5. 技术考量

- **图谱 P0 修复**：`graph_view` 对 nodes 按 id 去重（保留首个）、edges 过滤指向已删除节点的边；生产清理重复实体（按 entity_key 去重，保留 id 最小者）。
- **需求入库**：以本地 `backend/data/axure_extract_test/`（130+ HTML 含功能点表 + `images/` 设计稿截图）为输入源，走 上传→提取→确认→生成→导入 或直连知识源入库；图片完整上传/引用，避免「截图少数据/遗漏图片」。
- **来源可溯**：导入的每条知识源带 页面名/HTML 文件/图片清单，可在知识中心查看原文与图片。
