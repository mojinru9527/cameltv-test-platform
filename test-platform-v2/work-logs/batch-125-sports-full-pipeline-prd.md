# Batch 125 — PRD（体育平台完整链路接入）

> **Product (🟦)** | Date: 2026-08-09 | Status: Review

## 1. 问题陈述

用户明确要求：**以后输出的功能用例 / 接口用例 / AI 生成用例都必须走「功能用例规范 skill + 接口用例 skill」两个基座**，因此要对体育平台重新做一次**完整的链路接入**：

- 现状（Batch 122）：507 条 SP- 深度用例是**手工编写**，未先经基座生成基础用例 → 不符合「基座先行」要求。
- 现状（Batch 124）：两个基座 skill（含权威输出要求 + 深度用例补充层）已接入 `ai_service` 生成链路，蓝湖导出（用户端 109 页/运营后台 74 页）与模块树（218 节点）已就绪，但**生产知识中心尚未体现完整链路**：需求/设计稿未入库（C124-1 待部署后执行）、模块树生产仅 88 节点、无生产深度体验内容、用例未与模块树/需求关联展示。

## 4. 用户故事 + 验收标准

- As a **测试人员**, I want 看到体育平台全功能梳理（用户端+运营后台）在知识中心可查，so that 知道平台有哪些功能、对应哪些需求页/设计稿。
- As a **测试人员**, I want 生产深度体验/逻辑补充内容入库，so that 用例覆盖生产真实状态与边界。
- As a **测试人员**, I want 所有模块用例 = 基座基础用例 + 深度用例，so that 覆盖完整且可溯源。
- As a **知识中心用户**, I want 需求/设计稿/模块树/生产发现/用例关联 一体化可见，so that 知识库可靠可用易用。

验收（Given/When/Then）：
- Given 蓝湖导出（用户端/运营后台），When 功能梳理完成，Then 生成全量功能点清单并入库（source_type=requirement/feature_inventory）。
- Given 生产站点 camel1.tv，When 二次探索完成，Then 生产走查报告入库且用例含生产真实状态（登录/未登录/各活动状态/结算闭环）。
- Given 两 skill 基座，When 每模块生成用例，Then 输出 基础用例（正/负/边界）+ 深度用例（状态机/闭环/关联/权限）双覆盖，可溯源到需求页。
- Given 知识中心，When 全部入库完成，Then 需求文本+设计稿、模块树、生产发现、用例关联可见。

## 5. 技术考量

- **功能梳理**：复用 Batch 124 蓝湖导出 + `build_lanhu_hierarchy.py`（218 节点），从 HTML 提取功能点 → 生成 `sports-feature-inventory.json`（模块×页×功能点），经设计稿/需求入库链路写入知识中心。
- **二次探索+生产深度体验**：Playwright 走查 camel1.tv（登录/未登录、预测 pick 全状态、直播间、我的/钱包、UGC、搜索、资讯、联赛球队球员、个人中心等），记录页面/交互/状态/差异 → 结构化生产发现 JSON 入库。
- **用例生成链路**：ai_service 已加载两 skill 权威输出要求；生产 DeepSeek Key 已配置。每模块：先基座生成基础用例（正/负/边界）→ 再叠加深度用例（Batch 122 模式）。
- **知识中心体现**：design-assets 入库（C124-1）、import-tree 全量模块树、生产发现 source、用例-模块关联（tested_by 图谱关系）。
