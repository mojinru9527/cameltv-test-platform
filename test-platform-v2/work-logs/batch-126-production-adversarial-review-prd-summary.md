> **Product (🟦)** | Date: 2026-08-09 | Status: Approved

```markdown
mode: light
豁免理由: 生产验收与缺陷修复批次；仅修复图谱数据截断并补充既有差异对比入口引导，不新增接口、配置、依赖或业务能力，按 pipeline-modes.md 采用 PRD-lite + QA + Leader + 看板。
非目标: 不在本批实现实体来源回填、覆盖率口径调整、置信度计算或图谱分层聚合；这些事项登记为 C126-1~4。
```

## 1. 问题陈述

生产环境对抗性走查发现知识图谱只展示 195 个节点，而概览已有 970 个实体；同时，知识差异对比入口在未输入关键词时直接禁用，用户无法判断解锁条件。前者造成数据完整性误判，后者造成“功能不可用”的误解。

## 2. 成功指标

| 指标 | 基线 | 目标 | 测量方式 |
|------|------|------|----------|
| 图谱加载上限 | 200 | 1000，覆盖当前 970 个实体 | `fetchGraphView(1000)` + 类型检查/构建 |
| 大图谱风险提示 | 无 | 节点数大于 400 时展示性能提示 | 组件源码 + 前端测试 |
| 差异对比解锁引导 | 禁用且无说明 | 空关键词时展示说明与 tooltip | 组件源码 + 前端测试 |
| 前端回归 | 未知 | typecheck/build/全量 Vitest 全绿 | 本地可执行门禁与 PR required checks |

## 3. 非目标与 C 条件

- C126-1：实体来源补全与存量回填，不在本批处理，涉及后端和数据迁移。
- C126-2：需求覆盖率口径核对，不在本批改变统计定义。
- C126-3：AI 审核台置信度计算核对，不在本批修改产物算法。
- C126-4：图谱分层/聚合性能优化，不在本批扩大为架构重构。
- C123-3、C125-1 等既有开放条件保持原状态。

## 4. 用户故事与验收标准

- As a 知识中心使用者, I want 图谱展示当前完整实体集合, so that 我不会因分页截断误判知识资产缺失。
  - Given 当前实体数不超过 1000，When 打开知识图谱，Then 前端以 1000 为上限请求图谱，并在大于 400 个节点时提示性能风险。
- As a 差异对比使用者, I want 在按钮不可用时看到原因, so that 我知道输入关键词后即可发起对比。
  - Given 关键词为空，When 查看“发起对比”操作，Then 页面展示“请先输入需求关键词”并提供 tooltip。
- Given 分支准备交付，When 执行前端门禁，Then typecheck、build、相关测试与全量 Vitest 均退出 0。

## 5. 技术考量

- 仅调整前端请求上限、提示文案与语义颜色 token；无 API schema、数据库、依赖或部署配置变化。
- 1000 节点仍可能产生渲染压力，因此显式提示按域过滤，长期优化由 C126-4 承接。

## 6. 上线计划

| 阶段 | 成功门槛 |
|------|----------|
| Draft PR | 本地门禁全绿、Agent Team 基础审计通过 |
| 合入 main | required checks 全绿、最终审计通过、Leader APPROVED |
| 部署后复测 | 图谱数据完整性与性能提示在生产可见 |

## 7. 技能使用

- `cameltv-agent-team`：轻量批次判定、工件与 Git 门禁。
- `cameltv-ui-conventions`：使用 `text-status-warning` 语义 token，避免固定色板类。
- `cameltv-bug-guard`：复核异步 cleanup、请求链路和依赖边界未被本批破坏。
