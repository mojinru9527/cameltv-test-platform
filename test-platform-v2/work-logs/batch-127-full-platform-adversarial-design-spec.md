# Batch 127 — Design Spec（全功能对抗性加固）

> **Design (🎨)** | Date: 2026-08-09 | Status: Ready

## 1. 设计方向

本平台是高频内部 QA/工程工具，保留现有 shadcn/Radix + Tailwind 信息架构和高密度布局，采用针对性生产加固：设计方差 3、动效 2、密度 8。重点不是重做视觉，而是让状态、数字、权限和恢复动作一眼可信。

## 2. 信息层级

- 页面级：标题、用途、项目上下文、主要操作。
- 数据级：全量总数、当前筛选/加载数、更新时间或限制说明。
- 状态级：加载、空、成功、警告、错误、未配置互斥表达。
- 操作级：主操作文字按钮；纯图标操作必须有 `aria-label`/tooltip；危险操作必须确认。

## 3. 跨模块模式

### 3.1 统计可信度

- “总数”只能来自服务端项目级统计，不从当前页、当前域或加载上限推导。
- 历史 `functional` 在展示层归一为“功能用例”，不改变记录原始可追溯性。
- 实体页显示“项目全量 N / 当前展示 M”；按类型筛选时显示筛选后的服务端总量。

### 3.2 加载与性能

- 页面骨架必须在首次请求发出时立即出现，不能等待所有子模块完成才渲染页面壳。
- 交互缺口后端预构建一次小写搜索语料与模块提示集合；单边匹配不再重复拼接用例文本。
- 大图谱继续保留规模提示；本批不引入高风险图形库或新依赖。

### 3.3 状态本地化

- 审核：`pending=待审核`、`approved=已采纳`、`rejected=已驳回`、`imported=已导入`、`draft=草稿`。
- 来源：`active=生效中`、`parsed=已解析`、`syncing=同步中` 等按语义 token 显示。
- 未知枚举显示“未知状态（原值）”或中性原值，避免错误映射。

### 3.4 未配置态

- 运维发布控制的 release-control store 未配置属于预期能力边界，不使用通用错误红框。
- 展示 warning/empty 组合：当前环境未启用、不会提供写操作、启用条件由受控执行器/配置负责；保留刷新用于配置完成后的恢复。
- 非预期网络/服务器错误仍走 `AsyncState` error + retry。

### 3.5 路由与命名

- 菜单、`document.title`、页面 H1 采用同一产品词汇；别名只用于说明，不并列制造两个概念。
- 正式、实验、仅开发、退役四种路由状态写入审查报告；生产可访问的 demo 必须显式标记或门禁。

## 4. 响应式与可访问性

- 360/768/1280/1440 宽度检查页面级横向溢出；宽表允许容器内滚动，不允许文档级溢出。
- 图标按钮、Switch、Tab 和表格行操作必须有稳定名称；交互目标最小 36px，高频主操作 40–44px。
- 焦点环使用现有 token；不新增固定色板类；亮/暗主题均验证 warning/error/selected 对比度。
- `prefers-reduced-motion` 下不增加新的持续动画。

## 5. 关键状态线框

```text
页面标题 / 描述                         [刷新]
┌ 项目全量 970 ─ 当前展示 200 ─ 数据质量提示 ┐
│ 筛选 [全部类型]  搜索 [____________]        │
├──────────────────────────────────────────────┤
│ 表格 / 骨架 / 空态 / 非预期错误              │
└──────────────────────────────────────────────┘
```

```text
运维发布控制
┌ ⚠ 当前环境未启用发布控制数据源               ┐
│ 这是受控能力边界；页面不会提供发布/回滚操作。 │
└──────────────────────────────────────────────┘
┌ 发布记录：暂无配置后的持久化记录 ┐  ┌ 时间线 ┐
```

## 6. 预检结论

- IA：保留现有主导航；隐藏路由先完成产品状态审计，再决定暴露或门禁。
- 组件：复用 `PageShell/PageHeader`、`AsyncState`、`Badge`、`Card`、`Tabs`，不引入新组件体系。
- 数据：服务端负责全量统计与 canonical 口径；前端不猜测。
- 内容：错误文案不包含数据库/store/堆栈等内部实现细节。
