## 2. 优先级

- P0：认证绕过、跨项目数据泄露、生产误写、核心 CRUD 不可恢复、白屏/崩溃。
- P1：统计错误、核心页面长时间无反馈、错误降级、关键能力不可发现、可访问性阻断。
- P2：术语/标题漂移、状态未本地化、内部实验入口暴露、文档陈旧。
- P3：长期架构、外部依赖、存量数据回填与非关键视觉精修。

执行顺序以“安全与数据可信度 → 核心任务可完成 → 性能/恢复 → 一致性”为准，不以页面目录顺序推进。

## 3. 验收策略

- 生产：登录后只读访问、筛选、展开、详情和页签；记录 URL、可见标题、状态、关键数字、控制台和网络失败。
- 本地：用受控账号和独立 SQLite 完成创建/编辑/批量/删除/恢复；测试数据使用 `B127-` 前缀。
- 服务：契约测试验证项目隔离、软删除、历史枚举兼容、静态路由优先级和错误 envelope。
- 前端：组件测试验证取消请求、状态映射、全量/当前加载文案、无名按钮与受控空态。
- 回归：P0/P1 全执行；P2 按风险执行；外部阻塞项明确 Blocked/Deferred。

## 4. 风险控制

- 任何生产写操作视为 Blocker；浏览器流程以页面查询和直达只读 URL 为主。
- 若修复改变 API schema，同步 OpenAPI 与前端类型；否则优先增加向后兼容字段/端点。
- 性能测试不使用脆弱绝对毫秒阈值；验证索引构建次数和复杂度边界，并记录观察耗时。
- 每完成一个切片更新看板、发现清单、测试证据和 C 条件，避免长批次上下文丢失。
