# Batch 128 — 复盘卡

| 项目 | 结果 |
|------|------|
| 计划 | 公开访问边界 → 普通注册 → taxonomy → 用例服务/脑图 → 双端全量 → 三视口浏览器 |
| 原始问题 | 3 项，全部闭环 |
| 返工 | 5 类：注册默认、静态路由顺序、前端访客壳、子模块初始化、可选邀请码撤销语义 |
| 主要根因 | 后端已有数据语义但 UI 未消费；Batch 104 邀请制策略未随外放目标演进；根路由守卫把“发现”和“使用”混为一层 |
| 有效做法 | 先规定匿名数据最小集；阻止 Outlet 挂载；用存量字段推导 taxonomy；普通注册与强制邀请码双模式同时回归 |
| 下次改进 | 把公开目录、注册策略和 taxonomy 加入长期 E2E；发布控制面增加注册外部变量核对项 |

本批最重要的教训：公开“平台能做什么”和公开“用户的数据”是两个完全不同的安全边界。正确做法不是把整个产品锁在登录页后，而是公开能力目录，在真正访问数据和执行操作前统一鉴权。
