# Batch 129 — PRD Summary（访客功能浏览、项目引导与用例重分类）
> **Product (🟦)** | Date: 2026-08-09 | Status: Approved | mode: full

## 1. 问题陈述

### 1.1 为什么用户关心访客能进入模块页

1. 外部用户在注册前需要判断平台是否覆盖自己的测试工作，而不是只看到模块名称。
2. Batch 128 将访客模块点击直接绑定登录 Dialog（`GuestPlatformHome.tsx`），且 `MainLayout.tsx` 对访客不挂载任何路由内容；因此访客无法看到模块职责、主要能力和使用边界。
3. 公开业务数据会泄露项目资产，所以正确边界是“模块说明公开、项目数据与操作登录后开放”，不是匿名读取业务 API。

### 1.2 为什么无项目状态必须在布局层处理

1. 普通注册用户初始 `projects=[]`、`currentProjectId=null`，但当前布局仍挂载 `<Outlet />`。
2. 各业务页随后各自请求依赖 `X-Project-Id` 的接口，造成重复的“缺少项目 ID”错误；页面级逐个补丁既容易遗漏，也会继续产生无效网络请求。
3. 项目是业务数据的最小租户边界，因此布局必须在挂载业务页前阻断，并提供“创建第一个项目”的明确入口。

### 1.3 为什么“其他”必须重分类

1. 用例分类用于导航，不只是统计标签；把可识别数据放在“其他”会丢失用户端/运营后台心智模型。
2. Batch 110 的 476 条存量功能用例使用 31 个旧业务域名，其中 12 个为运营后台域、19 个为用户端域；现有分类器只识别域名中显式出现的“用户端/后台”等字样，因而全部或大部分落入“其他”。
3. 仓库已有《体育平台-用例结构规范》和《体育平台-功能模块地图》作为确定性归类依据，无需猜测或修改历史用例正文。

## 2. 成功指标

| 指标 | 基线 | 目标 | 测量窗口 |
|------|------|------|---------|

## 4. 用户故事 + 验收标准

### US1：访客查看模块能力

- As a 未登录访客, I want 点击侧栏或首页模块后进入模块说明页, so that 我能在注册前判断平台能力。
- 验收：Given 未登录且公开目录已加载 / When 点击任一模块 / Then URL 切换到模块路径，显示该模块名称、说明、能力清单和登录后可用提示，不弹登录且不发业务 API 请求。

### US2：访客开始使用

- As a 未登录访客, I want 在模块说明页选择“登录后使用”, so that 登录后回到原目标模块。
- 验收：Given 位于访客模块说明页 / When 点击主 CTA / Then 弹出登录 Dialog；登录成功后导航到原路径；注册入口按公开策略显示。

### US3：新用户创建首个项目

- As a 已登录但无项目的普通用户, I want 在任何项目功能入口看到创建项目提示, so that 不再遭遇缺 Project ID 错误。
- 验收：Given `projects=[]` 且 `currentProjectId=null` / When 访问项目域路由 / Then 不挂载业务 Outlet，展示空状态和“创建第一个项目”按钮；When 点击 / Then 到 `/my-projects` 并可创建项目。
- 验收：Given 同一用户 / When 访问 `/my-projects` 或 `/organizations` / Then 页面正常挂载，项目创建链路不被边界拦截。

### US4：存量用例正确归类

- As a 测试人员, I want 用例服务和脑图按用户端/运营后台展示旧数据, so that 我能沿产品界面和子模块定位用例。
- 验收：Given 31 个 Batch 110 旧域 / When 请求用例列表或 taxonomy / Then 每条返回一致的 `surface`，且没有一个落入“其他”。
- 验收：Given 当前用例集中没有未知归类 / When 打开脑图界面筛选 / Then 不显示“其他”选项；若未来确有未知域，则保留“其他”作为显式数据质量信号。

## 5. 技术考量

- 访客页使用静态能力目录，不读取项目数据，避免扩大匿名 API 面。
- 项目阻断必须发生在 `<Outlet />` 上层，才能保证子页面副作用不会运行。
- `surface` 由后端单一分类器生成并随 `TestCaseOut` 返回，脑图消费该字段；避免前后端各维护一套旧域规则。
- 旧域映射来自仓库事实源，并以完整 31 域回归测试锁定；未知域仍保留“其他”，避免静默误分类。
- KB 在线检索当前无可用凭据；以 `C-CONDITIONS.md`、Batch 104/122/128 工件、Bug Guard 与仓库历史缺陷检索作为替代证据。
