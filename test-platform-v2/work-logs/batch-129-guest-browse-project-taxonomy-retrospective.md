# Batch 129 — Retrospective

> Date: 2026-08-09 | Mode: full | Executor: codex

## What worked

- 把“可浏览”重新定义为公开静态说明，而不是匿名挂载业务页，既满足产品发现又不扩大数据攻击面。
- 把项目缺失提升到布局边界，单点阻断所有子页副作用，浏览器 Network 直接证明请求为 0。
- 用 Batch 110 审计源计算整批结果，而不只用几条样例；476 条/31 域的归类闭环可量化。
- 先让测试针对缺失边界变红，再实现组件和分类器，避免仅凭截图判断完成。

## What was adversarially challenged

- 仅隐藏错误 toast 不能阻止子页请求；验收标准改为“子组件不挂载 + 业务请求为 0”。
- 直接移除“其他”会掩盖未来未知域；最终保留后端未知信号，只在当前数据没有未知时不展示空筛选。
- 前端维护一份旧域映射会再次漂移；最终把 `surface` 加入列表契约，让服务和脑图共享后端事实源。
- 首次后端全量的 3 个失败来自未初始化 submodule；初始化后先复跑失败集，再完整重跑，避免把环境问题写成“历史失败”。

## Reusable lessons

1. 产品公开浏览应公开“能力元数据”，不应以匿名请求真实业务页来实现。
2. 任何项目级页面在无项目时都应由布局级 boundary 阻断，而不是让每个页面各自处理 400/422。
3. 分类规则应由提供数据的一侧输出稳定结果，展示层不重复推断。
4. 存量迁移/重分类验收必须对完整审计集合计数，样例测试只能作为补充。

## Follow-up

- 不新增新的 C 条件；C122-4 的用例结构联动已由列表/taxonomy/脑图共享 `surface` 及 476 条审计结果满足。
- 生产发布后复验访客直达、注册用户无项目提示和生产数据“其他”计数；该外部状态不在本地代码合入中伪造完成。
