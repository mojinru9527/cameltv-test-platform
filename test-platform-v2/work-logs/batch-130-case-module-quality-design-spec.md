# Batch 130 — Design Spec（业务模块聚合与异常审查）
> **Design (🎨)** | Date: 2026-08-09 | Status: 就绪

## 1. 信息架构

```text
模块分类
├─ 用户端
│  ├─ 首页
│  ├─ 赛事详情
│  │  ├─ 预测 Pick
│  │  ├─ 赛程
│  │  └─ 阵容
│  └─ …
├─ 运营后台
│  ├─ UGC
│  ├─ 财务管理
│  └─ …
└─ 接口测试（仅“全部/接口用例”时出现）

终端范围：安卓/iOS、PC Web、移动 Web → 用例标签与详情字段，不进入树层级
```

## 2. 规范化规则

1. `case_type=api` 优先归接口测试；否则按显式前缀和存量域映射确定用户端/运营后台/其他。
2. 从 domain 去除 `体育/体育平台/用户端/运营后台/接口测试/功能` 等纯壳层，保留剩余业务段。
3. 从每个路径段去除完整终端节点和 `_pc_/_web_/_mb_/_移动_/(PC)` 等展示后缀；不删除正文或 tags 中的终端信息。
4. 合并 domain 与 module 的重叠前缀；业务首段为 taxonomy domain，其余为子路径。
5. 别名仅做有证据的最小归一：如 `赛事详情页 → 赛事详情`、`ugc → UGC`；不猜测未知业务含义。

## 3. 用例服务 UI

| 区域 | 规格 | 行为 |
|------|------|------|
| 分类树 | 220px 现有卡片，最多显示业务三级 | surface/domain/任意 module 节点均可筛选，父节点包含全部后代 |
| 业务域 Select | `sm:w-[150px]` | 数据来自当前 taxonomy；切换后清空子模块 |
| 子模块 Select | `sm:w-[170px]` | 扁平展示当前业务域的规范路径 |
| 场景 Select | `sm:w-[120px]` | 全部场景、正向、负向、边界；使用非空 sentinel |
| 场景标签 | 表格与 Drawer 统一语义 | 正向=success、负向=danger、边界=warning；同时显示文字 |

## 4. 状态与无障碍

- taxonomy 加载/错误/空态沿用现有页面四态，不用空树冒充成功。
- Select 均有 `aria-label`；树节点计数为文字，不只靠颜色表达。
- 场景标签在深浅主题均可辨；不引入硬编码浅色背景。
- 移动端继续隐藏左树，但三个筛选下拉可换行为全宽，异常筛选仍可达。

## 5. 对抗用例设计

### 读取型功能

- 故障恢复：首次请求超时/5xx → 明确错误与重试 → 单次重试恢复；旧数据不伪装为新数据，列表不重复。
- 重复交互：快速重复切 Tab/筛选/刷新 → 最终状态与最后一次选择一致；有效请求受控、结果不重复。

### 写入/交易型功能

- 重复提交：按钮防重 + 服务端幂等；业务记录、余额/库存/奖励、审计各只变化一次。
- 并发/故障：并发修改或下游失败时不得部分提交；冲突明确、原值可复核，重试后只形成一次最终结果。

### 管理配置型功能

- 无权限与跨角色访问被拒绝，不泄露详情或数量。
- 保存失败不发布半成品；缓存/用户端读取仍为旧版本；恢复后重新保存，配置、审计和下发版本一致。

## 6. 设计签核

结论：**通过**。业务模块是导航主轴，终端是覆盖维度；异常场景必须可筛、可执行、可验证副作用。
