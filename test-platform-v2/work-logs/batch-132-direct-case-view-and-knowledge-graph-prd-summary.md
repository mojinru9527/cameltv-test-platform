# Batch 132 — 直属用例可查看 + 知识图谱计数/分域修复 PRD
> **Product (🟦)** | Date: 2026-08-10 | Status: Approved

mode: full（完整批次）
判定理由: 引入新行为（直属用例精确过滤可点击查看）、新接口参数（taxonomy 直属过滤）、知识图谱全量用例入图与分域隔离，属"新行为/新接口/数据口径"。

## 1. 问题陈述

用户在生产环境发现三个问题：

### 1.1 直属用例不可点击查看/编辑
直属用例是**真实用例库记录**（无子模块路径、直接归属父级），与普通用例一样需要可查看、可编辑（详情/编辑抽屉、批量操作等）。Batch 131 将"直属用例"实现为只读核算行（`selectable=false` / `role="note"`），只能看数字，不能点击进入这些用例。根因：列表接口 `taxonomy_module` 是"父级含所有后代"语义（`taxonomy_location_matches` 前缀匹配），没有"只看直属本级、无子模块路径"的精确过滤口径，前端因此无法把核算行变成可点击筛选。

### 1.2 知识图谱用例计数与用例库不一致
知识中心图谱/实体列表显示的用例约 526 条，而用例库全量为 7559（PRD 基线）。根因：
- 图谱 `test_case` 实体只来自"实体提取/自动建图/用例关联器"处理过的**用例子集**，未覆盖用例库全量；
- 前端图例数字取**当前已加载图谱节点**（`graphData.nodes.filter(...)`，接口默认 `limit=1000`）的过滤结果，不是权威总量；
- C125-3（生产导入 7559 基础用例 + 用例-模块关联）仍 Open，全量入图/关联能力未闭环。

### 1.3 项目知识与平台研发共用同一数据
知识中心图谱"项目知识 / 平台研发"两个 tab 展示同一份核心数据。根因：
- `graph/view` 分域过滤为 `实体.source 属于该域 OR source_id 为空（孤儿实体保留）`，孤儿实体在两个域都出现；
- `/graph/entities`、`/graph/entities/stats` 完全没有 `knowledge_domain` 过滤；
- 后端代码无任何 `knowledge_domain='platform'` 知识源接线（C126-1"实体来源补全"Open）。

## 3. 非目标与 C 条件
- **纳入 C125-3**：全量用例入图 + 用例-模块关联能力（脚本/接口 + 验证）。
- **纳入 C126-1**：知识实体来源补全（填充 `source_id`/`source_ref`，存量实体回填脚本）。
- **纳入 C126-4**：图谱大数据量渲染/计数口径（承接分层/聚合，至少保证 7000+ 用例不崩溃且计数权威）。
- **豁免**：C125-1/C125-2（需求设计稿与模块树生产导入）作为本批关联能力的前置，本批构建能力与脚本，生产执行单独排期；C95-1/2、C96-1、C99-1、C101-2/3、C106-2、C110-4、C111-1/4 及 Deferred 项与本批无关；C104-5（编辑工具落点）照常遵守。
- 不修改 7559 条生产用例数据、不重分类模块、不改变既有 taxonomy 层级语义（父级含后代语义保留，直属过滤为新增精确口径）。

## 4. 用户故事与验收标准
- As 测试平台用户, I want 点击"直属用例 (N)"查看并编辑这 N 条用例, so that 直属用例与普通用例一样可维护。
  - Given 展开的父节点有直属用例 / When 点击"直属用例 (N)" / Then 列表精确显示该父级直属用例（N 条），且不包含子模块用例。
  - Given 列表中的直属用例 / When 打开详情或编辑 / Then 走现有 CaseDrawer 查看/编辑链路，保存后列表与计数一致刷新。
  - Given 直属用例为 0 / Then 不显示核算行（沿用 Batch 131 规则）。
- As 知识中心用户, I want 图谱用例数与用例库一致, so that 我不再困惑"526 vs 7559"。
  - Given 用例库有 7559 条 / When 查看图谱/实体统计 / Then 用例计数使用与用例库一致的权威口径（全量 7559），并明确"已入库/全量"。
- As 知识中心用户, I want 项目知识与平台研发各自独立, so that 图谱不混源。
  - Given 切换"项目知识 / 平台研发" / Then 两 tab 数据不重复；同一实体只归属单一知识域。

## 5. 技术考量
- 直属过滤：`list_cases`/导出接口新增 `taxonomy_direct` 参数；`taxonomy_location_matches` 增加 direct_only 语义（module_path 精确相等；域级直属 = module_path 为空）；前端核算行变为可点击筛选，进入列表后走**现有查看/编辑链路**（CaseDrawer 详情、编辑、批量操作均正常，无需新编辑功能）；保留视觉区分（防误触，沿用 Batch 131 样式差异化）。
- 全量入图：新增用例全量入库脚本/接口，遍历项目 active 用例落为 `test_case` 实体（entity_key 去重），复用 `test_case_linker` 策略关联模块（tested_by）；同时按 C126-1 回填 `source_id`/`source_ref`（如以用例库为来源）。
- 计数口径：图例/统计改为权威口径（用例库全量 + 已入图数），不再用"已加载节点过滤数"冒充总量；大数据渲染承接 C126-4（分层/聚合/按需），7000+ 节点不崩溃。
- 分域隔离：`graph/view` 孤儿实体不再双域重复——按实体来源的 `knowledge_domain` 归属，无来源实体归入"未分类/项目"并仅在"全部"可见；`/graph/entities`、`/graph/entities/stats` 支持 `knowledge_domain` 过滤；平台域知识源创建/分类入口接线。
- 风险：全量 7000+ 实体渲染性能；存量实体 source 回填的幂等；直属过滤对既有父级筛选的兼容（新增参数不影响旧行为）。
