# Batch 146 — 蓝湖重试领取与预览页码修复 PRD-lite
> **Product (🟦)** | Date: 2026-08-11 | Status: Approved

mode: light
豁免理由: 修复既有蓝湖采集任务提交后的领取时效和截图预览越界展示；不引入新接口、新配置或新依赖。

## 问题陈述
1. 失败任务重试后只创建 `pending/queued` 记录；在轮询调度器未及时执行时，任务会长期停留在排队状态，计数均为零。
2. 截图预览保留旧任务的选中页码；页面数从 10 缩至 7 时，界面展示不可能的“第 10/7 页”，并把越界页误呈现为没有截图和 OCR。

## 成功指标
| 指标 | 目标 |
|---|---|
| 创建/重试任务领取时效 | 持久化成功后立即尝试领取；定时轮询仍为容错兜底 |
| 领取失败的可恢复性 | 立即唤醒失败不影响已持久化任务，后续轮询可继续领取 |
| 预览页码 | 任意初始页码和页面数量组合均显示在 `1..total` 内 |
| 回归 | 蓝湖 worker 相关后端测试、预览组件测试、类型检查与构建通过 |

## 非目标与 C 条件
- 不改变蓝湖页面发现、OCR、截图存储或下游导入逻辑；首次“页面发现失败”仍需由有效 Cookie、蓝湖服务可用性等外部条件决定。
- 不修复生产环境已有的 `app/main.py` 存量 `except: pass` 扫描项；其不在本批修改范围。
- 已阅读 `C-CONDITIONS.md`；其中开放项未直接覆盖本批的蓝湖队列领取/页码越界缺陷，故不纳入。

## 用户故事与验收标准
- Given 用户重试一个失败的蓝湖采集任务，When 新任务成功写入数据库，Then 后端立即尝试唤醒采集工作器，且任务仍可由原有轮询器恢复处理。
- Given 截图预览收到 7 页数据而初始索引为 9，When 弹窗显示，Then 当前页收敛为第 7/7 页，显示第 7 页数据而非空白越界页。
