# Batch 147 — Design Spec（审查方法规范：四视角对抗 · 双 AI 交叉验证）

> **Design (🎨)** | Date: 2026-08-11 | Status: 就绪

## 0. 技术体系确认

平台前端为 shadcn/ui + Radix + Tailwind + CVA；Token 走语义类（bg-muted / text-muted-foreground / border / variant）。UI 审查对照 `cameltv-ui-conventions` skill 的 Red Flags 逐条比对；不基于 Ant Design 假设。

## 1. 审查操作基线（每个模块强制）

| # | 操作 | 检查点 |
|---|------|--------|
| 1 | 列表加载 | 数据加载、分页条数、排序、空态、错误态 |
| 2 | 详情 | 字段完整性、展示格式、长文本截断、时间/状态可读性 |
| 3 | 筛选 | 级联筛选、搜索受筛选影响提示、防抖 |
| 4 | 创建 | 表单必填校验、默认值合理性、提交反馈、临时数据标记 |
| 5 | 编辑 | 回填正确性、保存反馈、并发/脏数据 |
| 6 | 删除 | 确认守卫、级联影响提示、删除后列表刷新 |
| 7 | 错误路径 | 必填为空、非法输入、接口失败、网络抖动 |
| 8 | 边界 | 超长文本、空数据、大数据量、深色模式 |
| 9 | 网络 | 重复请求计数、N+1、未缓存、轮询退避 |
| 10 | 可访问性 | ARIA 树泄漏、键盘可达、焦点管理、读屏 |

## 2. 双 AI 交叉验证协议

- Agent-A：UI 设计工程师 + 测试工程师视角
- Agent-B：架构师 + 甲方交付视角
- 两 AI **独立**走查全部模块（不同浏览器会话），各自产出 `findings-{agent}.jsonl`
- 交叉核对：合并 → 去重（同问题保留双证据）→ 冲突标注（两 AI 结论矛盾时标记 CONFLICT 并复测裁决）
- 146 复查：每条 146 发现标记 `FIXED / STILL / NEW / UNVERIFIABLE`

## 3. 五维评分

| 维度 | 说明 | 分值 |
|------|------|:---:|
| 功能完整 | CRUD/流程闭环 | 1–5 |
| 易用性 | 学习成本/操作步数/反馈 | 1–5 |
| 一致性 | 术语/状态/交互/视觉 | 1–5 |
| 性能 | 加载/请求量/响应 | 1–5 |
| 价值密度 | 对测试团队效率的实际贡献 | 1–5 |

## 4. 问题分级

| 级别 | 定义 |
|------|------|
| P0 | 阻断核心测试链路 / 数据可信度崩塌 / 严重安全 |
| P1 | 明显影响效率或可信度，跨模块 |
| P2 | 单模块明显缺陷 / 一致性 |
| P3 | 细节打磨 / 建议 |
