## 3. 用例-功能-接口-UI 自动化四者关联（用户点名重点，P0 根因）

### 3.1 现状数据链（实测）

```
需求文档(5) → AI 导入用例 476 → 功能用例 7845（域/模块标注）→ 测试计划 325（仅接口用例！）
                                              ↘ 接口用例 34（样本级）↗     ↓ 一键执行
UI 自动化 job(3) ← 无用例映射                  ← 执行 325/325 失败 → 执行历史(325) → 报告 0（手动可生成）
                                                                        ↓
                                                                  缺陷 0（创建即崩溃）+ 通知 0
```

### 3.2 断裂点

1. **计划只有接口用例**：325 条全为 OpenAPI 导入生成的接口用例，功能用例 7845 完全没有进计划——「功能用例→计划→执行」主链路空转（计划列表 0/0 更让编排不可见）。
2. **接口执行不回流功能用例**：接口用例执行结果不更新功能用例状态，功能用例 7845 永远「草稿」态。
3. **UI 自动化与用例库零关联**：3 个 job 的 spec 与用例库无映射字段，用例变更无法驱动回归范围；用例服务「UI 自动化」标签数量为 0。
4. **执行失败无下游动作**：325 失败 → 无缺陷（创建即崩溃）、无报告、无通知；失败分诊需手动触发 AI 且置信度 0%。
5. **数据集参数化断链**：数据集声称「参数化注入 API 用例」，但接口用例无创建/编辑入口、执行界面无数据集选择。

### 3.3 四者关联优化方案（落地建议）

1. **统一资产模型**：以用例服务为唯一主数据（功能/接口/UI 三类合一），接口资产与 UI spec 全部挂用例 ID；先修正 7879 vs 9429 口径差。
2. **数据流闭环**：需求/接口资产 →（一键生成）→ 用例 →（计划编排 UI，当前缺失）→ 执行（**强制绑定环境**）→ 结果回写用例通过率 → 失败自动建缺陷（预关联用例/执行）→ 报告定时生成 → 通知推送（渠道已具备）。
3. **复用与触发链**：UI 任务按用例生成 spec 并回写结果；接口用例接入数据集参数化（`${变量}`）；定时任务统一串联「API 回归/UI 回归/报告生成」；执行结果同步知识图谱与追溯。
4. **防误操作**：所有「执行」统一快速调试式安全确认（目标/环境/影响数量）；**无环境禁止执行**（325 失败的直接根因）。
