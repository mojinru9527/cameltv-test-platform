# Batch 60 测试平台全模块生产验收矩阵

## 1. 执行原则

- 基线：`d15ed2197e41bbcecfac733f059160a912373317`
- 本地入口：`http://localhost:5196`
- 每个功能点至少一条正面和一条负面用例。
- 写操作必须核对 UI、API、DB/后台任务和审计的一致性，并清理 `batch60-*` 数据。
- R1/R2/R3/M 数据等级见 `batch-60-real-data-manifest.md`。
- `失败` 必须关联缺陷 ID；`阻塞` 必须写缺失条件和解除条件；P0/P1 未执行不得放行。
- `A13` 单独检查前端、后端、Alembic 的不可变发布单元和 test→production 同 digest 晋级；production 基础设施未就绪时保持 `DEFERRED`，不得记为通过。
- `A14` 单独检查甲方可查看的 PC 使用快照；每个标记为 `PASS` 的功能都必须有 `1440×900` 真实成功状态截图和索引，失败/阻塞项不得用 Mock 或空壳截图代替。

## 2. 身份与项目矩阵

| 身份 | 项目关系 | 主要验证 |
| --- | --- | --- |
| 超级管理员 | 全局 | 全功能、跨项目总览、用户/角色/项目/系统设置 |
| 项目管理员 | 项目 A 成员 | 项目内管理；不得访问项目 B 实体 |
| 测试人员 | 项目 A 成员 | 常规业务操作；不得管理系统级资源 |
| 只读角色 | 项目 A 成员 | 只能查看授权资源；写入口应隐藏或禁用，API 必须拒绝 |
| 无项目用户 | 无成员关系 | 不得看到项目数据、数量、名称或子资源结构 |
| 未登录用户 | 无会话 | 只能访问登录和明确开放的健康接口 |

项目 A 与项目 B 都使用唯一 `batch60-` 实体。所有资源 ID 测试同时覆盖不存在 ID、同项目 ID、跨项目 ID。

## 5. 通用检查点

每个模块都必须按适用性覆盖：

- 必填、空/null、类型、长度、值域、枚举、默认值、特殊字符和组合参数。
- 新增重名、修改使用中数据、删除确认/级联/重建、重复点击和中途取消。
- 搜索、筛选、排序、分页、total/count、空结果、大于一页数据和稳定顺序。
- 无权限、低权限、跨项目、资源不存在、列表/详情/子资源/写操作一致拒绝。
- UI 提示、API envelope、DB/后台任务、计数和审计同时提交或回滚。
- 超时、断网、服务不可用、重试、并发、幂等、取消和恢复。
- 1440×900、768×1024、390×844；键盘、焦点、标签、可访问名称、对比度和减少动画。
- 每个用户动作只产生预期数量的有效请求；无 N+1、逐键无意请求或陈旧响应覆盖。
- 敏感字段加密、掩码和证据脱敏；不把真实密码、Token、Cookie、私钥或个人信息写入日志/截图。
- 每个验证通过的功能操作保存至少一张 `1440×900` PC 成功状态 PNG，并在 `batch-60-pc-usage-snapshot-index.md` 映射功能点、数据来源、动作、结果和证据；加载态、空壳、失败态和 Mock 不计为通过快照。

运维发布平台还必须专项覆盖：

- manifest 被篡改、制品 tag 相同但 digest 不同、test/prod digest 不一致时强制拒绝。
- 环境发布锁、数据库 migration lock、重复回调和幂等键，确保无并发迁移和重复部署。
- 备份不可读、Alembic 多 head、Secret 引用缺失、健康/Smoke/观察失败时进入正确失败状态。
- 应用回滚不自动执行数据库 downgrade；数据库恢复必须独立审批并验证 RPO/RTO。
- 开发、QA、运维、DBA、Secret 管理和审计角色的后端权限矩阵及审批失效条件。
- production 未登记基础设施时 API/UI 明确返回 `DEFERRED`，不得回退到 local/test 或生成成功记录。
