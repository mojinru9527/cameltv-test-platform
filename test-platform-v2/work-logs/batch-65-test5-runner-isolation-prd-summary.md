# Batch 65 — PRD Summary（Test5 验收执行器隔离 + 外部前置条件清单）

> **Product (🟦)** | Date: 2026-08-02 | Status: Approved

## 1. 问题陈述

1. **Test5 验收与 AI 的网络互斥**：Test5 验收需要 OpenVPN（内网）；AI（DeepSeek）依赖 vpn07 全局代理。
   两者在同一台 Windows 主机上是两个全局隧道，路由/DNS 互相干扰。batch-64 验证了
   `pull-filter` 路由分流 + hosts 的共存法，但依赖 Windows 路由表和 hosts 手工维护，脆弱且难自动化，
   用户明确判定「太麻烦」，需要更彻底的隔离。
2. **无正式执行器网络方案**：仓库中 `生产测试平台固定配置与双VPN切换验收手册.md` 的「双 VPN 切换」
   模式已暂停（2026-07-29），仓库没有替代的「网络域隔离」正式方案。
3. **外部前置条件无统一清单**：Test5/VPN、AI/蓝湖/OCR、SMTP/Webhook、真机、旧 PG 快照、DevOps 基础设施、
   DB/Redis/MQ 地址等验收前置条件分散在多个台账中，没有一份可勾选、可登记的交付清单
   （C63-2 要求「解除时先登记提供人/日期/授权范围」）。

## 3. 非目标（本次不做）

- **不实际搭建执行器**：本批是方案与文档批次；WSL/容器环境的搭建与验证为 batch-66+（需 Test5 授权窗口）。
- **不删除旧《双 VPN 切换手册》**：新方案取代其地位，但文件删除走独立审计批次。
- **不做 API-only UI**（C63-1 维持顺延，C64-4 跟踪）。

- **外部阻塞项继续豁免**（C63-2）：仅登记清单，不伪造验收证据。

## 4. 用户故事 + 验收标准

- As a 平台负责人，I want Test5 验收与 AI 的网络域彻底隔离，so that 本机 vpn07 常开不影响验收、验收不影响 AI。
  - 验收：Given 方案文档 / When 按文档执行器运行 Test5 验收 / Then 主机 AI 与执行器验收互不干扰（验证矩阵给出）。
- As a 运维/验收人员，I want 一份前置条件勾选清单，so that 我能逐项解锁验收且留下登记证据。
  - 验收：Given 清单 / When 逐项填写 / Then 每项有「提供物、存放位置、登记人/日期」字段且无明文 Secret。
- As a 项目成员，I want 执行器方案与 ADR-0015 一致，so that 后续运维平台发布时无需返工。
  - 验收：Given ADR-0017 / When 对照 ADR-0015 执行器契约 / Then 无冲突。

## 5. 技术考量

- 依赖：纯文档批次，无新依赖；不触碰 FastAPI/React。
- 已知风险：WSL2 默认内核是否支持 tun 设备、Clash TUN 与 WSL2 NAT 的交互、OpenVPN 授权（子网掩码）
  需在 batch-66 实测；方案文档给出备选路径（容器/VM）与回退。
- 待用户提供：Test5 内网网段/DNS、执行器宿主选择（WSL2 发行版 or Docker）、验收授权窗口。
