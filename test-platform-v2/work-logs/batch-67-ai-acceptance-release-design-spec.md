# Batch 67 — Design Spec（前置条件登记与凭据槽位规范）

> **Design (🎨)** | Date: 2026-08-02 | Status: 已就绪（非 UI 批次）

## 0. 技术体系确认
本批无前端/组件改动；交付物为文档与本地配置登记。设计对象 = 清单登记字段与 .env 凭据槽位的一致性契约。

## 1. 登记字段规范（C63-2）

| 字段 | 规则 | 示例 |
|------|------|------|
| 状态 | ✅已提供 / ⏳待提供 / 🔒无法提供 / ❌已填但失效 | ⏳ |
| 提供人 | 实际提供者 | 用户 |
| 日期 | YYYY-MM-DD | 2026-08-02 |
| 授权范围 | 用途/权限边界 | 只读、测试额度 |
| 证据位置 | 非秘密路径或校验证据 | `backend/.env`（值不回显） |

## 2. .env 凭据槽位契约

| 槽位 | 位置 | 校验方式 |
|------|------|---------|
| AI_API_KEY | backend/.env | 调用 `{AI_API_BASE_URL}/models` → 200 |
| LANHU_USERNAME/PASSWORD | backend/.env + lanhu-mcp/.env | 非空、无占位符 |
| LANHU_COOKIE | lanhu-mcp/.env（部署侧 deploy/.env） | 非空；运行时 Cookie 有效（C67-3） |
| LANHU_OCR_PROVIDER | backend/.env = local | 无需云凭据 |

## 3. 状态设计（四态）

| 清单项 | 已填待实测 | 未填 | 失效/异常 | 未启用 |
|--------|-----------|------|-----------|--------|
| 2.1 AI Key | ⏳ 待实测 | ⬜ 未填 | 401 → ⏳ 待换新 | AI_ENABLED=false 时豁免 |
| 2.2 蓝湖 | Cookie 待验 | ⬜ 未填 | Cookie 过期 → 重新获取 | lanhu 链路未用时可豁免 |
| 6.1 服务器 | 部署中 | ⬜ 未提供 | 构建失败 → 修复后重试 | 不发布时可豁免 |

## 4. 设计 QA 走查发现

- B67-D1（P3）：清单 2.1 曾为「已提供」但缺实测证据 → 本批改为 ⏳ 并附 401 证据（禁止假解锁）。
- B67-D2（P3）：6.1 行无登记字段 → 补「待提供 + 解锁步骤引用」。

## 5. 设计签核
结论：有条件通过（非 UI 批次；2.1/6.1 按真实状态登记即可签核）。
