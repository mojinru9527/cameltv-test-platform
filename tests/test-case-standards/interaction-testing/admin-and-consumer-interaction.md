# 管理后台交互与 C 端关联覆盖规范

## 1. 后台交互的特殊性

管理后台的用户通常是运营、编辑、审核、发布、客服、财务、管理员或租户成员。后台交互测试不能只验证按钮 CRUD，还要验证角色任务效率、批量数据操作、状态管理、错误预防、审计和下游影响。

## 2. 后台页面通用交互清单

### 工作台/仪表盘
- 指标口径、统计时间范围、刷新、空数据、权限数据范围。
- 卡片/图表点击后的过滤条件和跳转上下文。
- 数据加载失败与部分数据成功的呈现。

### 列表/表格
- 首次加载、骨架/Loading、空列表、无搜索结果、接口失败。
- 搜索输入时机、回车/清空、组合筛选、筛选条件回显。
- 排序字段、正反序、默认排序、服务端排序一致性。
- 分页边界、切换每页数量、翻页后筛选条件和选择状态。
- 列宽/固定列/横向滚动/溢出/悬浮提示/多选框。
- 行点击与行内按钮的事件区分，避免点按钮触发整行跳转。
- 选择跨页语义明确；批量操作前显示对象数量和影响范围。
- 部分失败时逐条列出成功/失败，不以“全部成功”掩盖部分失败。
- 并发更新后旧数据提示、刷新方式和冲突处理。

### 表单/编辑器
- 必填、格式、长度、边界、默认值、字段依赖、动态显隐和联动。
- 实时校验/失焦校验/提交校验的触发规则一致且反馈位置清晰。
- 错误聚焦到首个错误字段；多个错误可定位。
- 取消/关闭/切换路由时未保存提醒；自动保存状态和失败恢复。
- 新建、编辑、复制、只读、禁用模式的视觉与行为区分。
- 重复提交、防抖、接口超时、并发编辑和版本冲突。

### 弹窗/抽屉/上下文菜单
- 打开来源、标题/对象信息、默认焦点、关闭按钮、ESC/系统返回、点击遮罩规则。
- 关闭后焦点回到触发元素；滚动锁定正确；多层弹窗层级与关闭顺序正确。
- 危险操作显示对象、数量、不可逆后果和确认动作。

### 上传/导入/导出
- 文件选择/拖拽/多文件/重复文件/格式与大小错误。
- 上传进度、取消、失败、重试、断网恢复、重复提交。
- 资源处理完成与上传完成区分；预览准确。
- 导入模板、字段映射、错误行、重复数据、部分成功、回滚。
- 导出权限、筛选范围、敏感字段、文件完整性与超大数据处理。

### 审核/发布/运营配置
- 状态合法迁移、非法迁移、审核人与提交人分离规则、驳回原因。
- 定时发布、时区、夏令时（适用时）、开始/结束边界、过期、撤回、回滚。
- 多运营位冲突、优先级、定向、排序、设备差异和灰度规则。
- 预览内容必须区分草稿预览和真实 C 端线上内容。
- 权限撤销、审核状态变更、发布任务失败必须有真实反馈。

## 3. 必须区分后台操作者角色与 C 端用户身份

它们通常是两套独立的身份/授权域，不能默认一一对应：

| 身份域 | 常见主体 | 授权对象 | 典型验证点 |
|---|---|---|---|
| 后台操作者 | 运营、编辑、审核、发布、客服、管理员、租户成员 | 后台菜单、管理动作、管理数据范围、审核/发布状态 | 是否能查看/编辑/审核/发布指定对象，能否越权调用接口 |
| C 端用户 | 游客、注册用户、会员、付费用户、地区/年龄/设备受限用户 | 内容可见性、功能入口、购买权益、播放/下载/提交能力 | 是否看到正确内容，能否执行对应动作，权益变化是否同步 |
| 系统/自动化主体 | 定时任务、发布服务、内容同步服务、设备服务账号 | 自动发布、过期下架、缓存刷新、消息消费 | 是否仅在允许的状态和范围内执行，是否可追踪、可重试、幂等 |

只有产品设计明确存在身份映射、代理操作、会员权益或租户关系时，才测试两套身份之间的关联。需要验证：后台操作者调整某个权益/内容规则后，哪些 C 端用户受到影响；调整何时生效；是否需要重新登录/刷新；是否存在缓存延迟；是否影响已经打开的页面/播放/下载任务。

## 4. 后台角色模型

角色测试按五维建模：

`主体/角色 × 资源对象 × 操作动作 × 数据范围 × 对象状态`

动作至少考虑：查看、创建、编辑、删除、导入、导出、提交审核、审核、发布、下架、回滚、配置、授权、审计。只选择系统真实存在的动作。

每个高风险权限至少从以下入口验证：
1. 菜单/按钮可见性；
2. 直接 URL/路由访问；
3. 前端请求/API 直接调用；
4. 数据范围与对象 ID 替换；
5. 角色/权限撤销后的现有会话；
6. 多角色叠加或互斥角色的实际策略。

## 4. 后台到 C 端的数据/交互映射

对每种后台管理对象建立映射表：

| 字段 | 说明 |
|---|---|
| admin_module/action | 后台模块和操作 |
| business_object_id | 内容/配置/资源唯一标识 |
| actor_role | 执行后台操作的角色 |
| object_state/version | 操作前后状态及版本 |
| publication_rule | 审核、发布、定时、下架规则 |
| consumer_surface | C 端页面/入口/设备 |
| consumer_persona | 游客、登录用户、会员、地区/语言等适用对象 |
| visible_oracle | C 端应看到的内容、状态、入口或跳转 |
| cache_rule | API/浏览器/CDN/本地缓存生效约定 |
| rollback_rule | 撤回/恢复/旧版本规则 |
| evidence | 管理后台、API、事件、资源、C 端截图/日志证据 |

至少检查：创建→预览→审核→发布→C 端展示→用户操作→变更/下架→C 端同步。按风险补充失败、权限不足、重复操作、缓存未刷新、旧版本、定时边界和并发编辑。

必须把这些结果区分开：后台保存成功 ≠ 文件处理完成 ≠ 审核通过 ≠ 发布任务完成 ≠ C端 API 可读 ≠ CDN 已更新 ≠ 浏览器实际展示。

## 5. 后台功能模块的快速首轮覆盖

按实际项目模块裁剪：
- 账号/角色/权限：登录、退出、过期、菜单/按钮/路由/API/数据范围。
- 内容管理：新增、编辑、保存、草稿、预览、版本、删除、恢复、搜索筛选。
- 文件/媒体：上传、校验、进度、取消、重试、预览、替换、删除、引用关系。
- Banner/广告/推荐位：素材、尺寸、位置、顺序、定向、跳转、投放时段、审核发布、撤回。
- 文档/帮助中心：分类、解析、预览、下载、版本、权限、过期和下架。
- 审核工作流：待办、通过、驳回、撤回、转交、多人审核、重复审批。
- 发布/配置：立即/定时、灰度、缓存、回滚、并发、版本兼容。
- 用户/会员/商品/支付配置：展示条件、权益和真实交易状态同步。
- 系统配置：开关、排序、默认值、优先级、配置回滚、跨环境隔离。
- 日志审计：操作者、对象、修改前后、结果、时间、关联 Trace/任务 ID。
