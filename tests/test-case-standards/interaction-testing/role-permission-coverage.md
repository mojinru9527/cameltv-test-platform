# 角色与权限交互覆盖方法

## 1. 为什么不能只测角色菜单

权限不只是“菜单是否展示”。应拆成页面可见性、控件可用性、路由访问、服务端动作授权、数据范围、业务状态限制、敏感字段可见性和会话生效时机。

## 2. 权限矩阵

为项目实际存在的角色与动作建立矩阵：

| 角色 | 资源范围 | 查看 | 新建 | 编辑 | 删除 | 审核 | 发布 | 导出 | 管理权限 |
|---|---|---|---|---|---|---|---|---|---|
| 管理员 | 全部/按项目实际定义 | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N |
| 编辑 | 所属内容 | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N |
| 审核员 | 待审核范围 | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N |
| 发布员 | 已审核范围 | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N |
| 只读 | 授权数据范围 | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N |
| 无权限用户 | 无/有限范围 | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N | Y/N |

上表仅为模板，不能把示例角色或 Y/N 当成项目事实。按实际 RBAC/ABAC 策略填写。

## 3. 每个高风险动作的权限层级

- L1 导航层：菜单、导航入口是否显示。
- L2 控件层：按钮、操作菜单、批量选择是否显示/启用。
- L3 路由层：直接输入受限路由/深链接是否被拦截。
- L4 服务层：直接 API 调用是否被服务端授权拒绝。
- L5 对象层：替换资源 ID、租户 ID、项目 ID 后是否越权访问/修改。
- L6 状态层：角色有动作权限但当前对象状态不允许时，是否阻止非法转换。
- L7 会话层：权限变更/撤销后，当前 Token、刷新 Token、已打开页面何时生效。
- L8 审计层：授权与拒绝行为是否留下符合策略的审计记录。

## 4. 快速首轮抽样策略

- 至少选择最高权限角色、最小权限角色、纯只读角色、无权限角色，以及业务上相邻的编辑/审核/发布角色（仅当系统实际存在）。
- 每个关键资源选取本人/本部门/其他部门/其他租户（若有）对象。
- 每个关键状态选取允许和禁止的动作组合。
- 对新增、编辑、删除、审核、发布、导出、权限管理等不可逆或敏感动作优先全链路验证。
- 对低风险权限组合采用边界角色和 Pairwise，避免无差别全排列。

## 5. 易漏场景

- UI 已隐藏操作，但 API 未限制。
- 直接访问 URL 仍可查看/编辑。
- 列表按权限过滤，但详情接口没有过滤。
- 通过批量接口访问范围外的对象。
- 只校验按钮权限，没有校验对象状态。
- 用户权限被撤销，旧会话仍可发布/导出。
- 同一用户具有互相冲突的多个角色，权限合并规则错误。
- 前端缓存旧权限导致显示与服务端不同步。
- 导出接口泄漏列表页面未显示的敏感字段。
- 权限拒绝后页面仍乐观更新，造成“看起来成功”。
