# 功能测试输出用例要求（重新整理版）

> 来源：用户提供的 7 份功能用例文档——
> 功能测试用例规范（飞书）、功能测试检查点【辅助】（飞书）、测试的具体体现、测试用例标准、
> 测试用例具体用法、界面测试的方法要点、功能测试用例用途。
> 本文件为**功能用例基座的权威输出要求**：生成/设计功能用例时必须按此框架逐类覆盖。
> 配套速查：`.agents/skills/test-case-design/functional-checklist.md`。

## 一、设计前置（来源：功能测试用例规范 / 功能测试用例用途）

### 1. 用例用途
- 指导测试工作有序进行，使实施测试的数据有据可依。
- 确保所实现的功能与客户预期的需求相符合。
- 完善软件不同版本之间的重复性测试。
- 跟踪测试进度，确定测试重点。
- 评估测试结果的度量标准。
- 增强软件的可信任度。
- 分析缺陷的标准。

### 2. 设计依据
- 需求说明书。
- 产品测试需求功能点。
- 所属行业的业务知识掌握程度。
- 测试工程师本人的理解程度（个人经验）。

### 3. 编写用例原则（六性）
- **系统性**：对系统业务流程完整说明整个系统的业务需求、子系统组成及其关系；对模块业务流程说明子系统内部功能、重点功能及其关系。
- **连贯性**：说明子系统之间如何连接（接口/页面链接是否正确）；模块内部同级/上下级如何构成子系统，功能接口是否连贯。
- **全面性**：尽可能覆盖各种路径、各个业务点，并考虑跨年/跨月数据及大数据量并发测试准备。
- **正确性**：输入数据与测试文档一致，预期结果与测试数据发生的业务吻合。
- **符合正常业务规则**：测试数据符合用户实际业务流程，兼顾业务变化与行业规范（人名/地名/电话等符合命名惯例，不与知名人物雷同）。
- **可操作性**：写清楚操作步骤，以及不同步骤对应的测试结果。

### 4. 编写用例标准
- 统一模板 + 约定模板使用方法；制定用例编写手册（编号规则/编写方法/编写内容/维护）。
- 步骤明确，输入输出要素清晰，与需求和缺陷对应。
- 严格依据需求规格说明书及测试需求功能分析点，**覆盖全部需求功能点**。
- 注重可复用性，减少相似系统的测试设计工作量。

### 5. 用例内容字段（18 项，PingCode 模板）
用例编号、模块名称、用例标题、维护人、用例类型、重要程度（P0/P1/P2）、测试类型（手动/自动）、
关联项目（故事编号）、前提条件、操作步骤（须明确输入数据）、预期结果（程序表现+验证手段）、备注、
执行结果（通过/失败/阻塞）、实际结果、缺陷、执行人、结果附件（截图等）。

### 6. 用例设计步骤
1. 测试需求分析：从需求文档拆出全部功能点，整理成测试需求。
2. 业务流程分析：熟悉业务，梳理主流程/备选流程/数据流向/关键判断条件/非必要条件（可画流程图/思维图）。
3. 测试用例设计：功能测试、边界测试、异常测试、性能测试、压力测试等，尽量考虑边界与异常。
4. 测试用例评审：设计者发起，测试负责人、开发、其他相关测试人员参加。
5. 测试用例完善：根据评审修改完善。

### 7. 用例级别划分
- **P0（优先执行）**：关键路径、最常用功能、基本流输入、界面数据有效性校验；全过 → 功能稳定。
- **P1（次级执行）**：不常用功能、异常流输入、边界值、异常数据；全过 → 可发布。
- **P2（最后执行）**：GUI、界面显示、错误信息提示一致性、可用性、压力性能等。

### 8. 用例的维护
- 删除过时的测试用例（需求变更后不再符合需求的内容，置废弃并备注）。
- 修改的测试用例（需求变更同步修改并备注；**用例执行超 2/3 后原则上不再变更/新增需求**）。
- 删除冗余的测试用例（相同输入/输出的多条只保留一条）。
- 增添新的测试用例（新增功能/评审发现缺漏/系统出现 BUG 但无对应用例时，按设计标准增添，插到对应功能模块最下方并备注）。

## 二、输出结构要求（来源：测试用例具体用法 / 功能测试用例规范）

### 1. 正/负用例成对（强制）
**每个测试需求至少编制两个测试用例**：
- 一条正面用例：证明该需求已满足（基本流/正常数据）。
- 一条负面用例：反映无法接受、反常或意外的条件或数据，论证只有在所需条件下才满足需求（备选流/异常流）。

### 2. 三事件模型
- **基本事件**：参照用例规约/设计规格，按关联功能+路径分析设计，**覆盖率 100%**。
- **备选事件**：从基本流某点分叉后重新加入基本流；覆盖各种分支条件。
- **异常事件**：错误/意外数据与条件；重点验证「报错 + 报错文字正确」。

### 3. 按功能/路径混合模式设置用例
- 简单/孤立功能：按功能遍历每一功能。
- 复杂操作模块（功能相互影响、环环相扣）：用路径分析法避免漏测；子系统间关联仍靠传统功能法。

### 4. 输出模板
- 功能用例表格模板：`用例编号 | 模块 | 用例标题 | 重要程度 | 前提条件 | 操作步骤 | 预期结果 | 备注`（设计交付核心列）。
- 复杂业务流程用**场景矩阵**：行=用例，列=条件 + 预期结果，用 V（有效/基本流）/ I（无效/备选流）/ n/a 标记，空白即缺用例。

## 三、覆盖维度（来源：测试的具体体现 / 功能测试检查点【辅助】/ 测试用例标准 / 界面测试的方法要点）

### 1. 功能性
- **功能点缺失/不一致**：实现功能少于需求；与需规不能一一对应；实现需求外功能但有误；title 与界面名不一致；弹窗名与按钮不一致。
- **功能实现错误**：计算/逻辑公式结果不符；开始时间>结束时间无提示；开始=结束应正常返回；导出 Excel 乱码/表头字段与页面不一致；必填项未标注；二次查询未按条件展示；必填项不填能保存成功；上传后无成功提示；导入格式不符模板应提示且失败；数据缺少单位。
- **系统稳定性**：异常退出、崩溃、停止服务、无法运行。

### 2. 常见功能模块检查点（按被测模块加载）
1. **安装**：缺省/指定目录、中途退出未装成功、对其它软件影响、裸机安装、磁盘空间判断、版权版本信息、重复/覆盖/升级安装、注册码/加密狗。
2. **配置**：多操作系统、最低配置、数据源错误提示、多数据库。
3. **卸载**：注册表/目录清除、共享文件、用户文档保留、中途退出、重启提示、选择性卸载、意外情况（掉电）。
4. **运行与关闭**：程序冲突、多实例、任务栏提示、未保存提示、资源释放。
5. **服务程序**：启动数量限制、长时间运行、异常自动恢复、关闭确认、兼容性。
6. **系统管理/参数设置**：参数应用、错误参数容错、关联模块影响、默认参数。
7. **用户/权限管理**：权限赋予后验证、删改在线用户权限、变更身份登录、删含用户的组/角色、不同权限范围、空用户名/口令组合、长用户名口令、删改管理员、用户改自身权限、权限交叉、删后重加是否保留权限。
8. **系统登录**：合法登录、用户名口令错误/漏填、多次非法登录次数限制、已登录账号再登、禁用账号、删改后原账号登录、空账号重复点确定/取消。
9. **注销**：原/新模块、中止注销返回、原/新用户、错误账号注销。
10. **修改口令**：正常、原口令错误/两次不一致、改后原口令是否可登录、能否改他人口令。
11. **右键功能**：与菜单功能一致、能正确实现、热键相同。
12. **记录列表**：重复/空白记录、改后不保存、删改使用中信息、级联删除、删除提示、缺省系统信息删改、列表及时刷新。
13. **统计/查询**：非法时间范围、与或非多条件、条件逻辑混乱、多表/单表、分类/精确/无条件/组合查询、默认条件、跨日/月/季/年统计、不同权限、终止大数据操作、按钮双击、查询结果可否修改。
14. **文件操作**：保存（缺省/指定位置、长文件名/特殊字符、其它扩展名、大小写、介质满）；打开（上次内容、非默认扩展名、被其它程序打开）；打印（格式/预览/字体/中断/本地网络）；导入导出（格式不符、有效文件、路径、客户端/服务器、不同格式）；检入检出。
15. **界面对象功能**：工具条、下拉列表、窗口、文本框（必填/长度/禁止字符/特殊字符组合）、口令域、时间域（年超 4 位、月 0 或 >12、日越界、负数、闰年闰月、格式/范围/服务器时间）、货币域（负/零/特大/小数/非数值）、身份证（15/18 位、非法年月日、由号算年龄、x）、电话号码（特殊号码/长度/汉字）、图表曲线（关键点对比公式）、列表（滚动条/排序/直接输入）。
16. **备份与恢复**：备份后恢复正确性、不同介质/介质满、终止（掉电/断网）、有/无操作时、部分/全部、权限限制。
17. **系统日志**：正确记录、清空、导出、超容量处理。

### 3. 易用性
- **响应慢**：确认时间过长、页面加载慢、整体卡顿。
- **界面**：展示不美观、文本/字符显示不全且无悬浮提示、超长字符出框、排版凌乱、边框对齐、遮挡、按钮/图标位置不统一、风格不一致、不可改项置灰、控件统一、按钮名不折行、避免横向滚动条、菜单不超三级。
- **可终止性**：缺取消/回退。
- **易操作性**：确认在左取消在右、时间框可清空、新增后对话框自动关闭、悬停高亮手型、快捷键不冲突、删除有提示、菜单打开后自动关闭。
- **输入校验**：手机/身份证/URL/邮箱格式、输入范围合理性、长度限制提示、唯一性校验（人名/电话/编号/身份证）、空值是否必填、特殊字符 @#￥% 禁止、表情符号、超长字符提示、NULL 处理、空格限制。
- **易理解性**：输入框提示正确，避免「系统内部错误/请联系管理员」类无指导信息。
- **默认值**：常用数据自动填默认值。

### 4. 界面测试要点（来源：界面测试的方法要点）
- **标题栏**：标题文字描述正确；最大化/最小化/关闭按钮按窗口特性显示或置灰。
- **文字**：描述与功能一致、无错别字；用语一致性（菜单/按钮/Label/ToolTip/窗口标题统一用词）；全面检查所有文字资源。
- **控件**：并排控件左对齐、同行横向对齐、所属关系缩进；不能操作的控件置灰引导；控件状态与功能匹配。
- 其余按 `界面测试的方法要点.md` 逐条执行（含菜单、快捷键、焦点、Tab 顺序、字体、滚动条、对话框、模态等）。

### 5. 其他质量维度
- **兼容性**：浏览器（IE/Chrome/Firefox/Safari 高低版本）、分辨率自适应、操作系统（Win7/Win10、Android/iOS）、其它软件（杀毒）、接口。
- **可维护性**：角色划分、错误日志/运行日志/告警日志/登录日志、日志开关、系统重启难易。
- **可靠性**：稳定性（意外退出/时好时坏）、容错性（错误输入不崩溃不丢数据）、容量（超大附件）。
- **可移植性**：适应性、易安装/卸载、易替换（在线/自动升级、覆盖安装、数据复用）、依从性。
- **文档**：完整性、正确性（格式/语法/拼写）、一致性、易理解性、易浏览性。

### 6. 性能 / 压力 / 容错 / 并发（按需）
- **性能点**：查询、保存、统计、刷新、显示、传输、响应、下载；关注小数据量与累积到一定量两种场景。
- **极限压力**：大数据文件接收/恢复/导入导出/录入/计算时间、多客户端同时提交、大数据量查询统计。
- **容错**：断网、断电、死机、服务器 down 时客户端处理。
- **并发**：登录并发、提交并发、数据库读写并发。

### 7. 易出错点（测试必查）
- 新建/修改为已存在内容是否提示、修改使用中数据。
- 删除：确认提示、实际校验、删使用中数据、级联数据、重用已删数据。
- 提示信息正确性（尤其改口令等重要操作，用其它方法验证真成功/失败）。
- 硬盘空间已满（存储/备份/生成/拷贝文件）。
- 修改系统时间对时间相关业务的影响。
- 慢按钮连续点击/中途取消再继续。
- 凡支持并发的功能必做并发测试。
- 版权声明/logo/图标正确性。
- 系统初始化与默认设置。

## 四、深度用例补充层（强制，基座基础用例之上叠加）

> 模式来源：Batch 122 体育全模块深度用例（507 条 SP-，覆盖 用户端 4 入口 + 运营后台/konfi + 接口）。
> 基础用例（基座按第一~三章结构生成）覆盖「功能点正/负」后，**必须**再叠加深度用例，
> 从单个功能、关联功能、全生命周期状态三个层面补足，禁止只出孤立的单点用例。

### 1. 状态机覆盖
- 列出被测对象的**全生命周期状态**（如赛事：未开始/进行中/已结束；预测活动：未开始/预测中/进行中但预测结束/待开奖/已开奖/已关闭/已取消退款）。
- 对**每个状态 × 每个可操作行为**至少一条用例，明确状态切换后的 UI 与数据表现。
- 特殊组合必须覆盖：如「比赛进行中但预测已结束」「比赛未开始但预测已关闭」。

### 2. 用户视角
- **登录态矩阵**：未登录 / 已登录（普通用户）/ 不同角色（运营、管理员）对同一功能的行为差异。
- **资产前置**：余额充足 / 不足 / 临界值 / 为 0 时的操作结果。
- **正常参与状态定义**：什么算「参与成功」（扣减、记录、弹窗、状态），并显式校验。

### 3. 闭环验证
- 跨功能串联一条完整业务闭环：操作 → 记录生成 → 状态流转 → 结算/发放 → 流水/明细可查。
- 例：下注 → 预测记录新增 → 开奖 → 奖励自动发放 → 我的资产-银钻明细可查；数值 = 投入 × 赔率（按需求规则取整）。
- 闭环用例必须是**可执行的多步骤场景**，不能拆成孤立单点。

### 4. 关联功能校验
- 主功能与相邻功能的联动：如 Pick ↔ Prediction History ↔ Predict More Matches ↔ 我的资产/钱包 ↔ 玩法说明。
- 每涉及一个关联入口（按钮/链接/Tab）都必须有对应用例校验其跳转、展示与回写。

### 5. 异常与边界
- 非正常状态操作拦截（非预测中点击预测 → 提示并拦截）。
- 活动取消退款、失败不返还、重复操作、三选项同时下注、超限拦截。
- 数值边界：单场/单日上限边界值（等于/超过/临界）。
- 空态：无数据、无预测、无记录时的展示。

### 6. UI / 交互细节
- 玩法说明（?）、实时数据变化（赔率 highlight 3s）、成功/失败标识（WIN 标记）、提示语文案、弹窗字段与按钮。

### 7. 权限与端差异
- **用户端 4 入口**：安卓/iOS 客户端、PC-web、移动端-web 各自覆盖；安卓/iOS 与移动端-web 同套样式但功能略有差异、PC-web 完全功能版，需分别标注并校验差异点。
- **运营后台（konfi/运营后台）**：后台管理功能单独覆盖（配置、审核、上下架、数据维护等）。
- 未登录/越权/权限不足的行为拦截。
