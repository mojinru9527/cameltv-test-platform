# 接口测试输出用例要求（重新整理版）

> 来源：`接口测试.xmind`（用户重新整理的接口用例输出要求）。本文件为**接口用例基座的权威输出要求**，
> 生成/设计接口用例时必须按此框架逐类覆盖。配套速查：`.agents/skills/test-case-design/api-checklist.md`。

## 一、业务功能测试

### 1. 冒烟测试
- **原则**：以业务中某一入参为起点，可以完成接口实现的功能，并可以通过结果进行验证或者其他接口得到验证。

### 2. 场景测试
- **原则**：从业务逻辑层面考虑，通过几个接口的连续调用，达到状态转变的效果，并通过返回结果或者其他接口得到验证。
- 输出：场景串联用例（多接口连续调用 + 状态转变断言）。

## 二、健壮性测试

### 1. 入参合法覆盖测试
- **原则**：在符合接口文档要求的前提下，通过等价类划分和边界值联合使用，进行入参设置。
- 具体包含：
  - **参数的取值范围覆盖**：范围小（≤10）建议全量取值覆盖；范围大建议等价类划分 + 边界值取值覆盖。
  - **组合配置可选参数合法入参**：参数类型符合接口要求；参数符合业务逻辑、真实存在。
  - **覆盖所有必选参数合法入参**：参数符合业务逻辑、真实存在；参数类型符合接口要求。

### 2. 入参非法覆盖测试
- **原则**：在不符合接口文档要求的前提下，通过等价类划分和边界值联合使用，进行入参设置。
- 具体包含：
  - **业务边界取值覆盖**：超长度限制取值入参（期望服务器处理）；特殊字符取值入参（期望服务器处理）。
  - **覆盖所有必选参数非法入参**：参数类型非法；参数字段缺少；参数字段值缺少；增加不存在的参数；参数设置为特殊字符；参数设置为 -1、0、null。

## 三、安全测试

### 1. 敏感信息是否加密
- 是否使用 https，保证通信过程加密。
- 是否包含请求签名，防止参数被篡改。
- 是否包含身份确认机制，防止恶意获取他人信息。
- 确认 APP、小程序等是否使用 SSL pinning（防抓包机制）。
- 所有的请求和响应都进行加密操作。

### 2. SQL 注入
- 永远不要信任用户的输入，对用户的输入进行校验（正则表达式 / 限制长度；对单引号双引号转换等）。
- 永远不要使用动态拼装 SQL，使用参数化 SQL 或存储过程。
- 永远不要使用管理员权限的数据库链接，为每个应用使用权限有限的数据库连接。
- 不要把机密信息直接存放，加密或 hash 掉密码和敏感信息。
- 应用异常信息给出尽可能少的提示，用自定义错误信息包装原始错误。

### 3. XSS 攻击（暂不进行）
- 原理：恶意往 Web 页面插入 Script 代码，浏览时执行。
- 反射型 / 存储型 / DOM 型 XSS（当前标记为暂不进行，保留检查项说明）。

### 4. 越权访问
- 接口权限最小化；每次调用将 token 作为 API 参数校验；校验用户请求合法性；
- 静态 API 密钥强加密后传输；参数含时间戳和随机数防重放；无密钥时通过访问权限控制。

### 5. CSRF 请求伪造
- 校验来源/凭证机制，防止跨站请求伪造。

## 四、性能测试

- 响应时间、吞吐量、并发数、服务器资源使用率（CPU / IO / 内存 / Network）。

## 五、数据测试

### 1. 基本测试
- 熟悉数据库字段类型、含义。
- 执行操作后，确认数据库正常入库。
- 依照需求验证字段长度、数据类型、长度定义是否正确。

### 2. 专业化
- 数据库表接口是否合理；数据结构（类型/长度）定义是否正确，且与输入页面数据长度类型一致。
- 表与表之间关系是否正确，主外键是否合理；索引创建是否合理；存储过程功能是否完整。
- 输入能否正确接收、能否输出正确结果；能否正确插入、更新、删除。
- 数据库操作权限定义是否正确；能否正确处理并发操作。
- 表级、列级完整性约束条件是否满足；数据库处理能力、可靠性、可维护性、性能是否满足要求。
