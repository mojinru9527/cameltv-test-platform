# Batch 47 测试平台需求服务生产级验收用例

> 执行环境：`http://127.0.0.1:5173/`；隔离后端 `127.0.0.1:8006`；隔离 SQLite 数据库。
> 执行版本：`origin/main@a68e492`，分支 `feature/batch-47-requirement-service-acceptance`。
> 设计方法：需求/历史验收对照、场景法、等价类、边界值、错误推测、状态迁移、事务与权限矩阵。
> 结果定义：通过 / 失败 / 阻塞（环境或依赖不具备）/ 未执行（需专项环境）。

## 1. 功能清单与主流程

| 业务域 | 正常主流程 | 必须覆盖的异常/边界 |
| --- | --- | --- |
| 文档管理 | 登录 → 上传 → 解析 → 列表/预览 → 删除 | 非法格式、空/损坏文件、20 MB 边界、101+ 分页、跨项目 |
| 功能拆分 | 上传 → AI 拆分 → 人工确认/驳回 → 恢复审查 | AI 不可用、旧结果读取失败、版本继承、重复确认 |
| 用例生成 | 已确认拆分 → 基于拆分生成 → 预览/编辑 | 直生成、重试、非法 AI 数据、并发生成 |
| 用例审查/导入 | 审查 → 批准/驳回/编辑 → 选择导入 | 越界索引、重复/并发导入、中途失败全回滚 |
| 需求模块 | 证据包 → 模块树 → 交互/导航/附件 → 用例关联 | 三层树、懒加载、跨项目、重复提取、非法关联 |
| 追溯与集成 | 需求 → API 资产/用例/计划/执行/缺陷覆盖 | 匹配持久化、真实覆盖率、审计日志 |
| 生产质量 | 桌面/移动端、键盘、迁移、依赖安全、全量回归 | 390 px、100+ 数据、旧库升级、依赖漏洞 |

## 2. 放行标准

- P0、P1 用例全部通过；不得有致命/严重且未关闭的缺陷。
- 上传、导入、审计必须满足“业务数据与状态/计数同时成功或同时回滚”。
- 所有读写 API 都必须校验项目归属和权限，不得跨项目泄露。
- 真实旧版本数据库升级到 head 后 `alembic check` 无漂移。
- 前端类型检查、构建、单元测试与后端 F821、专项/全量 Pytest 全绿且无新增失败。
- 需求页在 390 px 移动端可完整操作，关键鼠标操作具备键盘等价操作。
- 生产依赖不得残留未评估的高危/严重漏洞。
- 外部 AI、蓝湖和 PostgreSQL 场景如果环境不具备，版本不得因此宣称“生产验收通过”。
