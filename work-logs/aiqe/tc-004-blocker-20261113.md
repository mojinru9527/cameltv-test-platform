# Batch 343（M9-4：TC-AIQE-004 阻塞定性 + 可达性门禁）— 证据

> **日期**：2026-11-13 · **环境**：隔离 Test 实例 `aiqe-test-backend`（`release-m13-b341`）
> **结论**：TC-004 阻塞原因已定位为**网络不可达**（业务 Web DNS 指向内网 192.168.50.170，Test 云主机不在该网络），
> 不是自动化/产品缺陷；新增可复跑可达性门禁脚本，后续按"可达才执行、不可达即 BLOCKED"处理。

## 1. 背景

TC-AIQE-004（广告/其他功能浮层交叉干扰）要求：

1. Core Run 执行直播入口点击；
2. Integration Run 注入浮层 + 相同流程；
3. 对照两次 Run 并归因 `CROSS_FEATURE_DEFECT`。

第 1 步就依赖业务 Test Web（用户端）可达。

## 2. 实测（Test 云主机）

```bash
python3 scripts/qa/check_business_web_reachability.py
```

```json
{
  "host": "camelive-g3-test5.elelive.cn",
  "port": 443,
  "resolved": ["192.168.50.170"],
  "private_ips": ["192.168.50.170"],
  "status": "BLOCKED",
  "reason": "TCP 连接失败（DNS 指向内网地址 192.168.50.170，当前执行环境不在该网络）: timed out"
}
```

补充探测：

- `getent hosts camelive-g3-test5.elelive.cn` → `192.168.50.170`（RFC1918 私网）；
- TCP 443 → fail；HTTPS → `000`（12s 超时）。

## 3. 判定

| 项 | 判定 |
|----|------|
| 是否产品缺陷 | ❌ 否 |
| 是否自动化缺陷 | ❌ 否 |
| 是否环境/网络阻塞 | ✅ 是：业务 Test Web 仅在内部网络可解析/访问 |
| TC-004 结果 | **BLOCKED**（不计 PASS，不造绿） |

## 4. 解除条件（三选一）

1. **网络打通**：Test 云主机加入业务 Test 内网（VPN/专线/安全组），使 `192.168.50.170:443` 可达；
2. **入口白名单**：为业务 Test Web 暴露公网测试入口，或给 Test 出口 IP 加白；
3. **执行侧迁移**：在办公网/内网 runner 上注册节点（`node_capability_manifests` + evidence），
   由 AIQE 调度到该节点执行 TC-004（推荐长期方案，符合 M10 真机/内网集群方向）。
