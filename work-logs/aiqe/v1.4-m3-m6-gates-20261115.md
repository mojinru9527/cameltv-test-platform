## M3 真实 Agent Provider

- Provider：Test `ai_provider` 项目 1，DeepSeek 官方兼容接口
- 模型：`deepseek-v4-flash`
- A0：3 条验收标准，全部带 `source_ref`
- A2：`decision=approve`，5 条用例
- A3：`decision` 输出 3 个节点（health / ui / 项目计数），通过 Workflow Validator，`approval_status=pending`
- 人工审阅：A3 节点使用 `steps/query` 自由度字段，不满足 v1.4 Runtime 的 `input/assertions` 契约；人工转成可执行 graph（`a35f0100-05e9-4630-b953-0b674ea1fbb0`）后执行 Test Run `1dd2184e-c505-4464-808f-98df7c1193e4`，4/4 节点、5/5 断言 PASS。

**未完成点**：A3 的 prompt/schema 仍允许生成“Validator 通过但 Runtime 不可执行”的 workflow。这是 M3 的真实差距，下一步应让 A3 直接输出 `input/assertions` 或在审批前禁止不可执行节点。

## M4 归因与实验

- 每次输出均满足：`human_review_required=true`、`auto_close_defect=false`、`confidence=null`；UNKNOWN 约束由 Agent 校验。
- E1–E6：6 条实验创建成功；同一 idempotency key 返回同一行；双变量 change 被拒绝。

**未完成点**：这些是失败上下文（构造证据）而非全部真实注入；M4 的“7+ 类真实故障注入”仍应补真实 HTTP/网络/DB/浏览器故障。
