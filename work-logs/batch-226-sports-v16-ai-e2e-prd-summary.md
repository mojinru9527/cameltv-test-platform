## 3. 非目标与 C 条件处理

- 不部署生产、不修改生产数据、不替换第三方 AI 密钥；本地无健康密钥时如实标记外部阻断。
- 不验证体育客户端 16.0.0 是否已在线上线环境发布；本批验证的是测试平台承接该需求的能力。
- 不新增产品功能或美化 UI；仅修复本轮可稳定复现的平台缺陷。
- 纳入 `C225-1`：完成 B1-B15 出口审计、黑盒浏览器走查、交付/使用文档和实现文档。
- `C-CONDITIONS.md` 中除 `C225-1` 外的全部 Open 条件均明确豁免：它们属于体育网关业务参数、外部设备、旧文档归档、DSH 生产闭包或其他历史专项，不是本轮 B1-B15 本地 AI 主链路的前置；若运行时证明其中某项直接阻断本链路，则在 QA 报告中重新纳入并保留失败结论。

## 4. 用户故事与验收标准

- As a 黑盒测试工程师, I want 上传体育 16.0.0 完整需求并运行 AI 验收链路, so that 我能基于真实证据判断版本是否可放行。
  - 验收: Given 最新 `origin/main` 的隔离实例 / When 上传完整需求并生成、审核、执行、处理缺陷和放行 / Then 每一步可达、状态一致，且结果有真实证据。
- As a 测试负责人, I want 逐条看到 B1-B15 出口结论, so that 重构项目不因局部演示而被误判为完成。
  - 验收: Given B1-B15 路线图 / When 执行代码、API、浏览器和质量门禁核对 / Then 15 项各有 PASS/FAIL/BLOCKED 与证据锚点。

  - 验收: Given 可重复失败 / When 先留失败证据、再写回归测试和最小修复 / Then 聚焦测试与全量门禁无新增失败。
