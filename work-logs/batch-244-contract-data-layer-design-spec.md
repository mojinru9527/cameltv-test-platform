# Batch 244 — Design Spec

> **Design (🎨)** | Date: 2026-09-14 | Status: 就绪

## 0. 技术体系确认

本批数据/契约层改造不引入新视觉语言。页面继续使用 shadcn/ui + Tailwind 语义 token；设计目标是“交互结果不变、数据及时且类型可验证”。

## 1. 组件规格表

| 组件 | 规格 | 颜色/状态 | 说明 |
|------|------|-----------|------|
| API 数据列表 | 现有 loading/empty/error/data 四态 | 不改 token | 只改数据来源和失效 |
| Dashboard 指标 | 现有 StatCard | 不改 token | 避免陈旧数字 |
| 用例/计划表单 | 现有 React Hook Form | 不改 token | mutation 后精确刷新 |
| 错误态 | 现有 ErrorState/toast | destructive | 类型错误不改变用户可见行为 |

## 2. 布局与响应式

无布局变化；桌面/平板/移动端保持第一阶段后的现状。

## 3. 状态设计核对

| 组件 | Loading | Empty | Error | 写后刷新 |
|------|---------|-------|-------|----------|
| 列表页 | 保持 | 保持 | 保持 | 失效后重新请求 |
| 指标卡 | 保持 | `--`/0 | 保持 | 不再读取旧缓存 |
| 计划执行 | 保持 | 保持 | 保持 | 用例 map 批量取数 |

## 4. 设计 QA 走查发现

### 🟡 P2-01 缓存陈旧没有可见提示
`cachedGet` 命中 60 秒缓存时用户无法判断数据时间。建议后续在第三阶段评估“数据更新时间/刷新”提示；本批先保证 mutation invalidation 正确。

### 🟡 P2-02 API 类型迁移必须保持页面契约
生成类型和手写类型字段名可能不完全一致。迁移时以现有页面使用字段为兼容边界，禁止用 `as any` 掩盖差异。

## 5. 设计签核

结论：通过。本批不改变界面结构、主题、间距和响应式，只改数据正确性和开发者契约。
