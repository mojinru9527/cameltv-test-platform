## 1. 问题（为什么要做）

`C-CONDITIONS.md` 的 Open 计数长期虚高（此前 Open=56、rows=164），其中大量条目是
"已被后续批次覆盖但没登记关闭""永久流程约束""外部长期阻塞"。计数不准会导致
排期时无法判断真正待办量、历史条目反复被讨论、Leader 每周复核成本上升。

## 2. 成功指标

| # | 指标 | 判定 |
|---|------|------|
| M1 | Open 段只剩「平台内可排期」的真实待办 | 独立解析脚本输出 16 条，与用户指定分类一致 |
| M2 | 常驻规则不再计入待办 | 新增 `## 常驻规则` 节（9 条），审计工具不计入 Open |
| M3 | 废弃条目保留审计痕迹 | 新增 `## 废弃` 节（21 条），原文不删 |
| M4 | 审计无硬错 | `hard errors: 0`、`missing evidence: 0` |

## 3. 非目标

- 不做同 ID 去重与 C99-1 拆号（留待后续，避免与废弃判定冲突）。
- 不动任何代码、不重开已废弃条目的实现。

## 4. 用户故事

- **Given** 我要决定下一批做什么
- **When** 我打开 `C-CONDITIONS.md`
- **Then** Open 段只有平台内可做的真实待办，常驻规则与废弃项各自成节、便于审计
