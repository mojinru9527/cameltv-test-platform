# Batch 267 PRD-lite — 体育接口 P0 冒烟集（端点选择版）

> **Product/PM** | Date: 2026-09-20 | 档位：**轻量批次**
> `mode: light`
> 豁免理由：只产出**数据集与证据**（50 条接口用例 JSON + 实跑结果），不改平台代码、不动 Schema、不加依赖（`pipeline-modes.md` §1：纯数据/证据）。
> 非目标：不改执行链路（Batch 266 已完成）；不修改目标系统；不为自动生成用例"编造参数"。

## 1. 为什么用"端点选择"而不是"补参数"

`C266-1` 的缺口是：自动生成的 50 条接口用例假定"空 body 也能成功"，真实接口缺参数返回业务错误 → 45/50 失败。补真实参数需要业务方给口径，短期拿不到；而 B4-2 的试点口径本身是 **P0 冒烟**（要的是"这套链路在真实环境上能否稳定跑通并留证"），不是接口契约全覆盖。

因此本批改为：**在真实 Test5 上实测筛出信封 200 的健康端点**（10 个），每个端点生成 5 类断言（业务码 / 信封契约 / 响应时间 / 存在性 / 数据非空），构成 50 条 P0 冒烟用例。

## 2. 交付

1. `work-logs/evidence/batch-267/sports-api-smoke-cases.json`：50 条接口用例（含 `request{method,url,timeout}` 与 `assertions[]`，与驱动/节点 schema 对齐）。
2. `work-logs/evidence/batch-267/test5-api-anon-probe-20260920.json`：端点筛选依据（实测 http/信封码/data 形态）。
3. `work-logs/evidence/batch-267/api-smoke-run-20260920.json`：真实实跑结果（**42/50**）与 8 条失败的逐条归因。
