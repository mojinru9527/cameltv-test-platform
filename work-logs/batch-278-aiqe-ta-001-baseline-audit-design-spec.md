## 2. 每张表的固定模板（保证可比）

```markdown
### 4.x `表名`
**目标字段**（13 号 §4.x）：N 个 — `a`、`b`…
**现有候选**：`表`（Class，文件，M 列）：`a`、`b`…
**差异**：同名字段 X / 目标新增 Y / 现有独有 Z
- 同名（可直接复用）…
- 目标新增（需 ALTER 或新表）…
- 现有独有（保留，不删）…
**迁移策略**：…（含类型对齐 + 语义映射）
**预估迁移脚本行数**：≈ N（Alembic revision + 索引 + 回填）
```

**设计取舍**：

- "现有独有（保留，不删）"是刻意保留——旧表继续服务现有页面，避免"审计即重构"；
- 同名匹配是**机器初筛**，语义等价的改名（如 `case_id`≈`case_key`）写在"迁移策略"里，不由脚本猜；
- 预估行数公式固定：新建 `25 + 5×字段数`，扩展 `20 + 5×新增字段`，兼容层 `35 + 5×新增字段`，可复核。

## 3. 视觉与可读性

- 冲突用 `C-01..C-10` 编号，决策用 `D-278-x` 编号，全文档唯一，便于 PR 评审引用；
- 表格列宽控制：字段清单用顿号分隔的长段落，不拆成 315 行表格（否则 860 行会变 2000+ 行）；
- ASCII 时序图统一 `→` 与缩进，状态/心跳/取消/错误路径各占一行，不画花哨图。
