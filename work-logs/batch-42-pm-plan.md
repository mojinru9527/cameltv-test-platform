### [x] Task 2: 运营后台全量需求提取

### B. 需求ID体系命名规则

```
用户端:  {功能域缩写}-{序号}    如: AUTH-001, HOME-003, UGC-009
运营后台: ADM-{功能域缩写}-{序号}  如: ADM-USER-001, ADM-FIN-014
产品版本: {端标识}{版本号}-{序号}  如: U14.1.0-001, A8.2.0-001
基线版本: V13-{功能域}-{序号}     如: V13-AUTH-001, V13-UGC-003
```

### C. 三种检索路径

**按版本检索**:
- 查 `更新日志-*-完整版.md` → 定位目标版本 → 提取"更新内容"列 → 对照需求ID

**按模块检索**:
- 用户端8大功能域（A~H）→ 查 PRD §3.2 对应域 → 获取需求清单
- 运营后台9大功能域（A~I）→ 查 PRD §4.2 对应域 → 获取需求清单

**按优先级检索**:
- P0（核心阻断）: 登录/支付/赛况/骆驼币扣减/奖励发放/购买对账
- P1（主要功能）: 搜索/资讯/个人资料/联赛数据/创作者中心/内容审核
- P2（体验优化）: PC分辨率适配/装扮预览/推送统计/FAQ搜索
