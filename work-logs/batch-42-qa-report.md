## 一、遗漏项（按严重级别排列）

### 🔴 P0 — 致命遗漏（影响核心业务）

#### P0-1: 活动管理模块独立成域
**现状**: PRD 将"充值赠币活动"归入财务管理域（ADM-FIN-015），但最新原型（2026-06-11）已将活动管理独立为一级模块，含3页：充值赠币活动、活动内容(法币)、活动内容(数字货币)。
**影响**: 活动配置流程涉及独立的状态机（创建→审核→上线→到期→下线），与财务流水是解耦的，混在一起会漏测活动生命周期管理。
**建议**: **将活动管理从财务域分离为独立域J**，补充需求：
- ADM-CAMPAIGN-001: 活动创建（类型:法币/数字货币，时间范围，叠加规则）
- ADM-CAMPAIGN-002: 活动内容配置（赠送比例/阶梯规则/首充vs续费差异）
- ADM-CAMPAIGN-003: 活动状态流转（草稿→审核→上线→到期→下线）
- ADM-CAMPAIGN-004: 活动与套餐的互斥/叠加策略

#### P0-2: 首单退币规则未在后台可配置
**现状**: 用户端 14.1.0 引入首单不中退币（REFUND），14.0-features.md 标注"无需后台单独配置"，但这意味着退币规则（退币比例/有效期/适用文章范围）固化在代码中。
**影响**: 运营无法调整退币策略，每次规则变更需要代码发布。
**建议**: **需确认**：退币是否确实是固定规则（如 100%退还、仅限首次购买）？若未来可能需要调整，应在运营后台增加退币活动配置页。

### 🟠 P1 — 严重遗漏（影响主要功能）

#### P1-1: 聊天文案白名单功能未覆盖
**现状**: 运营后台风控管理域新增"聊天文案白名单"页面（72页原型第70页），原需求分析（运营后台-需求分析.md）未提及。
**影响**: 缺失敏感词白名单机制的需求规格和测试点。白名单与敏感词库的优先级规则（白名单优先 vs 黑名单优先）是关键测试点。
**建议**: 补充到 ADM-INTERACT-002，新增子需求：白名单CRUD/优先级规则/导入导出。

#### P1-2: 数字货币支付流程端到端未完整定义
**现状**: 用户端 14.1.0 引入数字货币支付（ECON-014），后台 8.1.0 引入数字货币配置（ADM-FIN-014），但以下环节缺失：
- 数字货币汇率获取机制（实时/定时/手动）
- 支付回调处理（链上确认数要求/超时处理）
- 数字货币支付退款流程（法币退款 vs 原币退还）
- 数字货币钱包地址管理与校验
**建议**: 补充数字货币专项需求子文档，覆盖上述 4 个环节。

#### P1-3: "说明附件"6页未纳入需求体系
**现状**: 用户端原型有6页"说明附件"（广告位系统/银钻系统/银钻预测玩法/UGC功能概述/付费活动/骆驼币及绿钻），这些页面描述的是业务规则和系统设计，不是传统UI页面，但包含了关键的业务逻辑。
**影响**: 部分业务规则仅存在于设计说明中，未转化为可测试的需求规格。
**建议**: 将6页说明附件中的业务规则提炼为需求规格条目：
- 广告位系统说明 → 合并入 ADM-AD-003（广告位优先级与排期规则）
- 银钻系统说明 → 补充银钻获取/消耗/过期完整规则
- 银钻预测玩法说明 → 补充预测算法和赔率计算规则
- UGC功能概述 → 补充UGC整体生命周期规则
- 付费活动说明 → 合并入 P0-1（活动管理域）
- 骆驼币及绿钻说明 → 补充双币种差异与兑换规则

#### P1-4: UGC内容审核流程未完整建模
**现状**: 运营后台有内容审核基本流程（审核→通过/拒绝），但缺失以下环节：
- 多级审核（初审→复审→终审）的状态机定义
- 用户申诉/编辑后重审规则
- 审核超时自动处理（如48小时未审核自动通过/拒绝）
- 审核意见内部可见 vs 创作者可见的区分
**建议**: 补充 ADM-CONTENT-015（UGC审核完整流程），覆盖上述4个环节。

#### P1-5: 充值赠币与首单退币互斥逻辑未定义
**现状**: 当用户同时满足"首单不中退币"和"充值额外赠送"两个活动条件时：
- 首单购买UGC文章 → 若未猜中 → 退币金额是否含赠送部分？
- 赠送的骆驼币是否可用于购买UGC（还是仅限打赏/装扮）？
**影响**: 财务对账时赠送币与购买币的流水混淆风险。
**建议**: 明确两活动互斥/叠加规则，补充到 ECON-013 和 UGC-009 的验收条件中。

#### P1-6: 预测系统与UGC付费预测的关系未定义
**现状**: 用户端有"赛事预测"（域C）和"UGC文章预测"（域E）两套预测体系，但两者使用相同的骆驼币，且可能涉及同一场比赛。当前需求未定义：
- UGC文章的预测项（赔率/选项）是否与赛事预测系统同步？
- 同一场比赛的官方预测 vs UGC作者预测结果冲突时如何处理？
**建议**: 补充预测体系统一规则需求。

### 🟡 P2 — 一般遗漏（有替代方案）

#### P2-1: 数据保留与清理策略缺失
**现状**: 所有模块均无数据保留期限需求。GDPR/个人隐私法规要求用户注销后数据需在指定期限内删除。
**影响**: 合规风险。
**建议**: 补充至系统配置域：
- ADM-SYS-006: 用户注销后数据保留期限（如90天后自动清理）
- ADM-SYS-007: 聊天记录保留期限
- ADM-SYS-008: 支付流水永久保留 vs 定期归档

#### P2-2: 权限粒度与角色定义不完整
**现状**: 需求中多处提到"权限控制"（如 ADM-FIN-003 余额手动调整），但缺少完整的 RBAC 角色-权限矩阵。
**影响**: 开发和测试无法验证权限隔离的完整性。
**建议**: 补充独立的"权限体系需求规格"，至少定义以下角色：
- 超级管理员 / 内容运营 / 财务专员 / 客服 / 只读审计

#### P2-3: 通知触发规则矩阵缺失
**现状**: 推送消息功能（ADM-INTERACT-005~009）描述了推送能力，但未定义"何时触发什么通知"的规则矩阵。
**影响**: 测试时只能验证推送功能可用，无法验证推送时机是否正确。
**建议**: 补充通知触发规则矩阵，至少覆盖：
- 充值到账通知 / 提现结果通知 / 预测结算通知 / UGC审核结果通知 / 封禁通知 / 活动开始通知

#### P2-4: PC端与移动端功能差异清单缺失
**现状**: 用户端 PC端6页 + WEB端3页 + APP端24页 + 直播间7页，但没有系统化记录各端功能差异。
**影响**: 跨端测试时需逐个页面比对，效率低。
**建议**: 补充多端功能差异对照表（列：功能/APP/PC/WEB/直播间）。

#### P2-5: 第三方服务依赖与降级策略不明确
**现状**: 多个功能依赖第三方服务（支付渠道/推送通道/ELK日志/视频流），但降级策略仅个别标注（如开屏广告降级、动画直播降级）。
**影响**: 第三方服务不可用时系统的行为不一致。
**建议**: 补充第三方依赖清单与统一降级策略。

#### P2-6: API接口规范未与需求关联
**现状**: 需求ID体系完备，但未与后端API端点建立关联。测试平台v2的接口测试需要从需求追溯到API。
**影响**: 接口测试用例编写时需要手动映射需求→API。
**建议**: 在需求追溯矩阵中补充 API 端点列。

## 二、功能优化建议

### 💡 OPT-1: UGC排序权重需量化（P1）
**现状**: UGC-002 描述"置顶优先，非置顶按比赛时间就近排序"，UGC-010 描述"人工置顶排序变量"。
**问题**: "人工置顶"与"比赛时间"的权重关系不明确——如果同时有3篇置顶文章+10篇普通文章，置顶文章之间如何排序？按置顶时间倒序还是可手动拖拽？
**建议**: 明确排序公式：`Score = isPinned * 10000 + pinnedTime + (1-isPinned) * matchTime`，并补充置顶文章之间的二次排序规则。

### 💡 OPT-2: 骆驼币精度与舍入规则未定义（P1）
**现状**: ECON-006 描述骆驼币消耗扣减，ADM-FIN-011 描述提现手续费计算精度。
**问题**: 多处涉及金额计算（充值/购买/退款/提现/预测/手续费），但未统一定义骆驼币精度（整数？小数点后几位？）和舍入规则（四舍五入/向下取整？）。
**建议**: 统一在虚拟经济域补充"金额计算规范"：骆驼币为整数（最小单位1币），手续费计算四舍五入到整数。

### 💡 OPT-3: 版本号体系文档化（P2）
**现状**: 用户端38版本 + 后台22版本，14.0-features.md 文档化了版本体系。
**问题**: 但蓝湖系统版本号（系统版本29/50）与产品版本号（14.1.0/8.2.0）并行存在，新成员容易混淆。
**建议**: 在更新日志页首增加版本号使用说明，明确"产品版本号"为唯一需求主键。

### 💡 OPT-4: 测试平台需求模块应支持版本化管理（P2）
**现状**: 当前测试平台v2的需求模块（Requirement Management）按模块组织需求。
**问题**: PRD 中已经建立了"需求ID + 版本号"的体系，但测试平台自身未利用这个版本信息做需求继承/差异对比。
**建议**: 测试平台需求模块增加"版本标签"功能，支持按版本筛选需求、自动计算版本间需求差异。
